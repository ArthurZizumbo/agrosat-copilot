## 1. Objetivo

Producir la documentación de cierre verificable y reproducible del MVP en su vertiente de seguridad y trazabilidad de modelos:

1. **`docs/security.md`** — revisión OWASP Top 10 documentada con el estado **real** de cada control en el código (qué está implementado, qué es Full/post-presentación y qué es deuda anotada), más el procedimiento del penetration test manual básico.

3. **`docs/glosario.md`** — glosario técnico con estandarización de términos IT/ES/EN.

Regla de Arthur aplicada: cada cifra, métrica o claim debe venir de un artefacto real del repo (JSON de resultados, run MLflow, ADR). Si un dato no se puede verificar, se anota en `docs/blockers/epic10-notas.md` (a crear) y se sigue, nunca se inventa un placeholder.

## 4. Enfoque técnico por entregable

### 4.1 `docs/security.md`

Documento en español, prosa neutra, sin emojis. Secciones:

1. **Resumen del modelo de amenazas del MVP** — SaaS conversacional multi-tenant por `session_id`; superficie: API FastAPI (Cloud Run), frontend Nuxt SSR, agente ADK con LLMs cloud/on-prem, Postgres + PostGIS + pgvector.
2. **Tabla OWASP Top 10 (2021)** — una fila por categoría (A01 Broken Access Control … A10 SSRF) con tres columnas: *riesgo en AgroSatCopilot*, *control implementado / estado*, *evidencia (ruta de archivo o US)*. Cada estado debe ser uno de: **Implementado** (con ruta real), **Full/post-presentación** (diferido conscientemente), o **Deuda anotada** (enlace al blocker doc). Anclas reales a citar:
   - A01 (Access Control): multi-tenant por `session_id` (regla CLAUDE.md); RLS **pendiente US-051** → estado Deuda anotada con la realidad de `docs/STATUS.md`.
   - A02 (Cryptographic): HTTPS vía Cloud Load Balancer + cert managed (Full/post-presentación; demo sobre Cloud Run TLS por defecto).
   - A03 (Injection): SQLModel/SQLAlchemy parametrizado; validación XSS del markdown del LLM en frontend (`isomorphic-dompurify`, US-057) — enlazar como control real.
   - A05 (Misconfig): CORS endurecido + slowapi rate-limit en `main.py`; `Settings.extra="forbid"`.
   - A07 (Auth): `user_id` demo hardcoded para 27-jun; Clerk OAuth2 + JWT refresh = Full/post-presentación.
   - A09 (Logging/Monitoring): structlog estructurado (US-065), Sentry DSN declarado, Prometheus pushgateway (US-059).
3. **Gestión de secretos** — `.env.local` en dev, Secret Manager (GCP) / Key Vault (Azure) en prod; **corregir la referencia muerta del v6**: el secrets-scan es `make secrets-scan` (gitleaks) + CI, NO un hook `detect-secrets` ni `.pre-commit-config.yaml` (regla irrevocable: el proyecto no usa pre-commit).
4. **Penetration test manual básico** — procedimiento documentado (no necesariamente ejecutado en CI): comandos `nmap` (escaneo de puertos del endpoint Cloud Run) y `nikto` (escaneo HTTP) contra el deploy de staging, con la nota de que es un check manual humano pre-deploy (alineado con la skill `agrosat-security-audit`, que es documentada/no-automatizada). Si no se puede ejecutar contra un endpoint live esta sesión → anotar en blocker doc y dejar el procedimiento listo.
5. **Enlaces** — a `agrosat-security` y `agrosat-security-audit` (skills), ADR-009 y ADR-012 (inferencia síncrona MVP), y a US-051 (RLS), US-057 (XSS), US-065 (observabilidad).

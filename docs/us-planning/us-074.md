> **Riesgo de match documentado**: tres clases PASTIS no tienen una hoja 1:1
> perfecta y se mapean al nodo de grupo mas cercano (decision explicita, no fallo):
> - **Mixed cereal (17)** -> `cereal` (3301010000, nodo L2 de grupo, no hoja): es una
>   mezcla de cereales sin especie unica; se asigna al grupo cereal, NO a una hoja.
> - **Fruits, vegetables, flowers (12)** -> `fresh_vegetables` (3301070000): la clase
>   PASTIS funde horticultura mixta + flores; se elige `fresh_vegetables` como hoja
>   representativa dominante y se documenta la perdida de granularidad (flores/frutos).
> - **Leguminous fodder (14)** -> `legumes_harvested_green` (3301090300): forraje
>   leguminoso cosechado en verde (no `legumes_dried_pulses`), decision agronomica.
> El `.md` lista estos tres con un flag `match_quality = approx` (vs `exact`).

### 3.2 Colapso a macro-clases (nivel de grupo HCAT)

Regla determinista: `macro = mapeo(hcat_leaf -> nodo de grupo HCAT)`. El nodo de grupo
es el ancestro L2 (6-dig significativos) salvo pasture/permanent que ya son L1.
Resultado: **11 macro-clases** (en el rango pedido 10-20):

| Macro (HCAT group) | HCAT group code | PASTIS ids (semantic18) | n_parcels acum. |
|--------------------|----------------:|-------------------------|----------------:|
| cereals            | 3301010000 | 1,2,3,5,9,10,16,17 (8 clases) | 30570 |
| oilseed_industrial | 3301060000 | 4,6 (rapeseed, sunflower) | 3124 |
| root_tuber         | 3301030000 / 3301290000 | 8,12 (beet, potato) | 1422 |
| legumes            | 3301090300 / 3301160000 | 13,14 (fodder leg., soy) | 4386 |
| vegetables         | 3301070000 | 11 (fruits/veg/flowers) | 2619 |
| grassland          | 3302000000 | 0 (meadow) | 31292 |
| orchard            | 3303010000 | 15 (orchard) | 2998 |
| vineyard           | 3303060000 | 7 (grapevine) | 10640 |

> **Variante mostrada como comparativa (no canonica)**: el JSON `pastis_class_mapping.json`
> ya trae `hcat_l1_6` (6 grupos: CEREALS/OILSEEDS/ROOT_CROPS/LEGUMES/PERMANENT_WOODY/OTHER)
> que es el que ya logro **XGBoost 0.6535 F1-macro** (hallazgo de producto v8). El
> notebook MUESTRA ambos: el de 6 familias (legado, compatibilidad con E4/E6) y el de
> ~11 macro-clases por grupo HCAT (canonico de US-074, mas fino para multi-region).
> El label-space registrado (`hcat-macro`) usa el de 6 familias por compatibilidad con
> el clasificador semantic18 existente (ver §5), y el parquet incluye AMBAS columnas.

**Mitigacion del long-tail**: Meadow (45% de parcelas crop) queda aislado en `grassland`,
y los 8 cereales hermanos (incl. los inseparables Soft/Durum winter wheat) se funden en
`cereals`, reduciendo la varianza inter-clase que hundia el F1-macro a 18 clases.

## 5. Ampliacion del registry US-053 (SIN tocar classify.py)

En `ml/eval/class_remap.py` se anade, despues de `FRANCE_9`, un constructor del
label-space HCAT que se registra via `register_label_space`. Reusa la maquinaria
existente (`LabelSpace` dataclass, `_SEMANTIC18_SIZE`, validacion de ids).

```python
# ml/eval/class_remap.py  (NUEVO, sin tocar nada previo)

#: Mapeo semantic18_id -> macro HCAT de 6 familias (compatibilidad con el
#: clasificador semantic18 de US-053; misma particion que pastis_class_mapping.json
#: groupings.hcat_l1_6, resuelta a ids contiguos).
_HCAT_MACRO_L1_6: dict[int, str] = {
    0: "GRASSLAND_OTHER", 1: "CEREALS", 2: "CEREALS", 3: "CEREALS",
    4: "OILSEEDS", 5: "CEREALS", 6: "OILSEEDS", 7: "PERMANENT_WOODY",
    8: "ROOT_CROPS", 9: "CEREALS", 10: "CEREALS", 11: "GRASSLAND_OTHER",
    12: "ROOT_CROPS", 13: "LEGUMES", 14: "LEGUMES", 15: "PERMANENT_WOODY",
    16: "CEREALS", 17: "CEREALS",
}


def _build_hcat_macro() -> LabelSpace:
    """Construct the ``hcat-macro`` label-space over all 18 semantic18 ids.

    Unlike ``france-9`` (a *subset* of well-resolved ids), the HCAT macro space
    keeps ALL 18 ids but carries the macro-group mapping in ``class_names`` so a
    consumer can aggregate the semantic18 posterior into macro families without
    touching the classifier. Derived from the US-074 crosswalk.
    """
    from ml.data.pastis_filter import SEMANTIC18_CLASS_NAMES

    kept = tuple(range(_SEMANTIC18_SIZE))  # all 18
    class_names = {
        cid: f"{_HCAT_MACRO_L1_6[cid]}|{SEMANTIC18_CLASS_NAMES[cid]}"
        for cid in kept
    }
    return LabelSpace(
        name="hcat-macro",
        kept_class_ids=kept,
        dropped_class_ids=(),
        class_names=class_names,
        source="US-074 crosswalk PASTIS-18 -> HCAT v3 (data/reference/hcat_crosswalk.parquet)",
    )


HCAT_MACRO: LabelSpace = _build_hcat_macro()
register_label_space(HCAT_MACRO)
```

`__all__` se amplia con `"HCAT_MACRO"`. **`ml/agent/tools/classify.py` NO se modifica**:
sigue llamando `get_label_space(name)` y `restrict_posterior`; ahora `"hcat-macro"` esta
disponible por nombre. Esto cumple literalmente "EPIC 12 US-074 amplia el registry sin
tocar classify.py".

> **Nota de diseno honesta**: `restrict_posterior` opera sobre subconjuntos de ids
> (mask + renormaliza), no agrega ids en una macro-clase. `hcat-macro` mantiene los 18
> ids (subconjunto trivial = todos) y EXPONE el mapeo macro en `class_names`; la
> AGREGACION real semantic18->macro la hace el adapter/consumer leyendo el parquet, no
> el registry. Asi NO se cambia la firma ni el contrato de `restrict_posterior`
> (evita romper US-053). El registry queda como punto unico de verdad del nombre.

## 8. Estrategia clases disjuntas (recomendacion, sin implementar)

Documentar en el `.md` el protocolo **partial-label / null-class estilo UniSeg**:
- Una clase etiquetada en dataset A pero ausente (background) en B NO debe contar como
  negativo duro en B -> se trata como `null-class` (etiqueta desconocida, no negativa).
- Recomendacion de loss: **BCE class-independent** (un sigmoide por clase HCAT, no softmax
  mutuamente excluyente) + **cross-dataset relation loss** que penaliza solo las clases
  presentes en cada dataset, evitando el conflicto de gradiente entre regiones.
- **NO se implementa el loss en US-074** (lo consumira US-075/US-076). US-074 solo deja
  el espacio de etiquetas comun y la convencion null-class documentada.

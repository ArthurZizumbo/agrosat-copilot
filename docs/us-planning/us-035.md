# US-035 — Ablacion de bandas FarSLIP (RGB vs falso-color NIR-R-G vs 4-band) en H100

**Status**: planning · **Epic**: E5 (Modelos Alternativos / Comparativa) · **Avance del curso**: A5 (ensamble) / S7
**Sprint**: S7 · **Owner**: Arthur Zizumbo (ML/MLOps) · **Prioridad**: P4 (sigue a US-034 en la cola H100, US-038)
**Rama sugerida**: `feature/E5-US-035-farslip-band-ablation`
**Plan vigente**: `context/RefinamientoPlaneacionAgroSatCopilot_v8.md` (US-035, lineas 1247-1267; alias interno "US-031 ablacion bandas" en el subtotal EPIC 5 :1365 — encabezado canonico es US-035; ADR-009)
**Depende de**: US-034 (`build_text_prototypes` + `--proto-source pastis|random`, `set_text_prototypes` reproyeccion 384->768, `adapt_patch_embed_to_n_channels`; `code-complete`). Student `4band-pheno` de US-034 es la referencia de la variante 4band.
**Insumo de**: US-037 (eval FarSLIP vs AlphaEarth — la tabla de ablacion cuantifica si NIR/fenologia cierra el gap 0.163 vs 0.233).

> **Objetivo**: medir, con un A/B limpio en MLflow, **cuanto aporta NIR y cuanto aporta la fenologia real** al
> contraste region-aware de FarSLIP. Tres corridas que combinan **seleccion de bandas** x **fuente de
> prototipos**: `baseline-rgb` (B04-B03-B02 true color, protos random), `baseline-nir` (B08-B04-B03 falso
> color, protos random), `4band-pheno` (B02-B03-B04-B08, fenologia real US-034). Entregable: las 3 corridas
> con `data_version`+`code_version`, una **tabla comparativa** que aisla el aporte NIR (rgb vs nir) y el aporte
> fenologia (baselines random vs 4band-pheno), y el codigo de seleccion/reorden de bandas con su unit test.
> **Apuesta honesta**: `4band-pheno` gana (NIR + fenologia juntos), pero la tabla lo demuestra, no lo asume.

> **CLAVE DE DISENO — `band_selection` controla DOS cosas acopladas: (a) que bandas/orden recibe el modelo y
> (b) cuantos canales tiene el `patch_embed`**. Los dos baselines son **3 canales** (rgb/nir_rgb, sin
> adaptacion: el `patch_embed` se queda en 3, no-op de `adapt_patch_embed_to_n_channels`); la variante 4band es
> **4 canales** (adaptacion 3->4 con NIR = mean(RGB), YA implementada en `distill.py:312`, REUSAR). Hoy el
> student SIEMPRE se adapta a `n_in_channels=4` (default `distill.py:297`); para los baselines hay que **derivar
> `n_in_channels` de `band_selection`** (3 para rgb/nir_rgb, 4 para 4band) y que el dataset entregue ese numero
> de canales. UNA SOLA fuente de verdad para el numero de canales: `band_selection` -> `n_in_channels`.

> **RIESGO PRE-EXISTENTE (decidir explicitamente antes de implementar) — orden RGB vs BGR al teacher**:
> `distill.py:607-610` hace `teacher_input = images[:, :3, :, :]` con el comentario "pure RGB = B04/B03/B02 =
> BGR slice" (ambiguo: dice RGB y BGR a la vez). El dataset entrega `[B02,B03,B04,B08]` -> hoy `images[:,:3]`
> = `[B02,B03,B04]` = **BGR** (azul,verde,rojo), NO RGB. El teacher CLIP pretrained recibe canales invertidos.
> Para la variante **4band** debemos mantener el orden historico `[B02,B03,B04,B08]` identidad (compat con el
> checkpoint US-034 y con el comentario AC-2 del teacher). Para **rgb/nir_rgb** el `select_and_reorder_bands`
> entrega `[B04,B03,B02]`/`[B08,B04,B03]`, de modo que `images[:,:3]` SI seria RGB/NIR-R-G correcto al teacher.
> **Inconsistencia**: 4band manda BGR al teacher; rgb/nir_rgb mandan RGB correcto. **Decision recomendada para
> US-035** (documentar, no romper compat): mantener el orden de cada variante tal cual (4band identidad por
> compat con US-034; rgb/nir_rgb reordenadas) y registrar el caveat en la tabla — el A/B sigue siendo valido
> porque cada variante es internamente consistente y la comparacion mide el efecto de banda/fenologia, no la
> calidad absoluta del teacher. NO reescribir el slice del teacher en esta US (rompe el checkpoint 4band).

> **OJO ALCANCE / NO TOCAR**:
> - **NO regenerar** `data/farslip_pairs/` (15GB, 30173 crops; los 4 canales B02/B03/B04/B08 son el insumo) ni
>   `phenology_class_prototypes_pastis.parquet` (US-033, DVC). Solo se LEEN.
> - **NO tocar** `ml/farslip/cap_vocabulary.yaml` ni el default `weights_uri` del extractor (ml/CLAUDE.md).
> - **NO reescribir** `RegionCategoryAlignmentLoss.forward` ni el slice del teacher (`distill.py:610`): la
>   inconsistencia RGB/BGR se DOCUMENTA, no se corrige aqui (corregirla rompe el checkpoint 4band de US-034).
> - **NO reentrenar** desde cero la mecanica de prototipos de US-034: `4band-pheno` reusa `--proto-source pastis`
>   tal cual; los baselines reusan `--proto-source random`.

### 1.2 Metricas verificables (golden values de tests)

Tests **sin red, sin GPU, sin dataset real**: el indexado de bandas es slicing puro (CPU); la adaptacion
patch_embed ya tiene tests en `test_trainer_smoke.py`. Golden values:

- **Layout de bandas del crop (verificado, `dataset.py:3-6`)**: 4 bandas `B02,B03,B04,B08` -> indices
  `B02=0, B03=1, B04=2, B08=3`. El loader `src.read()` devuelve `(4,H,W)` tal cual, normaliza `/10000`,
  resize a 224; NO reordena ni selecciona bandas hoy.
- **Indices por variante**: `rgb`->`[2,1,0]` (B04,B03,B02), `nir_rgb`->`[3,2,1]` (B08,B04,B03),
  `4band`->`[0,1,2,3]` (identidad). Salida: `(3,H,W)` para rgb/nir_rgb, `(4,H,W)` para 4band.
- **n_in_channels derivado**: `{"rgb":3, "nir_rgb":3, "4band":4}`.
- **Adaptacion patch_embed (verificado, `distill.py:362-366`)**: copia primeros 3 canales; canal NIR =
  `old_proj.weight.mean(dim=1, keepdim=True)` (no dead neuron). 3->3 es no-op (`distill.py:335-336`).
- **VRAM (estimado FP32, recon US-034)**: ViT-B/16 distill batch=64 ~10-14 GB FP32. En H100 96GB caben **las 3
  variantes en paralelo** (3 procesos ~30-42 GB total). bf16 NO implementado (no es AC).
- **time_cap**: default `8.0 h` (`train.py:282`, warning 6h). El plan pide ~10h; subir `--time-cap-hours` para
  el run real o aceptar el corte. Fallback L4 24GB (~22GB techo) documentado.

**Mecanismo (cumple AC-2/AC-3)**: `select_and_reorder_bands(img, sel)` indexa `img[_SELECTIONS[sel], ...]` con
`_SELECTIONS = {"rgb":[2,1,0], "nir_rgb":[3,2,1], "4band":[0,1,2,3]}`. Se aplica como `transform` del dataset
(`FarSLIPDataset.__init__` parametro `transform`, aplicado en `__getitem__` DESPUES del resize) via
`functools.partial`, o como parametro `band_selection` del dataset. `n_in_channels` se deriva de un dict

(`distill.py:427-440`) ya llama a `adapt_patch_embed_to_n_channels(student, n_in_channels)` -> 3 = no-op,
4 = adaptacion mean-RGB. **NO se reescribe el loss ni el slice del teacher.**

## 2. Arquitectura de la solucion

```
CLI train.py  --band-selection {rgb|nir_rgb|4band}   --proto-source {random|pastis}
        |  validar contra set permitido (como proto_source)
        v
  n_in_channels = _N_CHANNELS[band_selection]      # rgb/nir_rgb->3 ; 4band->4  (1 fuente de verdad)
        |
        +--> FarSLIPDataset(..., transform = partial(select_and_reorder_bands, sel=band_selection))
        |        __getitem__: _load_crop (4,H,W) -> resize 224 -> transform -> (n_in_channels,H,W)
        |        select_and_reorder_bands: img[_SELECTIONS[sel], ...]
        |            rgb     -> [2,1,0]  B04,B03,B02   (RGB true color)
        |            nir_rgb -> [3,2,1]  B08,B04,B03   (falso color NIR-R-G)
        |            4band   -> [0,1,2,3] B02,B03,B04,B08 (identidad, compat US-034)
        |
        +--> build_text_prototypes(proto_source, ...)        # US-034 SIN CAMBIOS
        |        random  -> _random_fallback  (baselines)
        |        pastis  -> prototipos fenologicos US-033 (4band-pheno)
        |
        v
  FarSLIPTrainerConfig(n_in_channels=..., band_selection=..., extra_params={..., band_selection, ...})
        v
  FarSLIPDistillationTrainer._patch_student_proj
        adapt_patch_embed_to_n_channels(student, n_in_channels)   # distill.py:312 REUSAR
            n_in_channels==3 -> no-op (distill.py:335-336)
            n_in_channels==4 -> copia 3 RGB + NIR=mean(RGB) (distill.py:362-366)
        v
  step() (distill.py:606-624)  SIN CAMBIOS
        student(pixel_values=images(B,n,224,224))
        teacher_input = images[:, :3]      # caveat RGB/BGR documentado, NO se toca
        loss = alpha*loss_cls + beta*loss_patch + gamma*loss_kd
        v
  3 RUNS (ejecucion, no codigo):
    baseline-rgb  : --band-selection rgb     --proto-source random
    baseline-nir  : --band-selection nir_rgb --proto-source random
    4band-pheno   : --band-selection 4band   --proto-source pastis
        -> checkpoints/farslip/{run}/{epoch_NN,best,last}.pt (F:)
        -> MLflow 3 runs (:5010) con data_version+code_version+band_selection+n_in_channels
        -> TABLA comparativa (aporte NIR = rgb vs nir ; aporte fenologia = random vs 4band-pheno)
```

**Principio rector**: cambio **minimo**. La mecanica de US-034 (prototipos, reproyeccion, adaptacion 3->4)
NO se reimplementa: se REUSA. US-035 anade solo (a) el control `band_selection` (CLI + config), (b) el helper
`select_and_reorder_bands` + dict `_N_CHANNELS`, (c) el wiring para que el dataset entregue N canales y
`n_in_channels` se derive de la variante, y (d) un unit test de indexado. Las 3 corridas son **ejecucion**,
no codigo nuevo.

### Decision de paralelizacion

**1 SOLO agente ml para el CODIGO. NO paralelizable.** Los 3 archivos de codigo (`bands.py`, `train.py`,
`distill.py` config + test) forman **un solo flujo acoplado**: el contrato `band_selection -> n_in_channels ->
canales del dataset -> patch_embed` debe decidirse de una vez (dividir = acoplamiento de firma a ciegas,
anti-patron write-conflict logico). El test depende de los tres. **Los 3 RUNS son ejecucion, no codigo** (no
abren write-conflict): se lanzan tras el smoke verde, idealmente **en paralelo en H100 96GB** (caben las 3 a la
vez, ~30-42 GB total FP32).

| Agente | Write-set (archivos que escribe) | Tarea | Depende de |

### 1.1 Hechos que enmarcan el diseno (correcciones factuales obligatorias)

1. **GEO-Bench-2 != GeoAnalystBench**. GeoAnalystBench (ya en el repo) es plan-and-react de codigo
   geoespacial. GEO-Bench-2 es un benchmark de tareas de vision EO (clasificacion/segmentacion sobre
   imagenes satelitales). US-069 añade GEO-Bench-2 como **tercer eje nuevo**, no reusa el CSV
   existente. El AC pide ">=3 de las 19 tasks disponibles", filtradas a las **agricolas relevantes**
   (crop classification / land-cover con clases de cultivo).
2. **Variantes = SOLO dos reasoners** (AC literal): **Gemini 2.5-pro** (reasoner cloud GA, 1M ctx, NO
   2M, NO "3.1") y **Qwen3.5-35B-A3B vLLM** (variante on-prem, GPTQ-Int4, single-GPU, SIN
   `--tensor-parallel-size`). **Gemma 4 26B solo como base sin fine-tune** si entra (su LoRA esta OUT
   — experts MoE 3D fused bloquean QLoRA; ADR-009). El harness ya define `gemini`/`qwen`/`gemma-base`,
   asi que el trio del paper sale del registro existente.
3. **AgroMind es eval-only** (~28,482 QA sin train split): subset 1000 se evalua, NUNCA se fine-tunea
   (seria leakage). Lo mismo AgroMind-IT/ES (US-068) — eval-only por construccion.
4. **Patron "Be My Eyes"** (Huang et al. 2025, arXiv:2511.19417): el reasoner es FROZEN (perceiver =
   nuestros modelos de segmentacion; reasoner = LLM que comunica/explica). El benchmark mide
   comunicacion/razonamiento del reasoner, NO es un clasificador de pixeles. Claims defendibles: NO
   "VLM fine-tuned supera a Gemini"; targets de referencia AgroMind **>=0.75 Gemini / >=0.70 Qwen**
   (no sobre-afirmar).
5. **GeoAnalystBench se MANTIENE** como eval complementaria (ya corre en `agent_bench`); US-069 NO la
   borra. El trio del paper de esta US es GEO-Bench-2 + AgroMind + AgroMind-IT/ES; GeoAnalystBench
   sigue disponible para la tabla de ablacion de tools (US-070).

## 3. Enfoque tecnico

### 3.1 Modulo nuevo `ml/eval/paper_bench.py` (hermano de `agent_bench`, NO lo muta)

Sigue el contrato de `agent_system_eval.py`: modulo SIBLING que IMPORTA de `agent_bench` y nunca
modifica su API publica. Identificadores/docstrings en ingles (Google-style); prosa visible (CLI
help, tabla) en español; `structlog`; type hints; sin emojis. Backends **inyectables** por variante
y por benchmark -> tests deterministas, cero red.

| Pieza | Responsabilidad | Reuso |
|-------|-----------------|-------|
| `GeoBenchTask` (frozen dataclass) | Una task agricola de GEO-Bench-2: `id`, `name`, `modality` (classification/segmentation), `label_space`, `split`, `n_examples`. | nueva |
| `GeoBenchItem` (frozen dataclass) | Un ejemplo: ruta del tile/chip + gold label/mask + metadata. | nueva |
| `AgroMindItEsItem` (frozen dataclass) | Un par Q&A bilingue (lang `it`/`es`, question, options/answer, familia del catalogo). Esquema **compatible con AgroMind original** (AC US-068). | reusa shape de `AgroMindItem` |
| `load_geobench2(root, *, tasks, max_per_task) -> list[GeoBenchTask]` | Carga via el loader oficial `geobench` filtrando a >=3 tasks agricolas; degrada a `[]` si el dataset no esta (modo blocker, NO inventa). | nueva |
| `load_agromind_itses(path) -> list[AgroMindItEsItem]` | Lee el JSONL de US-068 (250 it + 250 es). Falla-suave si el archivo no existe aun (US-068 = FUTURE). | reusa `_read_jsonl` patron |
| `eval_geobench2(variant, tasks, *, backend, seed) -> dict` | Para cada item: prompt VLM (clasifica el tile / nombra el cultivo) -> exact_match/F1 vs gold via `agent_metrics`. Text-only Qwen SKIP de items que exigen imagen (reporta `n_skipped`, como `eval_agromind`). | reusa metricas + patron skip |
| `eval_agromind_itses(variant, items, *, backend, judge, seed) -> dict` | Igual contrato que `eval_agromind` (exact_match, f1_squad, bertscore, hallucination), por idioma (it/es) ademas del agregado. | reusa `agent_metrics` |
| `run_paper_benchmark(variants, *, seeds=(0,1,2), backends, ...) -> dict` | Corre los **tres** benchmarks por variante×seed, agrega mean±std (reusa `agent_bench._aggregate`), corre Wilcoxon pareado (§3.3), loguea MLflow, exporta HTML + LaTeX. Checkpoint+resume reusando `_save_checkpoint`. | reusa `_aggregate`, `_save_checkpoint`, `_log_to_mlflow` patron |
| `main()` (argparse CLI) | `--variants`, `--seeds`, `--geobench-root`, `--agromind-path`, `--itses-path`, `--out-latex`, `--dump-jsonl`, `--no-mlflow`. | reusa patron CLI de `agent_bench.main` |

### 3.2 Metricas del AC y donde salen

| Metrica AC | Fuente | Nota |
|------------|--------|------|
| accuracy / exact_match | `agent_metrics.exact_match` | ya existe |
| F1 | `agent_metrics.f1_squad` (QA) + macro-F1 propio para GEO-Bench-2 clasificacion | el macro-F1 multi-clase es helper nuevo pequeño en paper_bench (no en agent_metrics, para no tocar su API) |
| BERTScore | `agent_metrics.bertscore_f1` | ya existe |
| tool-call accuracy | `agent_metrics.tool_call_accuracy` (via `agent_system_eval.eval_tool_calling`) | se REPORTA reusando el harness de sistema; no se reimplementa |
| hallucination rate | `agent_metrics.hallucination_rate` (judge inyectable) | ya existe |
| latencia p50/p95 | wrapper de timing nuevo (`time.perf_counter` por item) -> percentiles | helper local; NO inventa, mide la llamada real |
| costo por query | tabla de precios por modelo (Gemini 2.5-pro $1.25/$10 por M; Qwen on-prem = costo GPU-hora amortizado) × tokens reales | constante documentada; on-prem se reporta como "amortizado", no $0 |

### 3.3 Significancia estadistica (3 corridas + Wilcoxon)

- 3 seeds (mismo patron `_aggregate` de `agent_bench`) -> mean±std (error bars del AC).
- **Wilcoxon signed-rank pareado** Gemini vs Qwen por benchmark: helper `wilcoxon_paired(a, b)`
  sobre los scores por-item pareados (mismo orden de items), via `scipy.stats.wilcoxon`. Devuelve
  `(statistic, p_value, n_pairs)`. Se reporta p-value en la tabla del paper. `scipy` ya es dep del
  proyecto (verificar en `pyproject.toml`; si falta, `poetry add scipy`).
- Honestidad: con `n` chico el Wilcoxon puede no alcanzar significancia; se reporta el p-value REAL,
  nunca se afirma "diferencia significativa" sin el test.

### 3.4 Export LaTeX (tarea tecnica AC)

- `export_latex_table(results, out_path)` -> tabla `booktabs` con filas=variante, columnas=benchmark×metrica,
  celdas `mean ± std`, marca de significancia Wilcoxon. Estilo cientifico (CVPR/ISPRS) coherente con
  `paper/tables/`. Se escribe a `paper/tables/us-069/benchmark_comparison.tex`.

### 3.5 MLflow (tarea tecnica AC)

- `run_paper_benchmark` loguea via el patron de `agent_bench._log_to_mlflow`: experimento
  `us069_paper_bench`, un metric por `{variant}/{benchmark}/{metric}` (mean y std), tags
  `code_version` (git SHA) + `data_version` (DVC rev de GEO-Bench-2 + AgroMind subset). Server Docker
  `:5010` (gotcha `ml/AGENTS.md`: cerrar runs de subprocess).

### 2.2 Diseno de los escalones (JUSTIFICADO)

**Escalon inicial = 4 clases dominantes** (Meadow 1, Corn 3, Soft winter wheat 2, Grapevine 8): concentran la
mayor masa de pixeles (Meadow ~20.2k, Corn ~8k, SWW ~6k, Grapevine ~5.3k) -> el contrastivo InfoNCE tiene
maxima senal para anclar el espacio antes de introducir clases minoritarias.

**Esquema propuesto: `+2 clases por escalon` a partir de 4** -> `4 -> 6 -> 8 -> 10 -> 12 -> 14 -> 16 -> 18`
(8 escalones, objetivo 18). **Justificacion del paso +2 (vs saltos grandes 4->8->12->18)**:
- **Granularidad de diagnostico**: el usuario quiere medir "hasta cuantas clases se resuelve bien". Un paso
  fino (+2) localiza con precision el escalon donde la convergencia se rompe (criterio de parada AC-8), cosa
  que un salto de +4 ocultaria (no se sabria si fallo la clase 9 o la 12).
- **Estabilidad del init encadenado**: anadir solo 2 clases por escalon minimiza el shock de distribucion
  entre `best_{k-1}` y el dataset del escalon k -> el `load_state_dict(strict=False)` parte de un optimo
  cercano (currículum learning clasico: dificultad creciente suave).
- **Las clases cola (<200 px: Sorghum 18, Potatoes 13, Mixed cereal 17) entran al final**, aisladas en los
  ultimos 1-2 escalones, donde es mas probable que disparen el criterio de parada sin contaminar el
  diagnostico de las clases medias.

**Plan B (si el presupuesto H100 aprieta)**: `4 -> 8 -> 12 -> 18` (4 escalones, saltos de +4). Menos
granularidad de diagnostico pero ~la mitad de runs. El orquestador acepta el esquema de escalones como
**parametro** (`steps: list[int]` o `step_size: int`), de modo que cambiar de +2 a +4 es config, no codigo.
**Recomendacion: +2** salvo que el presupuesto de horas (Seccion 7) no quepa; entonces +4.

### 2.3 Criterio de convergencia por escalon (AC-6) y criterio de parada del curriculum (AC-8)

- **Convergencia de un escalon**: `loss_cls` (media movil de ultimos K steps) deja de bajar mas de `1e-3`
  durante `patience` epochs, O se alcanza el `n_epochs` maximo (M, ~20-40). Se guarda el `best` por menor
  `loss_cls` de validacion (o por mejor macro-F1 si el eval por clase corre por epoch).
- **Parada del curriculum** (cualquiera dispara `break`, AC-8):
  1. `n_classes == 18` alcanzado y convergido (`stop_reason=max_classes_reached`, exito).
  2. `macro-F1(clases_previas)` cae > `0.05` absoluto vs el escalon anterior (`prev_classes_degraded`).
  3. Ninguna clase NUEVA del escalon alcanza `F1 >= 0.30` (`new_classes_unacceptable`).
  4. Presupuesto H100 agotado (`budget_exhausted`) — guarda el ultimo best convergido.

**Principio rector**: el orquestador NO reimplementa el trainer ni el dataset; **encadena** escalones
(dataset builder US-036 -> trainer FarSLIP US-017 -> eval por clase -> decision de parada) y **persiste** el
lineage. El cambio de US-034/035 a esta US es: (a) datos italianos sinteticos -> **PASTIS real**, (b) CAP-32
-> **PASTIS directo 1..18 con n_regions=1**, (c) 1 run de 4 epochs -> **N escalones x M epochs con init
encadenado y criterio de parada**, (d) smoke -> **run productivo con eval por clase y best -> DVC**.

```python
    first (Meadow=1, Corn=3, Soft winter wheat=2, Grapevine=8), then by
    descending n_pixels down to the tail (<200 px: Potatoes=13, Sorghum=18).
    """


def class_ids_for_step(
    step_idx: int, *, step_size: int = 2, base: int = 4, ranking: list[int] | None = None
) -> list[int]:
    """Return the PASTIS class ids active at curriculum step ``step_idx``.

    Step 0 = the ``base`` (4) dominant classes; each step adds ``step_size`` (2)
    more from the cardinality ranking. Always a superset of the previous step.
    """


def select_step_prototypes(
    proto_18: np.ndarray, class_ids_all: list[int], class_ids_step: list[int]
) -> np.ndarray:
    """Select the US-033 prototypes for the step's classes (n_regions=1).

    Filters the (18, 384) parquet matrix by ``class_ids_step`` (PASTIS direct,
    no CAP expansion). Returns ``(len(class_ids_step), 384)``; row order matches
    ``class_ids_step`` so it aligns with the loss category_id indexing.
    """


def stop_criterion(
    metrics_curr: StepMetrics,
    metrics_prev: StepMetrics | None,
    *,
    f1_well_resolved: float = 0.50,
    f1_new_unacceptable: float = 0.30,
    prev_degradation_margin: float = 0.05,
    max_classes: int = 18,
) -> tuple[bool, str]:
    """Decide whether to stop the curriculum after a step.

    Returns ``(stop, reason)`` where reason in {max_classes_reached,
    prev_classes_degraded, new_classes_unacceptable, continue}.
    """
```

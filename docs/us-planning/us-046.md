## 2. Datos REALES disponibles (verificados, NO inventar)

- **Corpus texto**: `data/farslip/parcel_phenology_captions.parquet` (16,012 filas: `parcel_id` compuesto `patch_local`, `patch_id`, `class_id`, **`description`** texto fenologico ES real de Gemini). Tambien `pastis_captions.parquet` (caption por patch/escena) para metadatos de escena.
- **Vector recuperacion AlphaEarth 64-dim**: `data/features/features_fused_winning_pastis.parquet` (85,951 filas, columnas **`dim_00..dim_63`** = AlphaEarth 64-dim ya persistido). Join por `parcel_id`.
- **Descriptor fenologico**: `ml/features/phenology_description.py` (`generate_phenology_description`, `build_phenology_text_block`) — texto via Gemini/litellm, encoder MiniLM 384d.
- **DB**: `features_parcels.alphaearth_embedding VECTOR(64)`, `parcels.geom`. Extension `vector` activa.

## 3. Arquitectura

```
  /chat (US-047 loop)
     |
     |-- evento SSE: perceiver_observation  <-- PerceiverLayer.observe(parcel/aoi)
     |        (cultivo, fenologia, vigor, confianza, texto)   [Be My Eyes: TEXTO]
     |
     |-- (si rag_enabled) tool diferida retrieve_context(query, aoi)
     |        ml/agent/rag.py:
     |          1. ST_DWithin(rag_documents.geom, aoi, radius)   <- PostGIS
     |          2. embedding <-> cosine (pgvector, VECTOR(64))   <- AlphaEarth
     |          3. fusion ponderada (spatial_weight*prox + (1-w)*cos)
     |        -> contexto de parcelas vecinas reales (grounding)
     |
     v
  reasoner Gemini (frozen) razona sobre TEXTO
```

**PerceiverLayer** (`ml/agent/perceiver.py`): wrapper que dado un parcel_id (o AOI) recolecta la prediccion del clasificador (xgb-alphaearth, reusa `ml/agent/tools/classify.py`) + la descripcion fenologica (`explain`/`phenology_description`) y los empaqueta en `PerceiverObservation` (Pydantic). Su `to_prompt_block()` produce el texto que el reasoner consume. NO ejecuta el LLM.

## 9. Riesgos y mitigaciones

| Riesgo | Mitigacion |
|--------|------------|
| pgvector cosine sobre VECTOR(64) con corpus de 16k docs sin HNSW puede ser lento | El lite filtra primero por `ST_DWithin` (espacial), reduciendo candidatos antes del cosine. Corpus de la demo es fold-5 (subset). |
| El corpus tiene parcel_id compuesto; `rag_documents` lo guarda como TEXT | `parcel_id TEXT` + join por ese id; no forzar BIGINT. |
| Geometria de las parcelas PASTIS (Francia) vs demo Italia | El RAG-lite es para grounding del razonamiento sobre el corpus disponible (PASTIS); documentar que el corpus es PASTIS-R real. |
| Flag mal cableado -> RAG siempre activo | Test de aislamiento AC-10 + default off en Settings. |

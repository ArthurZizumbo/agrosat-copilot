### 2.1 Decisiones tecnicas clave

| # | Decision | Justificacion | Trade-off rechazado |
|---|----------|---------------|---------------------|
| D1 | **`ml/eval/interpretability.py` NUEVO**, separado de `ml/eval/metrics.py` (US-019) y de `ml/features/selection.py` (US-018) | Cohesion: interpretabilidad de modelos (SHAP + importance de modelos production) es un dominio propio. `selection.py::compute_feature_importance` es importance *exploratoria* de feature engineering; `interpretability.py` interpreta los modelos *production* | Meter SHAP en `selection.py`: mezcla feature engineering con interpretabilidad de modelos; en `metrics.py`: mezcla metricas con explicabilidad |
| D2 | **Reusar `compute_feature_importance` de US-018 para la importance nativa** (AC-1), envuelto por `feature_importance_table` | `selection.py::compute_feature_importance` ya hace RF Gini / XGB gain. US-020 NO lo re-implementa; `feature_importance_table` lo llama o extrae `feature_importances_` del modelo ya entrenado de US-019 (mas directo: el modelo production ya esta fiteado, no hay que re-entrenar) | Re-implementar importance: viola DRY (regla CLAUDE.md §7) |
| D3 | **SHAP multiclase: manejar explicitamente la salida lista-por-clase** | `TreeExplainer.shap_values()` sobre un clasificador de 20 clases devuelve una lista de 20 arrays (API clasica) o un array 3D `(n_samples, n_features, n_classes)` (API nueva con objeto `Explanation`). `compute_shap_values` normaliza ambos casos y para el summary global usa la **media de `|SHAP|` sobre clases y muestras**. Verificado con Context7 que la API depende de version | Asumir salida 2D: rompe con multiclase, error silencioso de shape |
| D4 | **Importancia global SHAP = `mean(|shap_value|)`** agregada sobre clases y muestras | Es el ranking estandar de SHAP para summary plots. Permite un "top-20 global" consistente entre las 20 clases | `max(|shap|)`: sensible a outliers; importancia por-clase: 20 rankings distintos, no hay "top-20 global" |
| D5 | **`is_alphaearth_dim` por convencion de nombres** | Las dimensiones AlphaEarth se nombran **`dim_00..dim_63`** (64-dim) — **prefijo real confirmado 2026-05-21** inspeccionando `data/cache/gee/alphaearth_pastis_parcels_2019_85951_enriched.parquet`. Una funcion pura que clasifica `feature_name → {alphaearth, spectral_index, s1, srtm, era5, geom}` (regex `^dim_\d{2}$` para AlphaEarth) permite cuantificar la dominancia (AC-4) sin hardcodear listas | Lista hardcodeada de 64 nombres: fragil si cambia el schema. Asumir prefijo `A##`: era una suposicion erronea de la version inicial del plan, corregida tras inspeccionar el parquet |
| D6 | **SHAP sobre un subsample del dataset** (no las 85.951 filas) | `TreeExplainer.shap_values` sobre 85k × 187 × 20 clases es costoso en memoria y tiempo. Subsample estratificado de ~2.000-5.000 filas (parametrico `shap_sample_size`) da un summary plot estable. Documentado en el notebook | SHAP sobre todo el dataset: minutos + posible OOM, sin ganancia interpretativa |
| D7 | **El bloque Dagster es "verificar el servicio existente", NO crear assets** | `dagster_project/` ya esta completo (definitions + 4 modulos). El valor de US-020 es SHAP; el asset `baseline_model` que orquestaria la cadena es una US propia. Alinear el servicio local (que el UI cargue) es deuda tecnica ligera coherente con lo que US-019 hizo con MLflow | Definir assets `baseline_model`/`feature_importance` en US-020: scope creep, ~+3 SP, fuera del criterio SHAP |
| D8 | **Si los joblib de US-019 no existen, fallback: entrenar in-notebook** | US-019 aun no esta codificada (R1). El notebook §3 intenta `joblib.load(artifacts/baseline_*.joblib)`; si falla, entrena un RF/XGB rapido con los hiperparametros base documentados en US-019. El SHAP corre igual. Se documenta el modo usado | Bloquear US-020 hasta US-019: encadenamiento rigido; el fallback permite avanzar en paralelo |
| D9 | **PNG con `dpi=200`, solo 3 commiteados** | Entregable visual del Avance 3 sin inflar el repo. El resto se regenera con el notebook | Commitear todos los PNG: bloat; ninguno: el revisor no ve los plots sin ejecutar |

### 2.2 Flujo de datos en runtime

```

   rf  = joblib.load("artifacts/baseline_rf_v1.joblib")    # o fallback entrenar (D8)

   shap_xgb = compute_shap_values(xgb.model, X_sample, "xgb")
   shap_summary_plot(shap_rf, X_sample, top_n=20)       → beeswarm

   top20 = shap_rf.global_importance.head(20)

5. Conclusiones validacion FE (AC-5)
   cruce top SHAP vs reports/feature_selection/anova_f_scores.csv (US-018)
   → notebook §5 + (si refuta) docs/product-backlog/us-020-fe-adjustments.md
```

### 2.3 Justificacion del stack

- **shap ^0.46+** (NUEVO via `poetry add --group ml shap`): `TreeExplainer`, `summary_plot`/`plots.beeswarm`, `dependence_plot`, `plots.waterfall`. Compatible con numpy 2.3.x. Licencia MIT.
- **scikit-learn 1.8** + **xgboost 3.2** (ya en `pyproject.toml`): `feature_importances_` (RF), `get_booster().get_score(importance_type="gain")` (XGB).
- **matplotlib (Agg)**: PNG `dpi=200`. SHAP usa matplotlib internamente.
- **polars 1.x**: I/O del parquet y tablas de importance (regla `ml/CLAUDE.md NEVER pandas`). SHAP requiere numpy/pandas en su borde → conversion explicita en helper privado.
- **joblib**: carga de los modelos de US-019.
- **dagster ^1.13** (ya en `pyproject.toml` grupo `dagster`): solo se verifica que el servicio levante; sin codigo nuevo.
- **Una sola dep nueva**: `shap`.

from dataclasses import dataclass
from typing import Literal
import numpy as np
import polars as pl
from matplotlib.figure import Figure

ModelKind = Literal["rf", "xgb"]
FeatureFamily = Literal["alphaearth", "spectral_index", "s1", "srtm", "era5", "geom", "other"]

@dataclass(frozen=True)
class ShapResult:
    """Resultado de un analisis SHAP multiclase.

    Attributes:
        values: array SHAP normalizado, shape (n_samples, n_features, n_classes).
        global_importance: pl.DataFrame (feature, mean_abs_shap, rank) — ranking
            global = media de |SHAP| sobre clases y muestras.
        feature_cols: nombres de las features (orden de `values`).
        base_values: valores esperados del explainer (n_classes,).
        model_kind: "rf" | "xgb".
    """
    values: np.ndarray
    global_importance: pl.DataFrame
    feature_cols: tuple[str, ...]
    base_values: np.ndarray
    model_kind: ModelKind

# === NATIVE IMPORTANCE ===

def feature_importance_table(
    model: ClassifierMixin,
    model_kind: ModelKind,
    feature_cols: tuple[str, ...],
) -> pl.DataFrame:
    """Importance nativa: RF Gini (`feature_importances_`) o XGB gain.

    Returns:
        pl.DataFrame (feature, importance, rank) ordenado desc.
    """

# === SHAP ===

def compute_shap_values(
    model: ClassifierMixin,
    X: pl.DataFrame,
    model_kind: ModelKind,
    *,
    feature_cols: tuple[str, ...],
    sample_size: int = 3000,
    random_state: int = 42,
) -> ShapResult:
    """Calcula valores SHAP con `shap.TreeExplainer` sobre un subsample
    estratificado. Normaliza la salida multiclase (lista-por-clase o 3D).
    """

def shap_summary_plot(
    shap_result: ShapResult,
    X: pl.DataFrame,
    *,
    top_n: int = 20,
) -> Figure:
    """Beeswarm/summary plot de las top-N features (matplotlib Agg, dpi=200)."""

def shap_dependence_plots(
    shap_result: ShapResult,
    X: pl.DataFrame,
    *,
    top_features: int = 5,
) -> list[tuple[str, Figure]]:
    """Dependence plot por cada uno de los top-N features. Devuelve
    [(feature_name, figure), ...].
    """

def shap_waterfall_plot(
    shap_result: ShapResult,
    *,
    row: int = 0,
    class_idx: int | None = None,
) -> Figure:
    """Waterfall plot para una prediccion ejemplo (fila `row`). Si
    `class_idx` es None usa la clase predicha.
    """

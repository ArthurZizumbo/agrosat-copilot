### 2.1 Decisiones tecnicas clave

| # | Decision | Justificacion | Trade-off rechazado |
|---|----------|---------------|---------------------|
| D1 | **El escenario (b) Sentinel-2 crudo se GENERA en US-022** — no existe en el repo | Verificado 2026-05-21: ningun parquet tiene las bandas `B02..B12` a nivel parcela. PASTIS-R las tiene en `DATA_S2/*.npy` como tensores `(T,10,128,128)`. `scripts/build_s2_raw_parcels.py` las agrega (media temporal + espacial por poligono). Sin esto, el CA "3 escenarios" no se cumple | Saltar el escenario (b): incumple el CA literal y pierde los 20 pts de "Metrica". Usar indices como proxy: metodologicamente debil (indice ≠ banda cruda) |
| D2 | **Las 3 vistas se alinean por `parcel_id` con inner join** sobre las 85.951 parcelas | Para que la comparativa sea justa, los 3 escenarios deben evaluarse sobre **exactamente el mismo set de parcelas** y los **mismos folds espaciales**. El inner join descarta parcelas que falten en algun escenario y garantiza comparabilidad | Evaluar cada escenario sobre su propio set: la comparacion deja de ser valida (distinto N, distintas clases) |
| D3 | **Mismo spatial CV 5-fold (`build_spatial_kfold`) para los 3 escenarios** | Heredado de US-019/021: spatial CV con buffer anti-leakage. Los 3 escenarios comparten los mismos `(train_idx, test_idx)` → el delta de F1-macro refleja el dataset, no la particion. Reusar los folds cacheados si US-019 los persistio | Folds distintos por escenario: el delta seria ruido de particion, no senal |
| D4 | **`train_time_s` = wall-clock del `fit` final** (no del CV) | El CA pide "tiempo de entrenamiento". Se mide el `fit` del modelo final sobre todo el dataset de cada escenario — comparable y reproducible (mismo hardware). Documentar la maquina en el notebook | Tiempo del CV completo: depende de `n_jobs` y del numero de folds, menos interpretable como "costo del modelo" |
| D5 | **El notebook `04_baseline.ipynb` es construido por `scripts/build_baseline_notebook.py`** (patron US-018) | US-019/020/021 ya extendieron este builder con §1-§6 y §5b. US-022 le anade §7-§8. El notebook se regenera de forma reproducible; papermill valida que sigue ejecutable. Patron identico a `build_us018_notebook.py` / `build_avance2_notebook.py` | Editar el `.ipynb` a mano: no reproducible, conflictos de merge entre las 4 US |
| D6 | **`max_samples` y `shap_sample_size` como parametros papermill** para el CI | El CA-7 pide papermill en CI. El notebook completo sobre 85.951 × 3 escenarios × 2 modelos × CV es lento; papermill en CI lo corre con parametros reducidos (`max_samples=5000`, `shap_sample_size=500`) en < 5 min. El notebook commiteado tiene los outputs del run completo | Notebook sin parametrizar: el CI tarda 30+ min o se omite, perdiendo la garantia de reproducibilidad |
| D7 | **Export LaTeX via `df.to_pandas().to_latex()` aislado en `export_comparison_latex`** | Polars no exporta LaTeX nativo. El unico uso de pandas es en este helper, encapsulado — no viola la regla `NEVER pandas` en espiritu (es I/O de presentacion, no procesamiento). Alternativa: construir el `.tex` con un template string | `tabulate` u otra dep nueva: innecesaria para una tabla de 6 filas |
| D8 | **mIoU se mantiene como proxy** (jaccard macro a nivel parcela, heredado US-019 D6) | Coherencia con US-019. El notebook §7 documenta de nuevo que la mIoU del baseline es un proxy; la mIoU densa real llega en EPIC 5 | Omitir mIoU: el CA pide "2 metricas relevantes" ademas de F1-macro; mIoU es una de ellas |
| D9 | **US-022 integra, NO re-implementa** las secciones de US-019/020/021 | §2-§6 y §5b ya las producen las US previas via el builder. US-022 solo anade §7-§8 y se asegura de que el notebook completo corre end-to-end. El grueso de US-022 es la comparativa + el escenario (b) | Re-escribir §2-§6: duplica trabajo y rompe la trazabilidad a US-019/020/021 |

### 2.2 Flujo de datos en runtime

```
1. (si falta) Generar escenario (b) — UNA vez
   scripts/build_s2_raw_parcels.py:
     para cada patch PASTIS en pastis_parcels_full.geoparquet:
       s2 = load_pastis_patch(patch_id)["s2"]          # (T,10,128,128)
       para cada parcela (poligono) dentro del patch:
         mascara del poligono → media temporal + espacial de las 10 bandas
     → data/cache/pastis/s2_raw_parcels_2019_85951.parquet  (85.951 × 12)

2. Cargar y alinear los 3 escenarios (D2)
   df_a = AlphaEarth 64-dim   (dim_00..dim_63)
   df_b = S2 crudo 10 bandas  (B02_mean..B12_mean)
   df_c = vector combinado    (187 features)
   join inner por parcel_id → 3 frames sobre el mismo set de parcelas

3. Spatial CV compartido (D3)
   cv_splits = build_spatial_kfold(parcels, k=5, buffer_km=1.0)  # o cacheado

4. Comparativa (AC-2, AC-4)
   build_comparison_table:
     for esc, df in [(a,df_a),(b,df_b),(c,df_c)]:
       for kind in [rf, xgb]:
         result = train_one_model(df, model=kind, cv=cv_splits)   # US-019
         metrics = compute_baseline_metrics(...)                  # US-019
         row = (esc, kind, f1_macro, f1_weighted, miou, train_time_s)
   → ComparisonResult (6 filas) → CSV + MD + LaTeX

5. Notebook §7-§8
   §7: tabla comparativa + barplot
   §8: discusion valor incremental AlphaEarth + conclusiones EPIC 5

6. Validacion secuencial
   make notebooks-check  → papermill end-to-end exit 0
```

### 2.3 Justificacion del stack

- **scikit-learn 1.8 + xgboost 3.2** (ya en repo): RF/XGB reusados via `train_one_model` de US-019.
- **polars 1.x**: I/O de los 3 parquets, joins, tablas (regla `ml/CLAUDE.md NEVER pandas`). Unico uso de pandas: `export_comparison_latex` (D7), encapsulado.
- **numpy**: agregacion de las bandas S2 dentro de los poligonos.
- **rasterio.features** o el patron de `scripts/vectorize_pastis_parcels.py`: para la mascara poligono→pixeles en el escenario (b).
- **papermill** (ya usado en `make notebooks-check`): validacion secuencial en CI.
- **matplotlib (Agg)**: barplot comparativo `dpi=200`.
- **Sin deps nuevas** — todo el stack ya esta en el repo.

import polars as pl

             train_time_s).
        best_scenario: nombre del escenario con mayor f1_macro.
        alphaearth_delta: delta de f1_macro de AlphaEarth puro vs S2 crudo
            (cuantifica el valor incremental del embedding).
    """
    table: pl.DataFrame
    best_scenario: str
    alphaearth_delta: float

    buffer_km: float = 1.0,
    max_samples: int = 0,
    random_state: int = 42,
) -> ComparisonResult:
    """Entrena RF+XGB sobre 3 escenarios con el mismo spatial CV.

    Args:

            Los 3 parquets se alinean por `parcel_id` (inner join).
        k_folds, buffer_km: parametros del spatial CV (build_spatial_kfold).
        max_samples: subsample estratificado para dev/CI (0 = todo).

    Returns:
        ComparisonResult con la tabla de 6 filas + el delta AlphaEarth.
    """

def export_comparison_latex(

        Path del .tex escrito.
    """

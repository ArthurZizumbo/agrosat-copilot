### 0.4 Patrón de montaje EXACTO confirmado con Context7 (titiler-core 2.x)

- **Mount:** `cog = TilerFactory(...)` → `app.include_router(cog.router, prefix=..., tags=[...])` + `add_exception_handlers(app, DEFAULT_STATUS_CODES)` (de `titiler.core.errors`). El factory expone `.router` (un `APIRouter`).
- **Ruta de tile en 2.x:** la default del factory es **`/tiles/{tileMatrixSetId}/{z}/{x}/{y}.{format}`** (el TMS va en el path, ej. `WebMercatorQuad`). **NO** es `/tiles/{z}/{x}/{y}.png`. → El contrato US-053 (`/tiles/{z}/{x}/{y}.png`, sin TMS) **no coincide** con la ruta default del factory. Esto fuerza la decisión §2.1 (adaptador de contrato + factory bajo `/cog`).
- **GDAL env por request:** se inyecta vía `environment_dependency=lambda: {...}` (reemplaza el deprecado `gdal_config=` — confirmado en `CHANGES.md` de titiler). Devuelve un dict de vars GDAL aplicadas dentro de un `rasterio.Env` por request.
- **NDVI:** `expression=(b1-b2)/(b1+b2)` (bandas 1-indexed), `rescale=-1,1`, `colormap_name=rdylgn` (o `viridis`). El endpoint del factory ya soporta `url`, `expression`, `rescale`, `colormap_name`, `color_formula`, `colormap` (JSON), `nodata`, etc.
- **Caché:** patrón oficial = subclasear `TilerFactory` y sobreescribir `register_routes` con un decorador `@cached` sobre el handler `tile`. Alternativa más simple y desacoplada (la que elegimos, §2.3): **adaptador propio `/tiles` con caché Redis explícita**, dejando el factory `/cog` sin tocar.

## 2. Arquitectura

### 2.1 Decisión clave — DOS superficies: factory `/cog` (AC literal) + adaptador `/tiles` (contrato US-053)

El problema: la ruta default del `TilerFactory` en titiler-core 2.x es `/tiles/{tileMatrixSetId}/{z}/{x}/{y}.{format}` (TMS en el path), mientras que **el AC pide `/cog/tiles/{z}/{x}/{y}.png`** y **US-053 fijó `/tiles/{z}/{x}/{y}.png`** (ambos sin TMS en el path). Solución: **exponer ambas, sin duplicar lógica de render.**

```
# Superficie 1 — factory TiTiler completo, montado bajo /cog (cumple el AC literal)
app.include_router(cog_tiler.router, prefix="/cog", tags=["cog"])
#   -> GET /cog/tiles/{tileMatrixSetId}/{z}/{x}/{y}.png?url=...&expression=...&rescale=...&colormap_name=...
#   -> ademas /cog/tilejson.json, /cog/info, /cog/statistics, /cog/preview, etc. (gratis del factory)

# Superficie 2 — adaptador de contrato estable /tiles (mantiene el contrato US-053 byte a byte)
app.include_router(tiles.router)   # prefix "/tiles" (sin TMS en el path)
#   -> GET /tiles/{z}/{x}/{y}.png?url=...&index=ndvi|ndwi|ndmi   (TMS fijo WebMercatorQuad)
```

**El adaptador `/tiles/{z}/{x}/{y}.png` NO reimplementa el render.** Resuelve `index` → `expression` + `rescale` + `colormap` (tabla §2.2), fija `tileMatrixSetId="WebMercatorQuad"`, y llama a **la misma función `tile()` del factory** (la dependencia `cog_tiler` se importa y su lógica de render se reusa). Implementación concreta: el adaptador construye los params y delega a un helper compartido `render_cog_tile(...)` que ambos caminos usan (DRY), envuelto por la caché Redis (§2.3). Así:
- `/cog/...` = potencia completa de TiTiler (expression/colormap/rescale libres) → cumple AC-2 literal.
- `/tiles/...` = contrato simple y estable del frontend (US-053) → cumple AC-5.
- Cero lógica de tiling duplicada; el TMS WebMercatorQuad es el default de MapLibre/XYZ.

> **Por qué no `prefix="/tiles"` directo sobre el factory:** chocaría con la ruta `/tiles/{z}/{x}/{y}.png` de US-053 (el factory pondría `{tileMatrixSetId}` donde US-053 espera `{z}`), rompiendo el contrato. El adaptador desacopla el contrato público de la API interna del factory (que cambia entre versiones de titiler).

### 2.2 Mapeo `index` → parámetros de render (adaptador `/tiles`)

Asumiendo orden de bandas farslip/S2 `[B02, B03, B04, B08]` (b1=azul, b2=verde, b3=rojo, b4=NIR). El AC escribe `(B8-B4)/(B8+B4)` (NDVI) — en índices de banda del COG = `(b4-b3)/(b4+b3)`.

| `index` | expression | rescale | colormap_name | Notas |
|---|---|---|---|---|
| `ndvi` | `(b4-b3)/(b4+b3)` | `-1,1` | `rdylgn` | NIR=b4, Rojo=b3. (AC: RdYlGn) |
| `ndwi` | `(b2-b4)/(b2+b4)` | `-1,1` | `rdbu_r` | Verde=b2, NIR=b4 (McFeeters). |
| `ndmi` | `(b4-b3)/(b4+b3)` ó SWIR si existe | `-1,1` | `viridis` | El recorte de 4 bandas **no tiene SWIR**; NDMI canónico (NIR-SWIR) no es computable. **Degrada honesto** a NIR/Rojo + `viridis` y se documenta, o devuelve `422 "ndmi requires SWIR band, not present in 4-band COG"`. **Decisión: `422` honesto** (no fabricar un NDMI falso). |

> El orden exacto de bandas se confirma leyendo el builder del dataset farslip; si el orden real difiere, se ajusta la tabla (el dato sigue siendo real). El AC nombra B8/B4 → la única semántica fija es "NIR y Rojo".

### 2.3 Caché Redis 15 min — adaptador (no middleware global)

**Decisión: caché explícita en el helper `render_cog_tile`, NO middleware ASGI global.** Razones:
1. Un middleware global cachearía TODA respuesta (`/healthz`, `/chat` SSE, errores) — indeseable y peligroso con SSE.
2. La clave debe ser **hash del endpoint completo** (path + querystring), que es exactamente lo que el helper ve. Un decorator/wrapper sobre el handler es el grano correcto.

```python
# backend/app/services/tile_cache.py
import hashlib, redis.asyncio as aioredis
from backend.app.core.config import get_settings

TILE_TTL_SECONDS = 900  # 15 min (AC-3)

def tile_cache_key(method: str, path: str, query: str) -> str:
    # Clave = hash del endpoint COMPLETO (path + query ordenado), prefijo namespaced.
    raw = f"{method}|{path}|{query}"
    return f"tile:{hashlib.sha256(raw.encode()).hexdigest()}"

async def cached_tile(request, render_coro) -> Response:
    settings = get_settings()
    client = aioredis.from_url(settings.redis_url)        # reusa redis_url (rate_limit lo usa)
    key = tile_cache_key(request.method, request.url.path, _sorted_qs(request.url.query))
    if (blob := await client.get(key)) is not None:
        return Response(blob, media_type="image/png",
                        headers={"Cache-Control": "public, max-age=900", "X-Tile-Cache": "HIT"})
    resp = await render_coro()                            # delega al render del factory
    if resp.status_code == 200:
        await client.setex(key, TILE_TTL_SECONDS, resp.body)
    resp.headers["Cache-Control"] = "public, max-age=900"
    resp.headers["X-Tile-Cache"] = "MISS"
    return resp
```

- **Clave** = `sha256` de `method|path|sorted(querystring)` → cubre `url`, `expression`, `rescale`, `colormap`, `z/x/y` (todo el endpoint, AC-3). El query se **ordena** para que el mismo tile con params en distinto orden colisione (1 sola entrada).
- **TTL 900 s** (`SETEX`).
- En **tests** el cliente Redis se inyecta como `fakeredis.aioredis.FakeRedis` (sin red; patrón backend `CLAUDE.md` "Redis via fakeredis").
- Se aplica a **ambas** superficies (`/tiles` y `/cog/tiles`), envolviendo el render compartido.

### 2.4 CORS + headers HTTP (AC-4)

- **CORS:** el `CORSMiddleware` ya montado en `main.py` con `allow_origins=settings.cors_allow_origins` y `allow_methods` incluyendo `GET`/`OPTIONS` **ya cubre** `/tiles` y `/cog`. **No se añade un segundo middleware** (sería redundante y rompería el orden). Se verifica que `cors_allow_origins` incluye el dominio del frontend (`frontend_url` / `cors_allowed_origins`).
- **Headers de caché HTTP:** cada respuesta de tile lleva `Cache-Control: public, max-age=900` (alineado con el TTL Redis) + `X-Tile-Cache: HIT|MISS`. Opcional `ETag` = el hash de la clave (permite `304` en revalidación del navegador). MapLibre respeta `Cache-Control` para no repedir el mismo tile.

### 2.5 GDAL / GCS env (AC-1, AC-6) — `environment_dependency`

```python
# backend/app/services/gdal_env.py
def gdal_gcs_environment() -> dict[str, str]:
    """GDAL/VSI env for reading COGs from GCS (vsigs) and tuning COG range reads.

    Returns the dict TiTiler applies inside a per-request rasterio.Env.
    """
    settings = get_settings()
    env = {
        # COG-friendly range reads (do not list the bucket dir on open).
        "GDAL_DISABLE_READDIR_ON_OPEN": "EMPTY_DIR",
        "CPL_VSIL_CURL_ALLOWED_EXTENSIONS": ".tif,.tiff,.TIF",
        "GDAL_HTTP_MERGE_CONSECUTIVE_RANGES": "YES",
        "GDAL_HTTP_MULTIPLEX": "YES",
        "VSI_CACHE": "TRUE",
        "VSI_CACHE_SIZE": "67108864",   # 64 MiB block cache
    }
    # GCS auth: only when a service account / bucket is configured (prod/staging).
    # In dev (no GCS) the dict stays GCS-agnostic and local/http COGs work.
    if settings.google_application_credentials:
        env["GOOGLE_APPLICATION_CREDENTIALS"] = settings.google_application_credentials
        # GDAL reads gs:// and /vsigs/ when credentials resolve via ADC/SA.
        env["CPL_GS_ENDPOINT"] = "https://storage.googleapis.com/"
    return env

# en el factory:
cog_tiler = TilerFactory(environment_dependency=gdal_gcs_environment)
```

- **`url=gs://bucket/...`** → rio-tiler/GDAL lo resuelve vía `/vsigs/` cuando `GOOGLE_APPLICATION_CREDENTIALS` apunta a la SA (o ADC en Cloud Run). **`GDAL_DISABLE_READDIR_ON_OPEN=EMPTY_DIR`** es crítico para no listar el bucket en cada open (latencia/coste).
- **Dev sin GCS:** sin `google_application_credentials`, el dict no añade auth GCS; `url` local (path absoluto / `file://`) o `http(s)://` funciona → permite el test con COG real local (AC-6).
- **PROJ:** ver Riesgo R1 (entorno Windows dev tiene un PROJ de PostgreSQL que secuestra `PROJ_DATA`; se pinea `PROJ_DATA`/`PROJ_LIB` al `proj_data` de rasterio).

### 2.6 Variables nuevas en `Settings` (extra="forbid")

Ninguna estrictamente nueva: se reusan `redis_url`, `google_application_credentials`, `gcs_data_bucket`, `gcp_project_id`. **Si se añade un flag de TTL configurable** (`tile_cache_ttl_seconds: int = 900`), debe declararse en `Settings` o el arranque rompe (`extra="forbid"`). Decisión: **constante `TILE_TTL_SECONDS=900` en el módulo** (el AC fija 15 min; no necesita ser configurable). Cero variables nuevas → cero riesgo de `extra="forbid"`.

## 4. Fixture de COG REAL (regla Arthur, cero sintético)

**Origen del raster real:** un recorte farslip de Pianura Padana — **píxeles Sentinel-2 reales** (`data/farslip_pairs/pianura_padana/crops/<crop_id>.tif`, 4 bandas uint16 256×256) — más sus **coordenadas reales** (`lat`/`lon` del `manifest.parquet`, ej. `lat=45.0890, lon=9.6022`, `cap_class=soia`). **No hay `np.random` en ningún punto.**

Construcción del COG válido y georreferenciado (en el fixture de test, materializado en `tmp_path`, no commiteado):

```python
# backend/tests/conftest.py (esbozo)
import os, rasterio
# PROJ FIX (Riesgo R1): pinear PROJ_DATA al proj de rasterio ANTES de importar CRS-dependientes.
os.environ.setdefault("PROJ_DATA", os.path.join(os.path.dirname(rasterio.__file__), "proj_data"))

import polars as pl
from rasterio.transform import from_origin
from rasterio.warp import transform as warp_transform
from rio_cogeo.cogeo import cog_translate
from rio_cogeo.profiles import cog_profiles

@pytest.fixture(scope="session")
def real_cog(tmp_path_factory) -> Path:
    """Build a valid georeferenced COG from REAL farslip S2 pixels + REAL lat/lon."""
    man = pl.read_parquet("data/farslip_pairs/pianura_padana/manifest.parquet")
    row = man.row(0, named=True)                 # recorte real + sus lat/lon reales
    with rasterio.open(row["crop_path"]) as src:
        data = src.read()                        # (4, 256, 256) PIXELES REALES, sin tocar
    # Coordenadas reales -> EPSG:3857 (WebMercator) para que TiTiler calcule tiles XYZ.
    lon, lat = row["lon"], row["lat"]
    cx, cy = warp_transform("EPSG:4326", "EPSG:3857", [lon], [lat])
    res = 10.0                                   # Sentinel-2 = 10 m/px
    transform = from_origin(cx[0] - 128*res, cy[0] + 128*res, res, res)
    raw = tmp_path_factory.mktemp("cog") / "real_s2.tif"
    profile = dict(driver="GTiff", height=256, width=256, count=4,
                   dtype="uint16", crs="EPSG:3857", transform=transform)
    with rasterio.open(raw, "w", **profile) as dst:
        dst.write(data)                          # mismos pixeles reales
    out = raw.with_name("real_s2_cog.tif")
    cog_translate(raw, out, cog_profiles.get("deflate"), web_optimized=True)  # COG valido + overviews
    return out                                   # rio_cogeo.cog_validate(out) -> True
```

- **Real en todo:** píxeles del recorte S2 real + lat/lon real del manifest. Solo se **asigna** un CRS+transform georreferenciado (centrado en las coordenadas reales del recorte) — operación legítima, no fabricación de datos.
- El COG resultante pasa `rio_cogeo.cog_validate` (tileado + overviews) y es servible por TiTiler en `WebMercatorQuad`.
- `res=10 m/px` (S2). El `z` del test se elige para que el tile XYZ del centro intersecte el footprint (helper `morecantile.WebMercatorQuad` → tile de `(lon,lat)` a un `z` dado).

## 6. Riesgos

| # | Riesgo | Mitigación |
|---|--------|-----------|
| R1 | **PROJ secuestrado en Windows dev**: hay un PostgreSQL/PostGIS con `proj.db` viejo (`DATABASE.LAYOUT.VERSION.MINOR=2`) que rompe `CRS.from_epsg(3857)` y, en cadena, el import de `titiler.core`/`rio_tiler` (verificado: `CRSError`). | **Pinear `PROJ_DATA`/`PROJ_LIB`** al `proj_data` bundled de rasterio **antes** de importar cualquier módulo CRS (en `conftest.py` y, para runtime, en el arranque del proceso / Dockerfile `ENV PROJ_DATA=...`). Verificado que con el env pre-import `CRS.from_epsg(3857)` resuelve. En Cloud Run (Linux) el conflicto no existe; es un riesgo de dev box. |
| R2 | **Ruta del factory ≠ contrato US-053** (`/tiles/{TMS}/{z}/{x}/{y}` vs `/tiles/{z}/{x}/{y}`) | Adaptador `/tiles` + factory bajo `/cog` (§2.1); el adaptador fija `WebMercatorQuad` y delega al render compartido. Contrato US-053 intacto (test 4). |
| R3 | **Recorte farslip NO es COG** (sin CRS/overviews/tileado) | El fixture **construye** un COG válido desde los píxeles reales + lat/lon real (§4); `cog_validate` lo confirma. No se sirve el `.tif` crudo. |
| R4 | **Orden de bandas farslip** incierto (¿`[B02,B03,B04,B08]`?) | Confirmar leyendo el builder del dataset; la tabla `INDEX_RENDER` se ajusta. El AC solo fija semántica NIR/Rojo; el dato es real igual. |
| R5 | **NDMI sin SWIR** en COG de 4 bandas | `422` honesto (`"ndmi requires SWIR band"`), no fabricar un NDMI falso (regla Arthur). Documentado en §2.2. |
| R6 | **Caché global accidental** (middleware) cachearía `/chat` SSE | Caché explícita en el helper de render (§2.3), NO middleware ASGI. Solo `/tiles` y `/cog/tiles` se cachean. |
| R7 | **GCS auth en prod** (vsigs sin SA) | `environment_dependency` añade `GOOGLE_APPLICATION_CREDENTIALS` solo si está configurado; en Cloud Run usa ADC de la SA del servicio (`gcs-tiling@...`). `GDAL_DISABLE_READDIR_ON_OPEN=EMPTY_DIR` evita listar el bucket. Documentar la SA con `storage.objectViewer` sobre `gcs_data_bucket`. |
| R8 | **`extra="forbid"`** rompe arranque si se añade var no declarada | Cero variables nuevas (TTL como constante de módulo). Se reusan `redis_url`/`google_application_credentials`/`gcs_data_bucket`. |
| R9 | **Tamaño del body en Redis** (PNG ~10-50 KB) × muchos tiles | TTL 15 min acota la huella; clave namespaced `tile:` permite `SCAN`/flush selectivo. Aceptable para MVP. |

## 7. Mapeo rúbrica A6

- **App MVP desplegable**: overlay raster NDVI/NDWI sobre MapLibre sin pre-renderizar — cierra el bucle visual del producto (mapa + datos + IA).
- **Ingeniería madura**: TiTiler montado *dentro* de la imagen backend (un solo servicio, menos superficie de despliegue/coste — alineado FinOps ~$115/mes), GDAL `vsigs` + caché Redis + headers HTTP correctos.
- **Degradación honesta**: NDMI sin SWIR → `422` (no dato falso); COG inexistente → error mapeado; dev sin GCS funciona con COG local real.
- **Rigor de datos (regla Arthur)**: el test de render usa un COG construido desde **píxeles Sentinel-2 reales + coordenadas reales** del corpus farslip, no `np.random`.

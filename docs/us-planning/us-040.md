>    espacial del meta-learner se hace **particionando el fold-5 por geografia** (sub-folds espaciales
>    via `build_spatial_kfold` sobre las parcelas del fold-5), no re-prediciendo otros folds. Se documenta
>    como R-OOF-DEPTH. El blending usa un holdout espacialmente disjunto extraido del mismo fold-5.

>    aislado) reusando helpers de `avance4_figures.py` (DRY).
> 3. **Votante #3 = U-TAE, no "TSViT base".** El plan v8 menciona "TSViT base" como tercer votante denso,
>    pero `CHECKPOINT_REGISTRY` / OOF de US-031 solo tienen `tsvit-pheno`, `utae`, `unet`, `deeplabv3plus`,

### 1.2 Metricas y umbrales esperados (golden + objetivos)

**Umbral minimo de exito (rubrica)**: al menos **un ensamble** debe igualar o superar el mejor individual
en F1-macro sobre **fold-5 held-out**.

| Ensamble | Metrica primaria | Umbral minimo | Esperado | Justificacion |
|----------|------------------|---------------|----------|---------------|
| Mejor individual | F1-macro (TSViT-pheno) | baseline = **0.6253** | 0.6253 | Referencia fija del proyecto. |
| E1 Voting (pixel) | F1-macro fold-5 | `>= 0.6253` | 0.63-0.65 | Soft-vote de 3 densos reduce varianza; ganancia tipica +1-2 pts si miembros decorrelacionados. |
| E2 Bagging (parcela) | F1-macro fold-5 | `>= 0.55` (tabular puro) | 0.55-0.60 | XGB-AlphaEarth tabular es mas debil que densos; bagging reduce varianza pero no cierra el gap con densos. |
| E3 Stacking (parcela) | F1-macro fold-5 | `>= 0.6253` | 0.63-0.66 | Meta-learner aprende a pesar miembros heterogeneos; tipicamente el mejor de los 4. |
| E4 Blending (parcela) | F1-macro fold-5 | `>= 0.62` | 0.62-0.65 | Pesos simplex Optuna; algo por debajo de stacking pero mas robusto a overfit del meta. |

**Golden values (tests, computo puro determinista, sin inferencia real)**:
- `mean(probs)` de Voting suma 1 por pixel (tol `1e-5`); argmax determinista con seed fija.
- Pesos de Blending: `all(w >= 0)` y `abs(sum(w) - 1) < 1e-6`.
- Bagging: con `n_bags` bootstraps y semillas distintas, los indices muestreados difieren (sin fuga).
- Stacking: las features del meta en una fila de sub-fold `k` provienen solo de base learners
  predichos en folds `!= k` (anti-fuga verificable por mascara de fold).

        +-----------------------------+-----------------------------+

                       |                              |
        +--------------v------------+   +-------------v---------------------------+
        | E1 Voting (homogeneo)     |   | E2 Bagging  E3 Stacking  E4 Blending     |
        | TSViT-pheno + U-TAE + UNet|   | (parcela; reconciliacion ya en US-031)   |
        | mean(probs) -> argmax     |   | XGB-AlphaEarth / base learners parcela   |
        +---------------------------+   +------------------------------------------+

### 2.2 Clase base `EnsembleModel` (DRY)

Clase abstracta comun en `ml/ensemble/base.py` con el contrato compartido por los 4 ensambles:
carga de OOF, normalizacion de espacio (pixel vs parcela), evaluacion **siempre sobre fold-5** y
logging MLflow. Cada ensamble implementa `fit` / `predict_proba`; `EnsembleModel` provee
`load_oof_members`, `evaluate`, `log_to_mlflow` y el guardado del modelo elegido.

### 2.3 E1 Voting homogeneo (pixel)

- Lee `oof_{tsvit-pheno,utae,unet}_fold5.parquet` (por-pixel) via `read_softmax_parquet`.
- Promedia las probabilidades post-softmax `(18,128,128)` de los 3 miembros (media aritmetica;
  variante ponderada opcional fuera de alcance).
- `pred = mean(probs).argmax(axis=0)`. NUNCA promedia logits (la entrada de US-031 ya es post-softmax;
  el ensamble no tiene acceso a logits por diseno).
- Metricas densas sobre fold-5 reusando `ml/eval/dense_metrics.py`.

### 2.4 E2 Bagging tabular (parcela)

- Miembro: XGBoost-AlphaEarth (reusa `build_estimator("xgb", ...)` / `SpatialXGBClassifier` de
  `ml/train/baseline.py`).
- `n_bags` bootstraps distintos del training set (folds 1-4 tabulares); cada bag con seed propia.
- Tuning Optuna de hiperparametros XGB (max_depth, eta, subsample, colsample_bytree, n_estimators).
- Salida = promedio de `predict_proba` por parcela sobre las parcelas de fold-5.

### 2.5 E3 Stacking heterogeneo (parcela) + reconciliacion

- Base learners (3): `oof_parcel_tsvit-pheno_fold5`, `oof_parcel_utae_fold5` (ya reconciliados a parcela
  por US-031 via `pixel_to_parcel_probs`), y XGBoost-AlphaEarth (tabular).
- Meta-learner: XGBoost o regresion logistica multinomial.
- **Anti-fuga (clave)**: el meta-learner se entrena SOLO sobre las predicciones OOF de los base learners.
  Como solo hay fold-5 held-out, se hace **CV espacial dentro del fold-5**: `build_spatial_kfold`
  particiona las parcelas de fold-5 en sub-folds geograficos (H3 res 5 + KMeans + buffer 1 km); para cada
  sub-fold `k` el meta se entrena con las predicciones OOF de los demas sub-folds y se evalua en `k`. Las
  features del meta en una fila NUNCA provienen de un base learner que vio esa fila.
- **Reconciliacion pixel<->parcela** (documentada): los miembros densos ya estan reducidos a parcela en
  US-031 mediante moda/promedio de probabilidades dentro de la geometria de parcela (`method="mean"` por
  defecto). Pureza PASTIS-R ~98%: la mayoria de parcelas son monoclase; el caveat son los **pixeles mixtos
  de margen** que pueden pertenecer a dos parcelas, sesgando levemente el promedio de las parcelas pequenas.
  Se documenta y se reporta `n_pixels` por parcela para auditar parcelas con soporte bajo.

### 2.6 E4 Blending Optuna (parcela)

- Mismos 3 base learners que el Stacking.
- Combinacion lineal por **pesos simplex** `w_i >= 0`, `sum(w_i) = 1` sobre las probabilidades de parcela.
- Optuna optimiza los pesos sobre un **holdout espacialmente disjunto** (un sub-fold geografico del
  fold-5 separado via `build_spatial_kfold`), con objetivo que minimiza el gap F1 train-val:
  `maximize f1_val - lambda * |f1_train - f1_val|`.
- Parametrizacion simplex via softmax de logits o Dirichlet sampling en el espacio Optuna.

### 2.7 Reporte y comparativa

- `build_comparison_table()` consolida mejor individual + 4 ensambles + tiempo de inferencia + modelo
  elegido (tag `chosen_model` en MLflow).
- Figuras en `ml/eval/ensemble_figures.py` (reusa helpers de `avance4_figures.py`).

| `test_bagging.py::test_bootstraps_distinct` | `n_bags` muestras con seeds distintas -> indices distintos. |
| `test_bagging.py::test_optuna_study_runs` | Study Optuna con `>=1` trial; best_params poblado. |
| `test_stacking.py::test_meta_sees_only_oof` | **Anti-fuga**: features del meta en sub-fold k provienen solo de folds != k. |
| `test_stacking.py::test_spatial_cv_used` | El stacking usa `build_spatial_kfold` (no random split). |
| `test_blending.py::test_weights_on_simplex` | `all(w >= 0)` y `abs(sum(w) - 1) < 1e-6`. |
| `test_blending.py::test_holdout_spatially_disjoint` | Holdout via `build_spatial_kfold`, disjunto del train de pesos. |
| `test_anti_leakage.py::test_report_fold5_not_fold4` | `evaluate(fold=4)` -> `ValueError`; solo fold-5 valido. |
| `test_anti_leakage.py::test_probs_not_logits` | Toda entrada de ensamble suma 1 y `>= 0` (post-softmax). |
| `test_base.py::test_load_oof_members` | Carga pixel/parcela desde OOF; esquema correcto. |

Objetivo cobertura ML `>= 70%` en `ml/ensemble/`. `make check` limpio (ruff + mypy).

## 7. H100 / presupuesto de computo

**NO requiere H100.** Los 4 ensambles **reutilizan los OOF de US-031** (ya inferidos) y no re-infieren
densos:

- **E1 Voting**: solo promedia probabilidades en CPU/numpy. Coste ~ segundos.
- **E2 Bagging**: entrena `n_bags` XGBoost-AlphaEarth (tabular, `tree_method="hist"`, GPU local opcional
  via `resolve_xgb_device()`) + Optuna. CPU suficiente; minutos.
- **E3 Stacking**: meta-learner (logreg/XGB) sobre features OOF de parcela; CPU. Minutos.
- **E4 Blending**: Optuna sobre pesos simplex (evaluacion vectorizada de probabilidades). CPU. Minutos.

**Presupuesto VRAM**: N/A para H100 (no se toca la ventana de 80 h). XGBoost en GPU local (RTX 4070)
opcional y acotado (`<= 1 GB` VRAM por bag); Optuna es CPU-bound. El reuso de OOF es precisamente lo que
evita re-inferir los densos. Si Bagging corre solo CPU, ningun consumo de GPU.

## 9. Riesgos y mitigaciones

| # | Riesgo | Severidad | Mitigacion |
|---|--------|-----------|------------|
| **R-LEAK** | **FUGA (riesgo #1, lo mas importante de la rubrica)**: meta-learner viendo predicciones no-OOF; reportar en fold-4 (seleccion) en vez de fold-5; promediar logits. | Critica | `EnsembleModel.HELD_OUT_FOLD=5` fijo; `evaluate(fold!=5)->ValueError`; meta entrenado solo sobre OOF con CV espacial (mascara de fold testeada); entrada siempre post-softmax (sum-to-1). `test_anti_leakage.py` consolida los 3 cortes. |
| **R-OOF-DEPTH** | Un solo fold held-out (US-031 solo dumpeo fold-5) limita el "CV espacial sobre OOF" a sub-folds del fold-5, no a 5 folds OOF estrictos. | Alta | Documentar: CV espacial = particion geografica del fold-5 via `build_spatial_kfold`. El anti-fuga se mantiene (un base learner no vio las parcelas del sub-fold de evaluacion porque todas son fold-5 held-out). |
| **R-MARGIN** | Pixeles mixtos de margen al reconciliar pixel->parcela sesgan parcelas pequenas (pureza PASTIS ~98%, no 100%). | Media | `method="mean"` renormaliza; reportar `n_pixels` por parcela; auditar parcelas con soporte bajo; documentar caveat. |
| **R-VOTE** | "TSViT base" no esta dumpeado; tercer votante denso = U-TAE/U-Net. | Media | Voting usa TSViT-pheno + U-TAE + U-Net; documentar gap; sustituible si se dumpea TSViT base. |
| **R-TAB-FEATURES** | Features tabulares AlphaEarth por parcela PASTIS-R para XGB pueden no estar materializadas. | Media | Verificar `data/features/*` (DVC); si faltan para PASTIS-R, el miembro tabular usa las features disponibles o se documenta su ausencia; Bagging/Stacking degradan a 2 base learners densos si XGB-AlphaEarth no es viable (con caveat explicito). |
| **R-MLFLOW-RUNNING** | Runs lanzados por subprocess quedan RUNNING. | Baja | Cerrar runs manualmente; usar `with track_experiment(...)` que cierra al salir. |
| **R-OPTUNA-COST** | Optuna de Bagging+Blending puede tardar si `n_trials` alto. | Baja | `n_trials` acotado (30 bagging, 50 blending); CPU-bound, sin H100; `optuna_convergence_figure` para auditar convergencia. |

## 3. Insumos reales verificados (recon)

### 3.1 Esquema AgroMind real (a replicar — `ml/eval/agent_bench.py`)

`agent_bench.py::load_agromind_subset` ya parsea el subset real AgroMind de 500 items
(`data/agromind/agromind_subset_500.json`). El dataclass `AgroMindItem` (linea ~287) define los
campos canonicos: id de tipo de pregunta (`type_id`), `item_id`, texto, opciones multiple-choice,
respuesta (letra), `image_path`, flag `is_multimodal`. **El esquema JSONL de AgroMind-IT/ES debe
emitir exactamente estos campos** para que `load_agromind_subset` (o un loader gemelo) lo consuma
sin cambios -> esto cumple el CA "compatible con AgroMind original" de forma verificable, no
declarativa.

> Decision: el generador NO redefine el contrato; lo IMPORTA. Una funcion
> `to_agromind_item(record) -> AgroMindItem` cierra el loop: si el `AgroMindItem` se construye sin
> error, el record es compatible. El test lo ejerce.

### 3.2 Las 10 familias del catalogo del copiloto (taxonomia)

Las 10 familias del CA mapean a las tools/intents del agente (catalogo en
`context/RefinamientoPlaneacionAgroSatCopilot_v8.md` §US-046 y las 9 FunctionTools de
`ml/agent/tools/`):

| # | Familia | Tool/intent ancla del copiloto |
|---|---------|--------------------------------|
| 1 | clasificacion | `classify_new_parcel` |
| 2 | cuantificacion | area/conteo por clase |
| 3 | vigor | indices NDVI/EVI |
| 4 | estres hidrico | NDWI / humedad |
| 5 | fenologia | `phenology_descriptor` (Wen et al. 2025) |
| 6 | comparacion | `compare_models` / parcela-vs-parcela |
| 7 | anomalias | deteccion de outliers temporales |
| 8 | metadata | atributos de parcela / fecha adquisicion |
| 9 | intersecciones | spatial join / vecindad (PostGIS) |
| 10 | explicabilidad | `explain_prediction` (perceiver -> texto) |

El generador parametriza `family` por este enum -> garantiza cobertura de las 10 (250 IT + 250 ES
=> ~25 pares por familia por idioma como target del generador, configurable).

### 3.3 Cliente Gemini 2.5-pro existente

El proyecto ya usa Gemini 2.5-pro GA como reasoner (`ml/agent/backends/`, key via `get_settings()`).
El generador REUTILIZA ese cliente (`google-genai`, modelo GA `gemini-2.5-pro`, 1M ctx). **No** se
crea un cliente nuevo ni se hardcodea el id; se lee de settings. Si la key falta, el generador hace
dry-run (emite los prompts y el plan de N pares por familia, sin llamar a la API) -> ese es el modo
autonomo aqui.

### 3.4 Imagenes Sentinel-2 reales de Italia

El seed debe correr sobre imagenes S2 reales de Italia (no sinteticas). La descarga via GEE
(`agrosat-gee-alphaearth` skill) requiere service account / ADC -> **BLOCKER** (igual que el resto
de jobs GEE del proyecto). El generador acepta un `image_root` parametrizable; en modo autonomo
trabaja sobre un fixture de 1-2 imagenes de referencia (o sin imagen, modo texto) para ejercer el
pipeline, NUNCA fabrica un dataset de imagenes.

## 5. Enfoque tecnico

### 5.1 Esquema (`ml/benchmark/schema.py`)

- `class QuestionFamily(StrEnum)` — las 10 familias (§3.2). Identificadores en INGLES
  (`classification`, `quantification`, `vigor`, `water_stress`, `phenology`, `comparison`,
  `anomaly`, `metadata`, `intersection`, `explainability`).
- `@dataclass class QAItem` — campos espejo de `AgroMindItem`: `item_id: str`, `family:
  QuestionFamily`, `language: Literal["it", "es"]`, `question: str`, `options: list[str]`,
  `answer: str` (letra), `image_path: str | None`, `is_multimodal: bool`, `reviewed: bool`,
  `reviewer: str | None`, `source: Literal["gemini-seed", "human-edited"]`. Type hints obligatorios,
  docstrings Google-style en INGLES.
- `to_agromind_item(item: QAItem) -> AgroMindItem` — construye el `AgroMindItem` real (import desde
  `ml.eval.agent_bench`). Si construye sin error -> compatible. **Esta funcion ES la prueba de
  compatibilidad** del CA, ejecutable en test.
- `dump_jsonl` / `load_jsonl` — round-trip; rechazan cualquier registro con marca de train
  (eval-only por diseno).

### 5.2 Generador seed (`ml/benchmark/agromind_it_es_generator.py`)

- `PROMPT_TEMPLATES: dict[QuestionFamily, dict[str, str]]` — un template por familia x idioma
  (prosa visible en IT/ES, identificadores en EN). El template instruye a Gemini 2.5-pro a generar
  un par Q&A multiple-choice agricola anclado en una imagen S2 real de Italia.
- `class SeedGenerator` con `get_settings()` para la key Gemini (NUNCA `os.environ`); modelo GA
  `gemini-2.5-pro` leido de settings.
- `generate(family, language, n, image_root) -> list[QAItem]`. Si no hay key o `dry_run=True`:
  emite el PLAN (prompts + conteo objetivo) sin llamar a la API y marca `source="dry-run"`. Esto es
  lo que corre autonomo aqui.
- `structlog` para todo logging; sin `print`.
- Escritura a `data/benchmark/agromind_it_es/seed.jsonl` (gitignored si pesa; el fixture si va al
  repo).

### 5.3 Interfaz de revision (`ml/benchmark/review_app.py`)

- App Streamlit: carga `seed.jsonl`, muestra par + imagen S2, botones Aceptar / Editar / Rechazar,
  campo reviewer + idioma. Al aceptar/editar marca `reviewed=True`, `source="human-edited"`,
  registra `reviewer`. Export del split aceptado a `agromind_it_es_500.jsonl`.
- Prosa visible (labels, instrucciones) en ES (UI del miembro del equipo) — el contenido de los
  pares queda en su idioma nativo IT/ES.
- La app es el ENTREGABLE de codigo; correrla con reviewers reales es el BLOCKER de revision humana.

### 5.4 Metadata Zenodo (`ml/benchmark/zenodo_metadata.py`)

- `build_zenodo_metadata() -> dict` con titulo, creators, licencia `CC-BY-4.0`, keywords, descripcion
  (eval-only, 500 pares IT/ES, 10 familias). Escribe `.zenodo.json`.
- **No** incluye la llamada HTTP de upload (eso es blocker — requiere token Zenodo del sponsor).
  El builder de metadata si se prueba (estructura valida).

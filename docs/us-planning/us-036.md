### 1.2 Metricas verificables (POC, no SOTA)

- **Loss contrastiva por stage** (`loss_cls`, InfoNCE region-categoria, n_regions=1): se reporta por epoch.
  Umbral minimo POC: `loss_cls` de Stage-1 epoch 1 **< loss_cls epoch 0** (la mecanica aprende algo en 2ep
  con 4 clases). Para 4 clases, `ln(4)=1.386` es el loss de chance; Stage-1 debe quedar por debajo de chance.
- **Convergencia inter-stage**: `loss_cls` de Stage-2 epoch 0 (warm-start) **<** `loss_cls` de un Stage-2-from-scratch
  epoch 0 (control), demostrando que la transferencia del encoder ayuda. Para 18 clases, chance = `ln(18)=2.890`.
- **No-degradacion (gate del fallback AC-9)**: `loss_cls` final de Stage-2 (warm) **<=** `loss_cls` final de
  Stage-2-from-scratch + 0.05. Si NO se cumple -> activar fallback (entrenar 18-clase desde cero).
- **F1/IoU por clase**: **NO aplica** en US-036. FarSLIP destila un encoder contrastivo (CLS + patches), no
  produce mascaras densas; las metricas densas se evaluan en la cadena de segmentacion (EPIC 5) y en US-037
  (extractor FarSLIP vs AlphaEarth). Aqui la metrica es el loss contrastivo y la convergencia inter-stage.

## 2. Arquitectura de la solucion

### 2.1 Flujo end-to-end

```
PASTIS-R real (data/PASTIS-R/DATA_S2/S2_<pid>.npy  (T,10,128,128) int16)
   |
   v
PastisFilter(mode="dominance_ratio", ratio=3.0, meadow_class=1, target_classes=clases_activas)   # US-032 REUSO
   filter_folds(folds) -> kept_ids (patches 3:1, no sobre-dominados por Meadow)
   |
   v
PastisPairDataset(n_classes, folds)   # NUEVO (ml/farslip/pastis_pair_dataset.py)
   por patch kept:
     load_pastis_patch(pid)  ->  s2 (T,10,128,128)   # ml.ingest.pastis_loader REUSO
     composite pico-NDVI:
        NDVI_t = (B08 - B04)/(B08 + B04)   por timestep   (B04=idx2, B08=idx6 en layout 10-banda)
        t* = argmax_t  mean_spatial(NDVI_t)              # timestep de pico NDVI medio
        img4 = s2[t*, [B02=0,B03=1,B04=2,B08=6], :, :]   # -> (4,128,128) -> /10000 -> resize 224
     clase dominante:
        hist = bincount(semantic, 20); excluir {0,19}; restringir a clases_activas
        dom = argmax(hist[clases_activas])
        category_id = indice de dom dentro de clases_activas (0..n_classes-1)
     texto/prototipo:
        load_class_prototype_embeddings()  -> proto_18 (18,384) MiniLM   # US-033 REUSO, NO regenerar
        proto_active = proto_18[clases_activas]   (n_classes,384)         # DIRECTO, sin expand_to_cap
     yield {"image": img4, "region_id": 0, "category_id": dom_idx}
   |
   v
create_incremental_dataset(n_classes)  ->  (PastisPairDataset, n_regions=1, n_categories=n_classes, proto_active)
   |
   v
FarSLIPDistillationTrainer(cfg{n_regions=1, n_categories=N, n_in_channels=4})   # US-034 REUSO
   set_text_prototypes(proto_active)   # 384 -> 768 ortho frozen (REUSO; reconstruido por stage)
   |
   +--- STAGE-1 (N=4):  train(2 epochs)  -> save_student stage1/student_epoch_{0,1}.safetensors
   |        |
   |        v
   +--- STAGE-2 (N=18): trainer nuevo (n_categories=18)
            student.load_state_dict(stage1_best, strict=False)   # transfiere ENCODER, NO prototipos
            set_text_prototypes(proto_18)                        # 18 prototipos reconstruidos
            train(2 epochs) -> save_student stage2/student_epoch_{0,1}.safetensors
```

### 2.2 Por que `strict=False` es coherente (documentacion AC-6)

`save_student` (US-034, `distill.py:786`) persiste SOLO el `state_dict` del `CLIPVisionModel` (encoder
visual: `patch_embedding` + bloques transformer + CLS). Los **prototipos de texto NO viven en el `state_dict`**
del student: se inyectan via `set_text_prototypes` y se guardan como atributo plano (`_text_prototypes`, no
`nn.Parameter` ni buffer registrado, ver `_proto_to_clip_proj`). Entre Stage-1 (4 protos) y Stage-2 (18 protos)
cambia SOLO la dimension del banco de prototipos del loss; el `patch_embedding` (4 canales) y todo el encoder
son IDENTICOS en shape. Por tanto `load_state_dict(strict=False)` transfiere el 100% del encoder sin colisiones
(no hay claves de prototipo que sobren ni falten). El `strict=False` es defensivo ante prefijos
`CLIPVisionModel` vs `CLIPModel` (mismo motivo que el extractor de US-034). **El warm-start NO transfiere
semantica de clases nuevas** (las 14 clases que aparecen en Stage-2 no estuvieron en Stage-1); transfiere el
encoder que ya aprendio a mapear las 4 bandas S2 al espacio del teacher CLIP — ese es el aporte que el POC mide.

### 2.3 Diferencias clave vs FarSLIP italiano (US-034/035)

| Aspecto | FarSLIP italiano (US-034/035) — DESCARTADO | US-036 PASTIS real |
|---------|--------------------------------------------|--------------------|
| Imagen | crop sintetico `_synthetic_crop_uint16` 256x256 | composite pico-NDVI de patch PASTIS real (4 bandas) |
| Dataset | `FarSLIPDataset` sobre `data/farslip_pairs/` | `PastisPairDataset` sobre `data/PASTIS-R/` (NUEVO) |
| Clases | 32 CAP italianas | 18 PASTIS directas (4 en Stage-1) |
| Puente | `expand_to_cap` (PASTIS->CAP) | **ninguno** (las clases YA son PASTIS) |

| Prototipos | proto_18 -> expand_to_cap(32) -> tile(3) | proto_18[clases_activas] DIRECTO |
| Filtro | none | `PastisFilter` 3:1 dominance_ratio |
| Split | manifests ROI | folds oficiales PASTIS (spatial CV) |

## 4. Interfaces publicas de los modulos nuevos (signatures con type hints)

### 4.1 `ml/farslip/pastis_pair_dataset.py`

```python
#: Curriculum por cardinalidad (n_pixels real, mayor->menor) confirmado por EDA Avance1.
#: Stage-1 usa los primeros 4 (Meadow, Corn, Soft winter wheat, Grapevine — orden por
#: dominancia); el orden de los 18 fija que clases activa cada n_classes intermedio.
INCREMENTAL_CURRICULUM: tuple[int, ...] = (
    1, 3, 2, 8, 4, 14, 5, 16, 10, 6, 15, 7, 11, 9, 12, 17, 13, 18
)

#: Indices de banda en el layout PASTIS 10-banda (B02..B12) para el composite 4-banda.
_PASTIS_B02: int = 0
_PASTIS_B03: int = 1
_PASTIS_B04: int = 2
_PASTIS_B08: int = 6


def active_classes(n_classes: int) -> tuple[int, ...]:
    """Devuelve las primeras ``n_classes`` clases PASTIS del curriculum.

    Args:
        n_classes: Numero de clases activas (4 en Stage-1, 18 en Stage-2).

    Returns:
        Tupla de class_ids PASTIS (1..18) en orden de curriculum.

    Raises:
        ValueError: si ``n_classes`` no esta en ``[1, 18]``.
    """


def peak_ndvi_composite(s2: np.ndarray) -> np.ndarray:
    """Selecciona el timestep de pico NDVI medio y devuelve un composite 4-banda.

    NDVI_t = (B08 - B04)/(B08 + B04) por timestep; t* = argmax del NDVI medio
    espacial. Devuelve ``s2[t*, [B02,B03,B04,B08], :, :]`` escalado a [0,1] (/10000).

    Args:
        s2: tensor int16 ``(T, 10, H, W)`` (layout PASTIS 10-banda).

    Returns:
        float32 ``(4, H, W)`` en [0,1], bandas [B02, B03, B04, B08].
    """


def dominant_class(semantic: np.ndarray, active: tuple[int, ...]) -> int | None:
    """Clase PASTIS dominante del patch restringida a las clases activas.

    Excluye Background (0) y Void (19); cuenta pixeles por clase y devuelve el
    argmax SOLO sobre ``active``. Devuelve ``None`` si el patch no contiene
    ninguna clase activa (el patch se excluye del dataset).

    Args:
        semantic: mascara uint8 ``(H, W)`` con class_id PASTIS (0..19).
        active: clases PASTIS activas (de ``active_classes``).

    Returns:
        class_id PASTIS dominante, o ``None`` si no hay clase activa.
    """


class PastisPairDataset(Dataset):
    """Dataset de pares imagen-texto sobre PASTIS-R real (US-036).

    Cada item: ``{"image": (4,224,224) float32, "region_id": 0-d long (==0),
    "category_id": 0-d long en [0, n_classes-1]}``. El ``category_id`` indexa el
    banco de prototipos ``proto_active`` (clase dominante -> indice en active).

    Reusa ``PastisFilter`` (3:1) y ``load_pastis_patch``; el composite pico-NDVI y
    la clase dominante son los unicos calculos nuevos.

    Args:
        n_classes: clases activas (curriculum por cardinalidad).
        root: raiz PASTIS-R (default ``data/PASTIS-R``).
        folds: folds oficiales PASTIS (spatial CV; default ``(1, 2, 3)``).
        ratio: ratio Meadow:2da-clase del filtro 3:1 (default 3.0).
        resize_to: lado objetivo del composite (default 224, CLIP).
        seed: semilla determinismo (default 42).
    """

    def __init__(
        self,
        n_classes: int,
        root: Path = Path("data/PASTIS-R"),
        folds: Sequence[int] = (1, 2, 3),
        ratio: float = 3.0,
        resize_to: int = 224,
        seed: int = 42,
    ) -> None: ...

    def __len__(self) -> int: ...

    def __getitem__(self, idx: int) -> dict[str, torch.Tensor]: ...


def create_incremental_dataset(
    n_classes: int,
    *,
    root: Path = Path("data/PASTIS-R"),
    folds: Sequence[int] = (1, 2, 3),
    ratio: float = 3.0,
    seed: int = 42,
    prototype_path: Path | None = None,
) -> tuple[PastisPairDataset, int, int, torch.Tensor]:
    """Construye el dataset N-clase + sus prototipos para el trainer FarSLIP.

    Carga los 18 prototipos US-033 (MiniLM-384) via
    ``load_class_prototype_embeddings`` y selecciona DIRECTO las filas de las
    clases activas (sin ``expand_to_cap``). ``n_regions`` siempre es 1.

    Args:
        n_classes: clases activas (4 Stage-1, 18 Stage-2).
        root: raiz PASTIS-R.
        folds: folds oficiales (spatial CV).
        ratio: filtro 3:1.
        seed: determinismo.
        prototype_path: override del parquet US-033 (default el DVC-tracked).

    Returns:
        ``(dataset, n_regions==1, n_categories==n_classes, proto_active (n_classes,384))``.

    Raises:
        FileNotFoundError: si PASTIS-R o el parquet de prototipos no existen.
        ValueError: si ``n_classes`` no esta en ``[1, 18]``.
    """
```

## 9. Riesgos y mitigaciones

| # | Riesgo | Mitigacion |
|---|--------|------------|
| R-CONV | **Convergencia Stage-1 con set pequeno**: 4 clases + filtro 3:1 deja pocos patches; 2 epochs pueden no bajar el loss. | El POC mide la MECANICA, no SOTA. Gate minimo: `loss_cls` epoch1 < epoch0 y < `ln(4)=1.386`. Si no converge, subir folds (1..5) o documentar como limite del POC (no bloquea US-036-a). |
| R-STRICT | **`strict=False` silencioso**: una clave mal nombrada se ignora sin error y el encoder NO se transfiere (warm-start fantasma). | Test AC-6 verifica IGUALDAD de pesos `patch_embedding`+1 bloque encoder tras la carga; log de `missing_keys`/`unexpected_keys` de `load_state_dict`; assert que ambas listas solo contienen lo esperado (vacias para el encoder). |
| R-NDVI | **Composite pico-NDVI con timesteps nublados**: PASTIS no enmascara nubes; el argmax puede caer en un timestep saturado. | NDVI valido en [-1,1] (clamp como en `phenology_class_prototypes`); promedio espacial robusto (`nanmean`); documentar que el POC usa el pico crudo (US-036-a puede anadir QA). No bloquea la mecanica. |
| R-DOM | **Clase dominante mal definida en patch mixto**: patches PASTIS son muy mixtos; el argmax puede no ser representativo del par. | El filtro 3:1 ya descarta los mas mixtos (Meadow-dominados). La clase dominante se restringe a clases activas; patch sin clase activa se EXCLUYE (no se fuerza una etiqueta espuria). Documentar como limitacion del par patch-nivel. |
| R-PROTO | **Reuso DIRECTO de prototipos sin `expand_to_cap`**: si se indexan mal las filas, el `category_id` apunta a otra clase. | Test AC-5: `proto_active` filas == `active_classes(n)`; `category_id` = indice de la clase dominante DENTRO de `active`. Orden de `load_class_prototype_embeddings` (class_ids ordenados) se valida explicito. |
| R-SYNTH | **Regresion al error italiano**: importar por descuido `FarSLIPDataset`/`farslip_pairs`. | `PastisPairDataset` es independiente; los tests NO referencian `farslip_pairs`; el plan marca NO TOCAR. Grep en CI de `_synthetic_crop` ausente del path productivo de US-036. |
| R-GEMINI | **Texto via Gemini**: usar `gemini-3.1-pro` (404) o regenerar el parquet (rompe DVC US-034). | NO regenerar: se LEE `phenology_class_prototypes_pastis.parquet` (ya Gemini real). Si hiciera falta texto nuevo: `gemini-3.5-flash` EXACTO, key de `.env.local` (no shell). |
| R-DEGRADE | **Stage-2 degrada vs from-scratch** (fallback AC-9). | Control `--from-scratch` corre Stage-2 sin warm-start; gate: `loss_cls` final warm <= from-scratch + 0.05. Si falla -> documentar entrenar 18-clase desde cero (validado con el mismo POC 2ep). |
| R-MLFLOW | **Runs `RUNNING`** (subprocess no cierra el run). | `end_run` en `finally` (ya en `distill.train`); verificar 2 runs CERRADOS en `:5010` tras el POC. |

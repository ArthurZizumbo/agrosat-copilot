### 2.3 Decision de espacio FarSLIP (768 vs 512) y de granularidad

- **Espacio FarSLIP-pheno = 768 (CLS) recomendado**: el student de US-036-a se entreno con el InfoNCE
  contrastando el `student_cls` (768-dim, `last_hidden_state[:,0]`), NO la proyeccion 512 (`visual_projection`
  vive en `CLIPModel` completo, usado solo en inferencia — confirmado en US-034). Por tanto el espacio
  semanticamente alineado por el fine-tune es el **768**. `FarSLIPExtractor.extract_embeddings` devuelve 512
  (aplica `visual_projection` del teacher, NO afinada); para el CLS 768 se usa `extract_patch_features` (que
  devuelve `(B,196,768)` sin CLS) -> el helper de US-037 expone el **pooled CLS 768** del `vision_model`
  (`pooler_output`, equivalente al CLS que vio el loss). Se reporta el 768 como espacio principal; el 512 se
  puede registrar como comparativo secundario. La asimetria 768/512 vs 64 se DOCUMENTA (R-DIM).
- **Granularidad patch vs parcela (caveat clave)**: el builder de US-036 produce **1 par por patch** (composite
  pico-NDVI, clase PASTIS DOMINANTE del patch). El universo de etiquetas del notebook eval existente es **por
  parcela** (`parcel_id = {patch}_{instance}`, clase mayoritaria de la parcela). US-037 evalua el espacio
  FarSLIP-pheno a **nivel de patch** (la unidad que el student vio), con `parcel_id` = `patch_id` y `class_id` =
  clase dominante del patch; AlphaEarth se agrega a la MISMA unidad (media de embeddings de las parcelas del patch,
  o re-extraccion a nivel patch). Asi el apples-to-apples es por patch, coherente con la unidad de entrenamiento.
  La diferencia de unidad respecto al notebook por-parcela se DOCUMENTA como caveat (R-GRAN); ambos regimenes se
  pueden reportar (patch-level honesto para FarSLIP-pheno; parcel-level para continuidad con el oficial).

def silhouette_per_class(
    matrix: np.ndarray, labels: np.ndarray, *, sample_size: int = 10000, random_state: int = 42

    """Per-class mean silhouette of one embedding space.

    Computes ``sklearn.metrics.silhouette_samples`` and aggregates the mean per
    ``class_id``. Returns a Polars frame ``[class_id, silhouette_class, n]``;
    the n-weighted mean approximates the global silhouette (consistency check).
    Deterministic for a fixed ``random_state``.

def compare_to_alphaearth(
    *,
    pheno_df: pl.DataFrame,             # parcel_id + class_id + emb_*
    alphaearth_df: pl.DataFrame,        # parcel_id + dim_*

    per_class_cap: int = 500,
    min_class_samples: int = 50,
    prev_farslip_silhouette: float = 0.163,
    random_state: int = 42,
) -> ComparisonReport:
    """Apples-to-apples FarSLIP-pheno vs AlphaEarth on the shared parcels.

    Inner-joins both spaces (``align_spaces_on_parcels``) so they are evaluated
    on identical rows/labels, runs ``eval_space`` per space, computes the deltas
    vs ``prev_farslip_silhouette`` (0.163) and vs AlphaEarth-here, and returns a
    typed report with the comparative table and the per-class silhouette tables.
    """

## 7. H100: presupuesto VRAM + horas + nvidia-smi

**SI usa GPU brevemente** (extraccion de embeddings; NO entrena). La extraccion es ligera; cabe holgada en la H100.

- **`nvidia-smi` ANTES** (regla ml/AGENTS.md: 1 GPU compartida 96 GB, sponsor paga 24/7). Parar el daemon de

  (menos que el training de US-036-a porque no hay grafo de gradientes ni teacher activo). Cabe holgadisimo en 96 GB.
  Solo un proceso de extraccion a la vez.
- **Horas estimadas**: PASTIS-R folds 4/5 held-out son **~cientos de patches** (subconjunto de los ~2433 patches
  totales). 1 forward por patch (composite pico-NDVI) -> extraccion en **minutos** (cota superior <15 min). La
  evaluacion (silhouette + LogReg 5-fold) corre en **CPU**, segundos a minutos. **Total < 30 min de GPU.**
- **Fallback CPU**: `FarSLIPExtractor` resuelve `device="auto"` con fallback a CPU; si la H100 no esta disponible,
  la extraccion corre en CPU (mas lenta pero viable para cientos de patches). El reporte de eval NO necesita GPU.

  `data/farslip/embeddings_pheno_pastis.parquet` (cientos de filas x 768/512 col, decenas de MB) -> opcional `dvc add`.

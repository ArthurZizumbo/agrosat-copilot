# US-060 — Drift detection con Evidently AI

**Status**: planning · **Epic**: E10 (Observabilidad y Documentacion) · **Avance del curso**: A7 (rigor MLOps)
**Sprint**: S-A7 · **Owner**: Arthur Zizumbo (ML/MLOps) · **Prioridad**: P2 (observabilidad reentrenamiento futuro)
**Rama**: `feature/E10-observabilidad-docs` (sobre `feature/E12-transfer-multiregion`)
**Plan vigente**: `context/RefinamientoPlaneacionAgroSatCopilot_v8.md` §US-060 (linea 1989)
**Estimacion**: 2 puntos (~1 dia).

> **Objetivo**: detectar drift de distribucion en (a) bandas Sentinel-2, (b) embeddings
> AlphaEarth (asset GEE `SATELLITE_EMBEDDING/V1/ANNUAL`, data v1.1, 64-dim, CC-BY-4.0) y
> (c) clases predichas, comparando un reference set (linea base) contra un current set, y
> publicar un reporte HTML semanal con alerta cuando el drift supere el umbral. Se aterriza
> como pipeline reutilizable en `ml/monitoring/drift.py` mas un asset Dagster `drift_check`
> con schedule semanal que depende de los assets de ingesta reales.

> **Dominio**: SOLO `ml/monitoring/` (modulo nuevo) + `dagster_project/` (asset, schedule,
> registro en `definitions.py`) + `dagster_project/resources/` (notificacion) + `tests/`.
> NO toca backend, frontend ni db. Para variables de configuracion de la alerta/umbral usa
> env declaradas en el resource Dagster (no en `backend/app/core/config.py`, que es solo del
> backend FastAPI).

> **Regla Arthur (cero sinteticos)**: el drift se computa sobre datos REALES — los parquets
> ya materializados por los assets de ingesta del repo (FarSLIP embeddings consolidados,
> features fusionadas parcel-level, subset Sen4AgriNet/EuroCropsML de EPIC 12). Si en este
> entorno no hay un current set real con el cual contrastar (porque el pipeline aun no genera
> ingestas particionadas por fecha), se reporta ese hecho en `docs/blockers/epic10-notas.md`
> y se entrega el pipeline + asset + schedule + tests LISTOS, ejecutados sobre los parquets
> reales disponibles (p. ej. reference = consolidado FarSLIP, current = subset multi-region).
> NUNCA se fabrica un dataset sintetico para inflar o falsear el reporte.

## 4. Enfoque tecnico

### 4.1 Pipeline `ml/monitoring/drift.py` (Evidently 0.7.21, API moderna)

1. **Entradas**: `reference: pl.DataFrame`, `current: pl.DataFrame` con columnas tipadas:
   bandas S2 numericas (`B02..B12`/indices), 64 columnas de embedding AlphaEarth
   (`emb_0..emb_63` desde la lista `embedding`), y opcional `predicted_class` (categorica).
2. **API moderna**: construir `DataDefinition` declarando columnas numericas vs categoricas,
   envolver con `Dataset.from_pandas(...)`, y correr un `Report` con el preset de drift
   (equivalente moderno a `DataDriftPreset`). Verificar nombres exactos contra 0.7.21 al
   implementar; NO usar el `ColumnMapping`/`metric_preset` del snippet 0.4 de la skill.
3. **Tests estadisticos por tipo de feature** (mapeo a los AC):
   - Bandas S2 numericas -> **KS test** (AC-1).
   - Embeddings AlphaEarth 64-dim -> **MMD** (o PSI/Wasserstein por dimension como respaldo
     reproducible si la version no expone MMD directo; documentar la eleccion) (AC-1).
   - Clases predichas -> **Chi-cuadrado** sobre el espacio 18-clase contiguo (US-030) o macro
     HCAT (US-074) cuando el current set es multi-region (AC-2).
4. **Salida**: `(html_str, summary_dict)`. `extract_drift_score(summary)` devuelve el escalar
   comparable (share de columnas driftadas o metrica agregada); el umbral de alerta es **0.3**
   (AC-4) — constante `DRIFT_SCORE_THRESHOLD = 0.3`.
5. **Conversion Polars<->pandas** solo en el borde con Evidently (la API de Evidently no es
   nativa Polars); el resto del pipeline es Polars (regla `ml/`).

### 4.2 Reference vs current set (datos REALES)

- **Reference (linea base)**: el parquet consolidado mas estable del repo —
  `data/farslip/embeddings_pastis.parquet` (FarSLIP Italia) o `parcel_features_fused`
  (AlphaEarth 64-dim + indices). Es la "distribucion de entrenamiento" de referencia.
- **Current (lote a vigilar)**: el subset multi-region de EPIC 12 (Sen4AgriNet Catalonia /
  EuroCropsML via sus `.dvc`) — un dominio geografico distinto, por lo que el drift S2/embedding
  detectado es REAL y esperado (el mismo domain gap Franco-Iberico que US-075 midio: zero-shot
  mIoU 0.0000 -> few-shot 0.2468). Esto convierte el reporte de drift en evidencia coherente
  con el resultado de transfer ya cerrado, sin fabricar nada.
- Si en el futuro existen ingestas particionadas por fecha/trimestre, el current set sera el
  trimestre actual y el reference el ano base — el pipeline ya queda parametrizado para eso.

### 4.3 Asset Dagster `drift_check` + schedule

- `@asset(deps=[AssetKey("farslip_embeddings_consolidated"), AssetKey("parcel_features_fused")],
  group_name="monitoring", required_resource_keys={"mlflow"})` — dependencia de los assets de
  ingesta REALES del repo (AC-5).
- Cuerpo: lazy `import polars as pl` + `from ml.monitoring.drift import build_drift_report,
  extract_drift_score, DRIFT_SCORE_THRESHOLD`. Lee reference/current, construye reporte,
  computa `drift_score`, escribe HTML (`data/monitoring/drift/` local; sube a
  `gs://agrosat-reports/drift/{week}/` si hay ADC), y si `drift_score > 0.3` invoca
  `context.resources.drift_notifier.send(...)`.
- **Graceful skip**: si no hay parquet upstream o no hay credenciales GCS, retornar
  `MaterializeResult(metadata={"status": "skipped_no_upstream", "rows": 0})` (NO excepcion) —
  CI sin secrets debe pasar.
- `MaterializeResult(metadata=...)` con `report_url`, `drift_score` (float), `n_columns_drifted`,
  `data_version`, `code_version`, `status`.
- **Schedule**: `ScheduleDefinition(job=..., cron_schedule="0 6 * * 1")` (lunes 6am) en
  `dagster_project/schedules/__init__.py`, registrado en `definitions.py`. Primer schedule del
  proyecto.

### 4.4 Notificacion por email (AC-6)

- Resource `drift_notifier` (`ConfigurableResource`) con campos `smtp_host`, `smtp_port`,
  `sender`, `recipients`, `enabled` (default False en dev). Metodo `send(subject, body)`.
- En dev / CI (sin SMTP configurado) -> `structlog` `drift_alert` con `session_id`-free payload
  (`week`, `drift_score`, `report_url`) y NO falla. En prod se conecta SMTP / Cloud Monitoring.
- Vars declaradas como campos del resource (env `DRIFT_SMTP_*`), NO en `backend/app/core/config.py`
  (ese `Settings` con `extra="forbid"` es del backend FastAPI; Dagster es otro proceso).

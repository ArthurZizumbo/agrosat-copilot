### 1.1 Hechos que enmarcan el diseno

1. **AlphaEarth es global e incluye Mexico** (verificado: 64 bandas sobre Michoacan). El mismo
   colector que usa el baseline europeo aplica sin cambios a Mexico -> ese es el punto metodologico.
2. **Aguacate y guayaba son cultivos perennes arboreos** (no estacionales). Su firma fenologica
   esperada: NDVI alto y relativamente **estable todo el ano** (sin el ciclo siembra-cosecha de un
   cereal anual). Esto es justamente lo que la curva NDVI REAL debe mostrar y lo que la descripcion
   Gemini debe capturar cualitativamente.
3. **No hay clase "aguacate"/"guayaba" en PASTIS-18** (dataset frances). El espacio HCAT de US-074
   tiene `orchard` y `vineyard` (PERMANENT_WOODY) como las clases arboreas/perennes mas cercanas.
   Se usa SOLO como encuadre cualitativo ("la firma se parece a un perenne arboreo tipo huerto"),
   jamas como una prediccion con probabilidad/F1.

## 3. Arquitectura (reuso maximo, codigo nuevo minimo)

### 3.1 Que se REUSA sin tocar

- `ml/features/phenology_description.py::generate_phenology_description(...)` — pipeline Gemini Flash.
  La curva NDVI mexicana se pasa como `ndvi_curve` + `doy`; `crop_type_hint="aguacate (perenne arboreo)"`.
  `temperature=0.0` obligatorio (R7). Cache por hash de curva (idempotente, sin recosto Gemini).
- `ml/ingest/gee_sampler.py::{init_ee, sample_alphaearth_roi}` — embedding AlphaEarth zonal.
- `ml/eval/class_remap.py::get_label_space("hcat-macro")` — para nombrar la familia perenne (orchard)
  como ENCUADRE cualitativo. NO se llama a ningun clasificador.
- `ml/utils/notebook_setup.py::{find_repo_root, configure_ee_from_env}` — bootstrap + auth.

### 3.2 Codigo NUEVO: `ml/transfer/mexico_demo.py`

Modulo aislado en `ml/transfer/` (junto a `eurocropsml_fewshot.py` de US-076). Solo helpers de
extraccion + ensamblado de la curva; **sin clasificador, sin F1, sin entrenamiento**.

| Funcion | Responsabilidad | Firma |
|---------|-----------------|-------|
| `MexicoAOI` (dataclass frozen) | Describe una AOI: nombre, cultivo, lon, lat, buffer_m, fenologia_esperada. | `name:str, crop:str, lon:float, lat:float, buffer_m:int, expected_phenology:str` |
| `DEFAULT_AOIS` | Tupla con AOI-1 aguacate Uruapan + AOI-2 guayaba Calvillo (coords §2). | `tuple[MexicoAOI,...]` |
| `aoi_geometry(aoi)` | Construye `ee.Geometry.Point([lon,lat]).buffer(buffer_m)`. | `(aoi) -> ee.Geometry` |
| `extract_alphaearth_zonal(aoi, year, *, scale=10)` | `reduceRegion(ee.Reducer.mean())` del mosaico AlphaEarth del ano -> vector 64-dim REAL + cache parquet. | `-> np.ndarray (64,)` |
| `extract_s2_ndvi_series(aoi, year, *, cloud_pct_max=40, scale=10)` | Coleccion S2 cloud-masked (QA60), `normalizedDifference(['B8','B4'])`, `reduceRegion(mean)` por imagen -> serie `(date, doy, ndvi)` REAL + cache parquet. | `-> pl.DataFrame[date, doy, ndvi]` |
| `describe_phenology(ndvi_series, aoi, *, model="gemini-3.5-flash")` | Adapta la serie a `(ndvi_curve, doy)` y delega en `generate_phenology_description` (REUSO). | `-> str` |
| `hcat_perennial_framing()` | Devuelve el encuadre cualitativo: clases `orchard`/`vineyard` del espacio `hcat-macro` (familia `PERMANENT_WOODY`) como analogia de "perenne arboreo". **No predice nada.** | `-> dict[str,str]` |

**Regla de degradacion (Arthur)**: si GEE falla (cuota/red), las funciones de extraccion devuelven
un DataFrame/array vacio con schema valido y el notebook entra en modo `degraded` con un placeholder
EXPLICITO ("datos GEE no disponibles"), NUNCA una curva inventada. Si falta `GEMINI_API_KEY`,
`describe_phenology` propaga el `RuntimeError` del modulo de fenologia (no se mockea en notebook
entregable).

### 3.3 Por que NO hay clasificador

El pipeline completo (extraccion -> NDVI -> descripcion -> encuadre HCAT) es exactamente la
metodologia, **sin la cabeza de clasificacion**. La cabeza requeriria ground-truth mexicano curado
para entrenar/validar, que no existe. Esa es la frontera precisa entre "lo que mostramos" (REAL,
cualitativo) y "lo que dejamos FUTURE" (F1 mexicano validado).

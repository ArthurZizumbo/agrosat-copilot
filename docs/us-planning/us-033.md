### 1.2 Metricas verificables (golden values de tests)

Los tests **NO llaman a Gemini** (key autorizada solo como cache) ni descargan MiniLM en CI: el cliente LLM
se inyecta via `set_llm_client(mock)` y el encoder se monkeypatchea (patron de
`tests/ml/features/test_phenology_description.py` y `tests/ml/utils/test_phenology_text.py`). Golden values:

- **Schema del parquet REAL (verificado en disco, reproducido como skipif-test)**: `shape == (18, 388)`;
  columnas `[class_id, class_name, ndvi_curve, description, emb_000..emb_383]`; `class_id == [1..18]`.
- **Longitud de descripciones REALES (disco)**: `[807, 586, 686, 870, 717, 733, 671, 646, 726, 766, 636,
  584, 651, 810, 799, 666, 723, 594]` -> todas `> 50`, min 584, max 870. (Confirma "descripcion ES real",
  no placeholder.)
- **Embedding REAL no-trivial (disco)**: `abs(emb).sum()` por fila ~ `15.5` (filas 0-2: `15.501, 15.619,
  15.627`); `> 0` para las 18 -> no zeros.
- **Determinismo del cache (sintetico, mock)**: curva NDVI fija `c = np.linspace(0.2, 0.8, 37)`,
  `parcel_id="class_1"`, `model="gemini-3.5-flash"` -> `_hash_curve` produce el **mismo** key de 16 hex
  en dos corridas; 2.a corrida = cache-hit (mock LLM con contador -> `call_count` no incrementa).
- **Encoder determinista (mock)**: `mock_encode(["x","y"]) -> np.eye(2, 384)` (filas distintas, dtype
  float32) -> `generate_class_prototypes` escribe esos embeddings sin alteracion.
- **Variante por-parcela (sintetico, mock)**: DataFrame con `parcel_id in {"p1","p2","p3"}` (Utf8) ->
  `build_phenology_text_block` -> **3 filas**, una por `parcel_id`, columnas `pheno_text_000..383`.
- **Parquet por-parcela REAL (disco, skipif)**: `phenology_text_pastis.parquet` shape `(1080, 386)`,
  `parcel_id` String unico (1080 distintos), `pheno_text_000..383`.

**Mecanismo de cache SHA256 (cumple AC-4)**: `_hash_curve(parcel_id, curve, model)`
(`ml/features/phenology_description.py:710-717`) = `sha256(repr(parcel_id) + curve.astype(float32).tobytes()
+ model + b"prompt_v1")[:16]`. Cache en JSON por archivo `{key}.json` en
`data/cache/phenology_descriptions/`. En `generate_class_prototypes` cada clase usa `parcel_id=f"class_{c}"`
-> clave estable y distinta por clase. **Misma curva + mismo model -> mismo hash -> mismo texto** (sin
re-llamar al LLM). El literal `b"prompt_v1"` versiona el prompt (cambiar `PROMPT_TEMPLATE` exige bumpearlo).

## 2. Arquitectura de la solucion

```
   PASTIS-R DATA_S2/S2_*.npy (T,10,H,W)  +  ANNOTATIONS/TARGET_*.npy (3,128,128) canal 0
                                    |
        compute_class_mean_ndvi_curves(root, n_time_bins=37)  -> dict[int -> (37,) NDVI media por clase]
                                    |  (B4=idx2, B8=idx6; promedio sobre 37 bins DOY; clases 1..18)
                                    v
   generate_class_prototypes()  (loop 18 clases, ml/features/phenology_class_prototypes.py)
        for c in 1..18:
            desc[c] = generate_phenology_description(           <-- REUTILIZA phenology_description.py
                          ndvi_curve=curves[c], doy=bin_doy,
                          parcel_id=f"class_{c}",               <-- clave de cache SHA256 estable
                          crop_type_hint=class_name[c],
                          model=model, temperature=0.0)          <-- temperature=0 ENFORCED (R7)
                          |  cache HIT (data/cache/phenology_descriptions/{sha256[:16]}.json) -> NO LLM
                          |  cache MISS -> Gemini Flash (requiere key/cliente) -> escribe cache
        emb = _encode_descriptions(desc)  -> (18, 384) float32 L2-norm  (MiniLM frozen)
                                    |
                                    v
   data/features/phenology_class_prototypes_pastis.parquet  (18 filas; YA EXISTE, DVC-trackeado)
        columnas: class_id, class_name, ndvi_curve(list), description(ES), emb_000..emb_383
                                    |
        load_class_prototype_embeddings() -> (proto (18,384) float32, class_ids)
                                    |
        consumido por: US-034 RegionCategoryAlignmentLoss, ml/models/pheno_semantic_branch.py


   VARIANTE POR-PARCELA (descripcion individual por curva NDVI real, cacheada por parcel_id):
        ml/utils/phenology_text.py::materialize_phenology_text(df)
            -> build_phenology_text_block(df)  (ml/features/phenology_description.py)
                 for parcel_id: reconstruye curva NDVI (cols NDVI_t_* o fallback FFT)
                                -> generate_phenology_description(parcel_id=pid)  (cache por pid)
                 -> encode_descriptions  -> pheno_text_000..383
            -> data/features/phenology_text_pastis.parquet  (1080 filas; YA EXISTE, DVC)
```

**Principio rector**: la US esta **sustancialmente hecha**; el trabajo es de **endurecimiento** (tests de
determinismo + validacion de schema/contenido + exposicion de la variante por-parcela + doc de
regenerabilidad), **sin regenerar** el parquet (DVC, contrato fijo). El cache SHA256 ya cubre el
determinismo a nivel de descripcion; el test de US-033 lo ejerce sobre el loop de 18 clases con LLM y
encoder mockeados (cero red, deterministas por construccion).

## 10. Mapeo a rubrica del Avance

- **A5 (S7) / insumo de US-034 (FarSLIP `RegionCategoryAlignmentLoss`)**: la rubrica valora una perdida
  contrastiva alineada contra un **vocabulario semantico verdadero**, no contra `torch.randn`. Los 18
  prototipos fenologicos reales (descripcion ES por clase -> embedding MiniLM) son ese vocabulario:
  cubren el **100% de las 18 clases** PASTIS-R (vs el subset ~0.72% per-parcela), el input correcto del
  metodo Wen et al. 2025 para alinear las features densas de TSViT con el prototipo semantico de cada pixel.
- **Reproducibilidad (cache SHA256 + temperature=0)**: el determinismo del cache (test de US-033) + el
  enforce de `temperature=0` documentan que las descripciones son **reproducibles** y auditables, sin
  depender de la API en cada corrida (cache-hit = $0). Coste de la generacion ~$0.0018 (dentro de ~$115/mes).
- **Continuidad con `phenology_description.py`**: se **reutiliza** (no se reimplementa) el motor per-parcela
  de Wen et al.; los prototipos por-clase y la variante por-parcela comparten el mismo prompt, cliente LLM,
  cache y encoder MiniLM -> coherencia del espacio semantico (DRY, una sola fuente de verdad).

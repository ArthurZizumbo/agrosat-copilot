## 2. Decisiones tecnicas (consultado Context7: maplibre-gl, Pinia, Nuxt 4)

### D1 — `composables/useMap.ts`: que extraer y firma

**Que se extrae de MapCanvas** (la logica imperativa, NO el template ni los chips):
- Init: carga dinamica de `maplibre-gl` + CSS, `new Map(...)`, controles (Navigation/Scale), `buildBasemapStyle`.
- Sources/layers: `addOverlayLayers` (findings fill/line/highlight + AOI fill/line), constantes de ids.
- Sync: `syncFindings` (setData + `setParcelCount` + `fitToFeatures`), `syncAoi`.
- Handlers: `wireParcelInteractions` (click/mousemove/mouseleave sobre `FINDINGS_FILL`, cursor coords).
- Helpers de fly: `fitToFeatures`, `flyToDemoAoi`, `locateParcel`.
- Destroy: `map.remove()`, reset de refs, `removeEventListener`.
- Basemap live-switch watcher (`setStyle` + re-add overlays en `styledata`).

**Que NO se extrae** (queda en MapCanvas): el `<template>`, el rubber-band `drawRect` (estado visual de UI), los chips/overlays (`MapDrawToolbar`, `MapCropLegend`, `MapCoordsReadout`), `defineExpose` y el registro de `mapApiRef` (acoplamiento al layout, propio del componente).

**Firma del composable** (SSR-safe, sin estado modulo-global; cada llamada crea su contexto):
```ts
export interface UseMapOptions {
  onParcelSelect?: (parcelId: number, props: Record<string, unknown>) => void;
}
export interface UseMapHandle {
  initMap: (container: HTMLElement) => Promise<void>;
  destroyMap: () => void;
  flyToDemoAoi: () => void;
  locateParcel: (parcelId: number) => void;
  isReady: Ref<boolean>;
  // draw-rect bridge (la UI del rubber-band se queda en MapCanvas):
  drawRect: Ref<{ x: number; y: number; w: number; h: number } | null>;
}
export function useMap(opts?: UseMapOptions): UseMapHandle { ... }
```
- `initMap(container)` reemplaza el cuerpo del `onMounted` (recibe el `mapContainer.value` desde el componente).
- `destroyMap()` reemplaza el cuerpo del `onBeforeUnmount`.
- El composable lee `useMapStore()`/`useChatStore()`/`useI18n()` internamente (Nuxt auto-imports los hacen disponibles; `useI18n` solo se usa en el HTML del popup, que ya es client-side dentro de handlers).
- **SSR-safe**: el composable NO importa `maplibre-gl` en top-level; el `import()` dinamico vive dentro de `initMap` (que MapCanvas llama bajo `import.meta.client`). NO hay singletons a nivel de modulo (un singleton romperia multi-instancia y el cleanup entre navegaciones — patron Nuxt: estado dentro del composable, no fuera).
- **`useI18n` en composable**: valido en Nuxt; el `t` se captura dentro de `useMap()` (contexto de setup del componente que lo invoca). El popup HTML se construye con ese `t`.

MapCanvas pasa a:
```ts
const { initMap, destroyMap, flyToDemoAoi, locateParcel, isReady, drawRect } = useMap({
  onParcelSelect: (parcelId) => chatStore.setActiveParcelId(parcelId),  // fe/B
});
onMounted(async () => { if (import.meta.client && mapContainer.value) await initMap(mapContainer.value); });
onBeforeUnmount(() => destroyMap());
```

### D2 — Link parcela->chat (cross-store Pinia, parcel_id REAL)

**Flujo**: click sobre `FINDINGS_FILL` -> handler en `useMap` lee `e.features[0].properties.parcel_id` (patron Context7 maplibre `map.on('click', LAYER, e => e.features[0].properties.X)`) -> dos efectos:
1. `mapStore.setSelectedParcel({ parcel_id, crop_class, ... })` — estado de mapa (highlight + chip "parcela seleccionada").
2. `chatStore.setActiveParcelId(parcel_id)` — el chat store; `useChat` lo adjunta como `parcel_id` en el proximo `POST /chat`.

**Cross-store**: el wiring vive en `useMap` via el callback `onParcelSelect` que **MapCanvas** provee (MapCanvas ya consume ambos stores). Asi `useMap` NO importa `stores/chat` directamente (queda agnostico/testeable); el acoplamiento map-store<->chat-store lo decide el componente. Alternativa valida: `useMap` llama `useChatStore()` internamente — en Pinia un store puede usar otro (`useOtherStore()` dentro de una action/funcion). **Elegimos el callback** para que `useMap` sea testeable sin chat store y el cross-store quede explicito en MapCanvas.

**Dato REAL**: `parcel_id` sale de la feature renderizada (`Finding.parcel_id`), que es un id real del backend (o de demo en la ruta demo). NO se inventan geometrias: si la parcela tiene geometria es porque vino de `demoFindings` (demo) o de un futuro backend con geometria; el id siempre es real.

**`useChat` cambio** (1 linea en el body, ya soportado por el contrato):
```ts
const body: ChatRequestWithLocale = {
  messages, session_id: sessionId, aoi, year: 2019, locale: activeLocale,
  parcel_id: chatStore.activeParcelId ?? null,   // NUEVO
};
```

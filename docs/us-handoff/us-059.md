## Que entrega

Scaffolding de observabilidad tecnica del backend FastAPI:

- **Middleware HTTP Prometheus** (`PrometheusMiddleware`, Starlette `BaseHTTPMiddleware`) que instrumenta toda request real del proceso: `Histogram` `http_request_duration_seconds` (de aqui Grafana deriva p50/p95/p99 via `histogram_quantile`) + `Counter` `http_requests_total` (RPS via `rate()`, error rate via `status=~"5.."`) + `Counter` `http_request_exceptions_total`. Labels `(method, path, status)`.
- **Endpoint `GET /metrics`** (router fino, SoC: solo delega en `render_latest()`), exposicion en `CONTENT_TYPE_LATEST`, sin filtro por `session_id` (metrica de proceso, no de tenant) y sin rate-limit; en prod se restringe por ingress de red / Cloud Run.
- **Control anti-cardinalidad (R1)**: el label `path` se normaliza al template de ruta (`request.scope["route"].path`, p. ej. `/aois/{aoi_id}`), nunca la URL cruda; rutas no resueltas (404 / scanners) caen bajo el label constante `<unmatched>`. `/metrics` se excluye del histograma para no contaminar percentiles con la cadencia del scraper.
- **Plantillas Grafana versionadas** (3 paneles): API (latencia p50/p95/p99, RPS, error rate por endpoint), worker ML (GPU util L4/H100 Qwen, OOM, inference latency — metric name documentado, datasource a poblar), data pipeline (materializaciones Dagster, skips, drift score US-060). Datasource por variable `${DS_PROMETHEUS}`, sin UID hardcodeado.
- **Alert rules Prometheus** (`alert_rules.yml`): `HighP99Latency` (p99 > 3 s, 5m), `HighErrorRate` (5xx > 5%, 5m), `GpuOutOfMemory` (VRAM usada > 95% via `DCGM_FI_DEV_FB_USED`), con equivalente Cloud Monitoring documentado.

Las metricas son **reales del proceso** (regla Arthur: nada de sinteticos ni placeholders): cada request que entra al servidor incrementa contadores y observa el histograma. No se fabrica trafico `/chat` ni se inventan valores de GPU.

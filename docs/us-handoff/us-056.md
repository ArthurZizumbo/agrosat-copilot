## Estado final (implementación)

- **`backend/app/services/jobs_service.py`** — `JobsService` con la interfaz pública que el worker Full implementará:
  - `submit_job(request: JobRequest) -> job_id` y `get_job_status(job_id) -> JobStatus | None`.
  - `enqueue_mode="sync"` (default, **MVP, REAL**): corre la inferencia INLINE delegando al runner `classify_new_parcel` (el mismo tool que invoca el reasoner de `/chat`) y devuelve el job ya `DONE` (o `FAILED` con error estructurado). Sin cola, sin GCS, sin worker. `get_job_status` refleja el estado terminal de inmediato.
  - `enqueue_mode="pubsub"` (**FUTURE, Full-only**): lanza `NotImplementedError` claro — *"Pub/Sub mode is Full-only (US-056 deferred, ADR-009)"* — apuntando al topic `inference-jobs`. **Nunca** no-op silencioso.
  - Modelo pesado (fuera de `{xgb-alphaearth, stacking-5}`) en `sync` → `FAILED` honesto ("heavy models run on the Full Pub/Sub GPU worker"); el runner NO se invoca (no se finge).
  - Modelos Pydantic: `JobRequest{session_id, aoi_geojson: GeoJSONGeometry, model_id, year, params}` (AOI validada antes del service), `JobStatus{job_id, state, result_url, result, error}`, `JobState` (`StrEnum`: `queued/running/done/failed`). Runner + pool inyectables (tests sin XGBoost ni DB). `job_id` trazable (UUID4 hex) en todos los logs `structlog`.
- **`ml/workers/inference_worker.py`** (paquete `ml/workers/` nuevo) — esqueleto del subscriber Pub/Sub:
  - `handle_message(message)` — FORMA del callback Full: `validate -> infer (GPU) -> persist (GCS) -> publish (inference-results) -> ack`; `nack` en fallo transitorio (retry/DLQ); poison message → `ack` (drop).
  - `parse_job_request(data)` — REAL (sin GCP): parsea + valida el body a `JobRequest`.
  - `InferenceResult` — schema del topic `inference-results`.
  - `_run_inference` / `_publish_result` / `run_subscriber` — `NotImplementedError` explícitos (GPU + GCS + publish + loop son Full-only). El `__main__` NO arranca un subscriber: loguea + lanza `run_subscriber()` que falla claro. Flujo completo (Pub/Sub → callback → GCS → inference-results → SSE → frontend) en el docstring del módulo.
  - El tipo `Message` de GCP se importa solo bajo `TYPE_CHECKING` → cero dependencia de runtime; el módulo importa limpio sin `google-cloud-pubsub`.
- **`docs/decisions/ADR-012-inferencia-sincrona-mvp.md`** — por qué síncrono en MVP, la interfaz `JobsService`, y el plan de activación Full (Terraform topics + DLQ `max_delivery_attempts=3` + Cloud Run GPU + notificador SSE). Referencia ADR-009.

- Modo `sync` real: corre inline → `DONE` con `job_id` (uuid4 hex) + result inline; los campos del `JobRequest` (session_id, aoi, use_stacking, label_space) llegan al `ClassifyParcelInput`; `ToolContext` session-scoped (multi-tenant).

- Default = `sync` (ADR-012).

## Decisiones tomadas

| Tema | Decisión |
|---|---|
| Modo sync = real, no stub | `submit_job(sync)` invoca el tool `classify_new_parcel` existente (CPU-light, `xgb-alphaearth`) y devuelve `DONE`/`FAILED` real. El MVP no ejecuta modelos pesados, así que no viola la regla "inferencia >2 s vía Pub/Sub". |
| Modo pubsub = falla claro | `NotImplementedError` explícito (no no-op): nombra US-056 / ADR-009 / el topic `inference-jobs`. Honestidad: fingir éxito estaría prohibido. |
| Worker no arranca | `run_subscriber` + `__main__` lanzan `NotImplementedError` (requieren GCP Pub/Sub + Cloud Run GPU L4). Solo `parse_job_request` (validador) es runnable. |
| Registro de jobs in-memory | `dict` en el service: válido en MVP (el sync completa antes de retornar). El Full lo persistirá en PostgreSQL para coordinación inter-proceso (deuda explícita en ADR-012). |
| Runner default lazy | `_default_runner` importa `ml.agent.tools.classify` dentro de la función → `jobs_service` importa sin polars/xgboost. |
| `JobState` = `StrEnum` | Python 3.12; ruff `UP042` exige `StrEnum` sobre `(str, Enum)`. |
| Cero variables nuevas | Se reusan `pubsub_inference_topic`, `gcp_project_id`, `gcs_artifacts_bucket` (ya en `Settings`). Sin riesgo `extra="forbid"`. |

## Plan de activación en Full (qué falta para encender US-056)

Es **wiring, no rediseño** (detalle en ADR-012 D-4):

1. **Terraform**: topics `inference-jobs` + `inference-results` + `inference-jobs-dlq`; subscripción con `dead_letter_policy.max_delivery_attempts=3`; alerta Cloud Monitoring sobre DLQ; servicio Cloud Run GPU L4 + Dockerfile.
2. **`JobsService.submit_job` rama `pubsub`**: reemplazar el `NotImplementedError` por `PublisherClient.publish(...)`; persistir el job en PostgreSQL.
3. **`inference_worker.py`**: quitar los `NotImplementedError` de `_run_inference` (GPU + escribir a `gs://<artifacts>/inference/<job_id>.json`) y `_publish_result` (publicar a `inference-results`); arrancar `run_subscriber`.
4. **Backend SSE notifier**: subscribirse a `inference-results` y empujar `job_done` a la sesión del frontend (`ChatPanel` US-057).
5. **Idempotencia**: resultados keyed por `job_id` en GCS.

## API SHAP verificada (Context7)

- `shap.TreeExplainer(model)` — para modelos basados en arboles (RF, XGB).
- `explainer.shap_values(X)` — multiclase: devuelve lista de arrays (uno por clase) o array 3D segun version de shap. **Manejar ambos** (D3/R2).
- `shap.plots.waterfall(shap_values[0])` — waterfall de una prediccion.
- `shap.plots.beeswarm(shap_values)` / `shap.summary_plot(...)` — summary global.
- `shap.dependence_plot(feature, shap_values, X, ax=ax)` + `fig.savefig(...)` — dependence con figura explicita.
- `shap` NO esta en `pyproject.toml` — US-020 lo agrega via `poetry add --group ml shap` (AC-9). Licencia MIT.

## Bugs resueltos (Fase 3)

1. **`shap ^0.51` choca con el stack** — `shap >=0.51` declara `numba<0.63` (marker Darwin que poetry universaliza), incompatible con `numba 0.65` de `vllm`. Fix: `shap ^0.50.0` (pide `numba>=0.54` sin marker, compatible con numpy 2.3.5 y todo el stack).
2. **`_normalize_shap_multiclass` — 4 layouts** — `TreeExplainer` produce lista-por-clase / 3D / 2D / `(n_classes, n_samples, n_features)` segun version. El helper normaliza los 4 a `(n_samples, n_features, n_classes)`.
3. **Dagster `DAGSTER_HOME` relativo + driver async** — `.env.local` tiene `DAGSTER_HOME=./dagster_home` (relativo, Dagster exige absoluto) y `DATABASE_URL` con `asyncpg` (dagster-postgres necesita sincrono). Corregido parcialmente; el residual queda como follow-up.

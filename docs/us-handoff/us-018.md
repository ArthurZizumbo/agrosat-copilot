## Decisiones tecnicas clave (planning)

1. **Split espacial = folds PASTIS-R 1-5 oficiales** (Sainte-Fare-Garnot 2021), NO custom GroupKFold geografico. Disjuntos por construccion, ya cargados, comparable con literatura.
2. **scikit-learn 1.8 + xgboost 3.2 + umap-learn 0.5.7** — todos en `pyproject.toml`, cero deps nuevas.
3. **PCA con `target_variance=0.95` parametrico** (no `n_components` fijo) para cumplir literal el CA.
4. **UMAP solo 2D, no para training** — es prepro/EDA, no feature engineering productivo.
5. **Polars in / Polars out** + conversion explicita a numpy en `_to_numpy` privado (regla `ml/CLAUDE.md NEVER pandas`).
6. **chi2 con fallback sintetico documentado** (binning de `peak_doy` en cuartiles) ya que las 187 features upstream son todas numericas. Documentado en notebook §3.3.
7. **Feature importance con RF + XGB exploratorios** (n_estimators=200, params ligeros). NO production. NO van a MLflow Registry.
8. **Reportes en `reports/feature_selection/`** con solo 2 PNG commiteados (correlacion + UMAP) para entregable visual.
9. **`ColumnTransformer` por familia de modelo** (linear / nn), no un scaler unico global.
10. **Yeo-Johnson sobre NDVI (no Box-Cox)** porque NDVI puede ser negativo (agua, sombras).

### Hallazgos no triviales

1. **Granularidad parcel-level es la palanca clave**: pasar de 2433 patches con label proxy a 85951 parcelas con label real **duplica F1-macro** (+25 pp), mucho mas impacto que cualquier mejora de features o tuning.
2. **Spectral-temporal manual supera a AlphaEarth** en este dataset (0.5394 vs 0.5202). Los indices espectrales hechos a mano con FFT + fenologia capturan firma temporal que el embedding generico de 64-dim no preserva del todo.
3. **Fusion no aporta**: AE + S1 + SRTM + ERA5 + geom (103 cols) NO mejora sobre AE solo (-0.003 pts). Los bloques contextuales (SRTM/ERA5/geom) son redundantes con la informacion semantica ya capturada por AlphaEarth, y los NaN imputed por la cobertura imperfecta de ERA5 (85.75%) y S1 (92.4%) introducen ruido neto negativo.
4. **PCA conserva 80% del F1 con 24% de las features** (raw 185 → PCA 44 = 0.4328 vs 0.5416). Trade-off util si la velocidad de inferencia importa downstream.
5. **Percentile-clipping winsorize** (p01..p99 + imputacion mediana) reemplazo a `nan_to_num(0.0)` previo. Preserva la distribucion original de cada feature en lugar de inyectar el valor artificial 0.0 que distorsionaba el sesgo de columnas como GCVI (NIR/Green pequenos generan inf).

### Decisiones tecnicas adicionales

| # | Decision | Justificacion |
|---|----------|---------------|
| D17 | **Parcel-level via vectorizacion `rasterio.features.shapes`** sobre canal instance | El dataset PASTIS-R distribuye anotaciones panopticas; no hay justificacion para tratar 1 patch como 1 sample cuando cada patch contiene 30-120 parcelas reales con labels independientes |
| D18 | **`min_pixels=10` como filtro** en vectorize | Parcelas <10 px (~1000 m² con pixel ~10.7m) producen stats temporales muy ruidosos. Trade-off: descartamos algunas parcelas reales pero ganamos calidad de features en las retenidas |
| D19 | **Percentile-clipping (p01, p99) + imputacion mediana** | Mejor que `nan_to_num(0.0)` que inyecta un valor artificial; mejor que `dropna()` que reduce samples. La mediana es la mejor estimacion univariada en ausencia de modelo |
| D20 | **S1 patch-level propagado a parcel-level via JOIN** por `patch_id` | S1 ya es agregado espacial sobre el patch; todas las parcelas dentro de un mismo patch comparten el mismo backscatter VV/VH. Mantener resolucion patch para S1 evita el costo prohibitivo de re-muestrear S1 sobre 85k poligonos (~estimado 30+ horas GEE) |
| D21 | **Batching de samplers GEE** (SRTM 2000, ERA5 1000, S1 50, AE 100) | El sampler de US-016 manda todos los poligonos en una sola request; con 85k poligonos excede el limite GEE de 10MB payload o 5min compute. Batching local sin tocar `ml/ingest/gee_sampler.py` |

- **Cardinalidad: 32 categorias CAP, no 18**: el loss espera `n_regions*n_categories = 3*32 = 96` filas. El

## Logica del fix (resumen)

```
load_class_prototype_embeddings()                       -> proto_18 (18,384) L2-norm  (US-033, DVC)
expand_to_cap(proto_18, all_cap_classes(32), cap_to_pastis) -> proto_cap (32,384)
np.tile(proto_cap, (n_regions=3, 1))                    -> proto_tiled (96,384)  (orden region*32+cat)
trainer.set_text_prototypes(proto_tiled)                -> distill.py:456
    W = ortho_frozen(768,384,seed); proto_768 = proto_tiled @ W.t()   # _proto_to_clip_proj
    assert proto_768.shape == (96,768) and D == teacher.config.hidden_size
    self._text_prototypes = proto_768.to(device)
RegionCategoryAlignmentLoss.forward (SIN CAMBIOS):
    logits = norm(student_cls(B,768)) @ norm(protos(96,768)).t() / T   # alinea contra SEMANTICA
    loss_cls = cross_entropy(logits, region*32+category)
```

Golden values: CLS dim **768** (verificado en vivo `hidden_size==768`); `n_regions=3`, `n_categories=32`,
`expected_protos=96`; parquet US-033 `(18,388)`; `np.tile(emb_18,(3,1))=(54,384)` INSUFICIENTE -> tras
`expand_to_cap` `np.tile(cap_32,(3,1))=(96,384)` -> proyectar `(96,768)`. Proyeccion: `W.t()@W ~ I_384`,
preserva norma, frozen, deterministica (seed). VRAM FP32 ~10-14 GB batch=64 (cabe holgado en 96GB).

## Riesgos principales

1. **R-DIM (riesgo #1)**: CA v8 dice 384->512 pero el espacio del loss es **768** (`hidden_size`, CLS de
   `last_hidden_state`); 512 solo en inferencia. Reproyectar a 512 -> `RuntimeError` en el matmul (el loss
   NO valida D). Mitigacion: `_proto_to_clip_proj` 384->**768** + assert `D==hidden_size` (falla temprano).
2. **R-CARD**: 32 CAP vs 18 PASTIS -> `np.tile` da 54 != 96 -> `ValueError`. NO existe mapeo CAP->PASTIS
   (grep=0). Mitigacion: `cap_pastis_mapping.py` + `expand_to_cap` (18->32) antes del tile; test cardinalidad.
3. **R-ORDER**: `targets=region*32+category`; orden de `proto_tiled` debe seguir `all_cap_classes` del
   dataset o el CLS se alinea con el prototipo equivocado SIN error. Mitigacion: mismo orden canonico + test.
4. **R-PROVISION**: `data/farslip_pairs/` (15GB) NO DVC-trackeado -> `dvc pull` falla. Mitigacion: scp/rsync
   `--partial` por tunel Cloudflare + checksums (o `dvc add`+push). NO GEE (sinteticos), NO RTX 4070 (OOM).
5. **R-APPROX**: reproyeccion ortogonal 384->768 es aproximacion cruda (no es CLIP text encoder nativo).
   Mitigacion: caveat MLflow + doc; objetivo honesto = superar el 0.163 propio (US-037); solucion limpia
   (`_load_text_encoder` CLIPTextModel) post-entrega.
6. **R-LOSS**: la loss no baja -> bug en reproyeccion/mapeo/orden. Mitigacion: smoke `test_loss_cls_decreases`;
   comparar A/B contra `torch.randn` (debe ser estrictamente mejor).

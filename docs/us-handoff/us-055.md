## Estado final (implementación)

- **`/cog`** = `TilerFactory` completo montado en `main.py` (`prefix="/cog"`) + `add_exception_handlers(app, DEFAULT_STATUS_CODES)`. Endpoint literal AC-2: `GET /cog/tiles/WebMercatorQuad/{z}/{x}/{y}.png?url&expression&rescale&colormap_name` → PNG real (verificado con COG real).
- **`/tiles/{z}/{x}/{y}.png?url&index=ndvi|ndwi|ndmi`** = adaptador de contrato US-053 (TMS fijo `WebMercatorQuad`), delega al render compartido `render_cog_tile` envuelto por la caché Redis. Ya no es `501`.
- **GDAL/GCS** (`gdal_env.gdal_gcs_environment`): dict `vsigs` + tuning COG; `GOOGLE_APPLICATION_CREDENTIALS`/`CPL_GS_ENDPOINT` solo si hay SA → dev GCS-agnóstico.
- **Caché** (`tile_cache.cached_tile`): Redis `redis.asyncio` sobre `settings.redis_url`, clave `tile:sha256(method|path|sorted(qs))`, `SETEX` 900 s, headers `Cache-Control: public, max-age=900` + `X-Tile-Cache: HIT|MISS`. `fakeredis` en tests (dependencia `get_tile_redis` overridable).
- **PROJ fix** (`proj_env.ensure_proj_data`): pinea `PROJ_DATA`/`PROJ_LIB` al `proj_data` bundled de rasterio antes de cargar rasterio/titiler. Importado por `cog_tiler` (runtime) y `conftest` (tests). En Cloud Run (Linux) es no-op.

### Gotchas encontrados (no en el plan original)

- **`os.environ["PROJ_DATA"]` tras `import rasterio` NO basta** (GDAL ya inicializó PROJ): hay que pinear el env ANTES de importar rasterio. El módulo `proj_env` lo computa via `sysconfig.get_paths()["purelib"]` (sin `import rasterio`) y lo fija a nivel de import.
- **COG inexistente lanza `rasterio.errors.RasterioError`** (no `RioTilerError`): `render_cog_tile` captura ambas y el adaptador mapea a `404`.
- **mypy `warn_return_any`**: `return render_cog_tile(...)` / `return await cached_tile(...)` disparaban `no-any-return` (las libs titiler/rio-tiler no tienen stubs). Fix: asignar a locales tipados (`png: bytes = ...`, `response: Response = ...`) antes del `return`.
- **`rio-cogeo`** se añadió al grupo **dev** (`poetry add --group dev rio-cogeo`, v7.0.2) — solo lo usa el fixture de test.

## Resumen

TiTiler montado como **router DENTRO de la imagen backend** (no servicio aparte, no `titiler.Dockerfile`): tiles PNG/WebP on-the-fly desde COGs (GCS `vsigs` en prod, COG local/http en dev) para overlay NDVI/NDWI sobre MapLibre, sin pre-renderizar. Reemplaza el stub `501` que dejó US-053 en `backend/app/api/tiles.py`.

### Observación de seguridad (NO bloqueante — fuera de AC-1..AC-7)

- **SSRF: el parámetro `url` no valida scheme/host.** Tanto `/cog/...` (factory) como `/tiles/...` aceptan cualquier `http(s)://`, que rio-tiler/GDAL hará fetch **server-side**. Ningún AC de US-055 exige restringirlo, por eso no bloquea el cierre; pero antes de exponer en staging/prod debe añadirse un allowlist (`gs://<GCS_DATA_BUCKET>/...` + paths/`file://` locales) — registrar como hardening de seguridad. `CPL_VSIL_CURL_ALLOWED_EXTENSIONS=.tif,.tiff,.TIF` limita la extensión pero NO el host.

## Hallazgos verificados (factual)

- `titiler-core ^2.0.2`, `rio-tiler ^9.0.6`, `rasterio ^1.5.0` YA en `pyproject.toml`. `rio-cogeo` **falta**.
- **Riesgo GDAL/PROJ en el dev box (Windows):** un PostgreSQL/PostGIS instalado tiene un `proj.db` viejo (`C:\Program Files\PostgreSQL\17\share\contrib\postgis-3.5\proj\proj.db`, `DATABASE.LAYOUT.VERSION.MINOR=2`) que secuestra PROJ y rompe `CRS.from_epsg(3857)` → en cadena rompe el import de `titiler.core`/`rio_tiler` (verificado `CRSError`). **Fix:** pinear `PROJ_DATA`/`PROJ_LIB` al `proj_data` bundled de rasterio **antes** del import CRS (en `conftest.py` y en arranque/Dockerfile). Verificado que con el env pre-import `CRS.from_epsg(3857)` resuelve. En Cloud Run (Linux) no aplica.
- Ruta default del factory en 2.x = `/tiles/{tileMatrixSetId}/{z}/{x}/{y}.{format}` (TMS en el path) → **no** coincide con el contrato US-053 sin TMS → de ahí el adaptador.
- US-053 dejó `main.py` líneas 88-91 con el comentario del punto de montaje y `app.include_router(tiles.router)` ya presente.
- Frontend (`frontend/composables/useBasemap.ts`) consume tiles raster XYZ `{z}/{x}/{y}` como source MapLibre → el overlay añadirá un source `raster` apuntando a `/tiles/{z}/{x}/{y}.png?url=...&index=ndvi` (US-054 lado frontend).

## Decisiones tecnicas clave (planning)

1. **CV espacial = `build_spatial_kfold` (US-016)**, NO folds PASTIS-R 1-5 ni `KFold` aleatorio. Opera sobre geometrias reales de parcela, aplica buffer anti-leakage 1km.
2. **RF + XGBoost, NO LightGBM** — el CA del v6 nombra exactamente `RandomForestClassifier` + `XGBClassifier`.
3. **`tree_method="hist"` CPU, NO `device="cuda"`** — 85k×187 corre en < 15 min en CPU; no se justifica reservar L4.
4. **`GridSearchCV(cv=<lista de splits espaciales>)`** — el `cv` es iterable de `(train_idx, test_idx)`, no un entero, para respetar la particion geografica.
5. **`class_weight="balanced"` (RF) + `sample_weight` inverso (XGB)** — PASTIS-R tiene desbalance fuerte; F1-macro lo penaliza.
6. **mIoU = `jaccard_score(average="macro")` a nivel parcela** — proxy documentado; la mIoU densa real llega en EPIC 5.
7. **`mlflow_utils.py` reutiliza `git_meta.py`** — DRY; no duplica el subprocess de la skill.
8. **MLflow tracking contra el servidor Docker `http://localhost:5010`** (servicio `mlflow` ya en `docker-compose.yml`), con fallback `file:./mlruns` si el server no responde. Decision de Arthur 2026-05-21: reducir deuda tecnica levantando el servidor real (backend Postgres + Model Registry funcional) en vez de quedarse con `file:`.
8b. **DB `mlflow` dedicada + artifact root en bind-mount del host `./mlflow-artifacts`** — no mezclar las tablas internas de MLflow con el schema de negocio; artefactos inspeccionables y migrables a GCS.
9. **`agrosat-baseline` nombre unico en Model Registry, 2 versiones** (RF v1, XGB v1) — convencion de la skill `agrosat-dvc-mlflow`. El Registry es funcional gracias al backend Postgres.
10. **Notebook `04_baseline.ipynb` iniciado en US-019 (§1,§2,§6), completado en US-022** — evita merge conflict masivo; deja la justificacion de 40 pts en su sitio.
11. **`--max-samples` con submuestreo estratificado** para dev/CI.
12. **`LabelEncoder` sobre `class_id`** persistido en el joblib — PASTIS class_ids no contiguos tras dropear 0/19; XGB `multi:softprob` exige labels `[0, n_classes)`.
13. **Terraform `apply` limitado a los 4 buckets GCS** (`-target`), NO la infra completa — Cloud SQL no escala a cero, las Cloud Run apuntan a imagenes inexistentes; el Avance 3 evalua un notebook.
14. **Nombres de bucket sin sufijo `-env`** — `.env.local` es la fuente de verdad (`agrosat-dvc-remote`, `agrosat-data`, `agrosat-artifacts`); se quita el sufijo del modulo GCP.
15. **El `terraform apply` lo ejecuta Arthur, no Claude** — aplicar infra cloud crea costo; el sub-agente entrega codigo + `terraform plan` validado + runbook.

## Bugs resueltos (Fase 3)

1. **RF de ~700 MB / cuelgue en `log_model`** — `max_depth=None` generaba arboles sin poda; el modelo no se podia loguear a MLflow (se colgaba 25 min). Fix: grid RF acotado a `max_depth [15,20]`, `min_samples_leaf [10,20]`, `n_estimators [100,150]` — modelo final 124 MB. **Desviacion justificada del plan** (AC-1 fijaba `max_depth=None`): un RF sin poda es inmanejable y sobreajusta.
2. **`UnicodeEncodeError` en Windows** — MLflow 3.x escribe emojis en stdout al cerrar runs; consola `cp1252` falla. Fix: `train_baseline.py` reconfigura `sys.stdout/stderr` a UTF-8.
3. **Cuelgue del servidor MLflow Docker** — `log_artifact`/`log_model` contra el servidor HTTP se colgaba. Fix: el entrenamiento usa `file:./mlruns` (fallback que `resolve_tracking_uri` ya provee); el servidor Docker queda para inspeccion via UI.
4. **Contencion GPU en `GridSearchCV`** — `n_jobs=-1` con XGB-GPU lanza N workers que se pelean la unica RTX 4070 (thrashing, fits de 30+ min). Fix: `tune_baseline` usa `search_n_jobs=1` cuando XGB corre en GPU; cada fit baja a ~30-60 s.
5. **`build_spatial_kfold` O(N^2) sin cache** — el handoff R3 pedia cachear los folds; el run inicial no lo hizo. Fix: cache implementado en `data/test_fixtures/baseline_spatial_folds_n{N}_k{k}_b{buffer}_s{seed}.parquet`. (Nota: el `build_spatial_kfold` resulto tardar solo ~19 s; el cuello real era el `GridSearchCV`.)

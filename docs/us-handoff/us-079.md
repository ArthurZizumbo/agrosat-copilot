### Puente denso->parcela (CABLEADO, 26-jun) + eval denso del voto parcela
`ml/transfer/dense_to_parcel_italia.py` agrega las preds densas post-softmax de los
miembros densos (TSViT/U-TAE, `(K,128,128)`) a un voto por parcela. Como la mascara
`TARGET_<id>.npy` de US-078 rasteriza CLASE (no parcel_id —
`eurocrops_pastis_builder.rasterize_patch_mask` quema `class_id` con `fill=0`), hay
DOS estrategias honestas, sin tocar US-078:
- **`eurocrops`** (DEFAULT, la terna campeon): rasteriza las MISMAS parcelas
  EuroCrops que uso el xgb (reusa `parcels_in_patches` de `alphaearth_italia.py`),
  asi el `canonical_parcel_id` (`iti1_2018_p{patch}_{seq}`) une al OOF xgb. El
  transform por patch se reconstruye con
  `rasterio.transform.from_bounds(bbox_min_lon, bbox_min_lat, bbox_max_lon,
  bbox_max_lat, 128, 128)` desde el `metadata.parquet` de US-078 — **SIN tile
  cache** (hallazgo del orquestador, confirmado: el metadata ya guarda el bbox 4326
  por patch). Se rasteriza un surrogate int contiguo por parcela (rasterize exige
  un entero por geometria) y se guarda el inverso surrogate->`canonical_parcel_id`
  Utf8 para recuperar la clave de join. `load_eurocrops_parcel_rasters` YA NO lanza
  `NotImplementedError`.
- **`blobs`** (alternativa, `--parcel-strategy blobs`): cada componente conexa de
  una clase en la mascara = una "parcela" aproximada (`scipy.ndimage.label`,
  4-conectividad). Namespace propio `iti1_2018_p{patch}_blob_{n}` que **NO** une al
  xgb — sirve para el voto denso-only (2 miembros) o el smoke. Cobertura del join
  con el xgb = 0 (esperado).

**Cobertura del join eurocrops<->xgb (PILOTO 20 patches, validado 26-jun): 813/884
parcelas del OOF xgb = 92.0%.** El join es por `canonical_parcel_id` (100% de match
de ids), pero el voto a nivel parcela solo emite fila para una parcela que pinte
>=1 pixel en la grilla 128x128. Con `all_touched=False` (alineado con las mascaras
de US-078) 213 de 919 parcelas son sub-pixel (mas chicas que la celda 10m o entre
centros de celda) y pintarian 0 pixeles -> se perderian (cobertura caeria a 79.9%).
FIX honesto: **fallback de centroide** — a cada parcela sin pixel se le asigna su
pixel-centroide SOLO si sigue siendo background (nunca sobreescribe a un vecino
grande; `all_touched=True` se rechaza porque deja que una parcela chica robe pixeles
de borde y desalinea con las mascaras `all_touched=False`). Eso sube la cobertura a
92.0%. El ~8% restante son parcelas cuyo centroide cae fuera del patch o en un pixel
ya ocupado: sin senal densa propia, se dropean honestamente (nunca se imputan).

NOTA de alineacion: `from_bounds(4326)` arma una grilla lon/lat regular; las
mascaras de US-078 se rasterizaron sobre el transform UTM de la tile descargada, asi
que queda un offset proyectivo sub-pixel en bordes (~0.73 IoU de region vs
`TARGET_<id>.npy` en el piloto). Ese offset solo perturba que pixel de borde cae en
que parcela al PROMEDIAR; el join al xgb es exacto (por id, no por geometria) y el
interior de cada parcela se captura bien, que es lo que el promedio por parcela
necesita. En la VM con tile cache se podria mejorar el offset, pero NO es necesario
para el voto (que vive a nivel parcela).

### Proyeccion voto-parcela -> mapa denso (eval fino/coarse para la rubrica)
`ml/eval/transfer_italia_eval.py::project_parcel_vote_to_dense(parcel_probs,
crop_class_ids, parcel_rasters, num_classes, background_id)` re-pinta la distribucion
votada de cada parcela sobre TODOS sus pixeles (via los mismos ParcelID rasters
EuroCrops), reconstruyendo un mapa denso `(K,128,128)` por patch. Asi el voto
CAMPEON a nivel parcela tambien obtiene metricas DENSAS (mIoU + F1 fino/coarse via
`evaluate_dense_predictions`/`DenseConfusionAccumulator`) + discard curve +
`best_subset_over_threshold`, exactamente el harness denso de los miembros y de
EPIC 5. Un pixel sin parcela (background o parcela no votada) queda columna cero ->
su argmax es background -> lo dropea `ignore_index=background_id` (convencion de
pixeles supervisados). `ItaliaParcelVotingResult` ahora expone `parcel_vote()`
(`{canonical_parcel_id: (n_crops,)}`) y `blended_probs`/`parcel_ids` (cambio aditivo
en `voting_italia.py`, sin romper firmas). El runner `run_transfer_italia.py`
construye los rasters UNA vez (`load_eurocrops_parcel_rasters`), los reusa para la
agregacion Y la proyeccion, y mete el eval denso del voto en `report.json`
(`voting_dense_eval`, `voting_dense_per_class`, `voting_dense_discard_curve`,
`voting_dense_best_subset_f1_over_0.9`) + MLflow (`voting_fine_f1_macro`,
`voting_fine_miou`, `voting_coarse_*`, `best_subset_*`).

**Smoke piloto 26-jun (20 patches, probs densas sinteticas + OOF xgb real, CPU)**:
todo cablea — rasters eurocrops (919 parcelas, 20 patches) -> agregacion eurocrops
-> OOF denso por parcela (706+107 con fallback = 826 parcelas, 813 unen al xgb) ->
ItaliaParcelVotingEnsemble aprende 3 pesos `{tsvit-pheno: 0.391, utae: 0.365,
xgb-alphaearth-italia: 0.243}` OOF leave-one-fold-out sobre los 5 folds espaciales
-> `project_parcel_vote_to_dense` reconstruye `(40,128,128)` por patch ->
`compute_dense_metrics` da fine_miou/fine_f1/coarse sin error. Cifras = ruido (probs
sinteticas, sin fine-tune): fine_f1 0.047, coarse_f1 0.070, acc 0.46 — validan el
CABLEADO, no el resultado. El training real (densos fine-tuneados) lo coordina el
orquestador con el dataset full.

## Decisiones tecnicas tomadas en la implementacion (codigo)
- **Voting-3 = TSViT-pheno + U-TAE + xgb-alphaearth-italia a nivel PARCELA**
  (26-jun, replica fiel del campeon France F1 0.9069). El embedding AlphaEarth por
  parcela YA esta materializado (`alphaearth_italia.py` + `xgb_alphaearth_italia.py`),
  asi que la terna vuelve a ser la del campeon. El default del runner es

  experimentar (p.ej. `tsvit-pheno utae` denso-only con `--parcel-strategy blobs`).
  El `tsvit-pheno-fullm` queda como opcion documentada, NO como default.
- **Agregacion denso->parcela por ParcelID EuroCrops rasterizado** (`eurocrops`,
  DEFAULT, une al xgb por `canonical_parcel_id`) o por componentes conexas (`blobs`,
  alternativa). El transform por patch sale de `from_bounds(bbox del metadata)`,
  SIN tile cache (hallazgo del orquestador). Cobertura del join 92.0% en el piloto
  (fallback de centroide para sub-pixel). El voto parcela campeon se proyecta de
  vuelta a denso (`project_parcel_vote_to_dense`) para tener metricas mIoU/F1
  fino/coarse de la rubrica. Honesto sin tocar el builder de US-078.
- **TSViT warm-start = cls-tokens, no `to_seg`**. En TSViT-pheno-v1 (L4, dim=128,
  depth 4+4, n_timesteps=10, F1 0.75 PASTIS) la "cabeza por clase" es el banco de
  `temporal_cls_tokens (1,18,128)`; `to_seg (64,128)` es compartido (se copia
  verbatim). Se warm-startean las 20 filas de cls-tokens de las clases conservadas.
  (En `finetune_baltico` TSViT NO warm-starteaba cabeza: aqui SI, generalizado.)
- **U-TAE id namespace = semantic_id + 1** (id 0 background, 19 void en la cabeza

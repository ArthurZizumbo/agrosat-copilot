### Puente denso->parcela (la pieza que faltaba)
`ml/transfer/dense_to_parcel_italia.py` agrega las preds densas post-softmax de los
miembros densos (TSViT/U-TAE, `(K,128,128)`) a un voto por parcela. Como la mascara
`TARGET_<id>.npy` de US-078 rasteriza CLASE (no parcel_id —
`eurocrops_pastis_builder.rasterize_patch_mask` quema `class_id` con `fill=0`), hay
DOS estrategias honestas, sin tocar US-078:
- **`blobs`** (default sin inputs extra): cada componente conexa de una clase en la
  mascara = una "parcela" aproximada (`scipy.ndimage.label`, 4-conectividad). Se
  promedian las probs post-softmax de los pixeles del blob y se renormaliza. Los
  ids viven en un namespace propio `iti1_2018_p{patch}_blob_{n}` que **NO** une al
  xgb (parcelas EuroCrops reales) — sirve para el voto denso-only (2 miembros) o el
  smoke. Cobertura del join con el xgb = 0 con esta estrategia (esperado).
- **`eurocrops`** (recomendada para la terna campeon): rasteriza las MISMAS
  parcelas EuroCrops que uso el xgb (reusa `parcels_in_patches` de
  `alphaearth_italia.py`), asi el `canonical_parcel_id` (`iti1_2018_p{patch}_{seq}`)
  une al OOF xgb **1:1**. Necesita el transform/CRS por patch del tile cache (lo
  tiene la VM tras la descarga full; el piloto local solo trae las mascaras). El
  hook esta en `load_eurocrops_parcel_rasters` (lanza `NotImplementedError` claro
  hasta cablear los transforms en la VM).
- **DECISION QUE ARTHUR DEBE CONFIRMAR**: con el piloto local solo se puede validar
  el CABLEADO de la terna campeon (smoke con rasters sinteticos: cobertura 1.0,
  884 parcelas, 3 pesos aprendidos OOF sobre 5 folds). El join real 1:1 de la terna
  necesita rasterizar EuroCrops por patch en la VM. Alternativa si no se cablea: el
  voto denso-only de 2 miembros (blobs) funciona end-to-end pero NO es la terna
  campeon. Recomendacion: cablear el transform por patch en la VM (estrategia
  `eurocrops`) para la corrida real.

### Reconciliacion del espacio de clases
El xgb OOF expone `prob_000..prob_021` (22 clases presentes en las parcelas del
piloto, ids globales `[1..28]`); los densos producen un eje `[0,40)`. El voto
escatera cada miembro al espacio UNION de ids de clase crop (background excluido),
asi la columna `i` de cada miembro es la MISMA clase global antes de votar.
- **Fine-tune REAL** de los miembros densos al label-space italiano (no zero-shot).
- **Bandera de reciclaje** (kept-class flag): un array de clases CONSERVADAS cuyas
  filas de la cabeza se warm-startean desde la cabeza PASTIS; las NUEVAS (olive, durum)
  van con init random. ESTE PATRON YA EXISTE: `ml/transfer/finetune_baltico.py`
  `warm_start_head()` + `BalticLabelSpace`. REUSAR/GENERALIZAR, no reinventar.
- **Entrenar de verdad en la H100** (VM remota del sponsor). Depende de que US-078
  haya generado el dataset real (piloto 20 patches o full segun el gate de 078).

## Decisiones tecnicas tomadas en la implementacion (codigo)
- **Voting-3 = TSViT-pheno + U-TAE + xgb-alphaearth-italia a nivel PARCELA**
  (26-jun, replica fiel del campeon France F1 0.9069). El embedding AlphaEarth por
  parcela YA esta materializado (`alphaearth_italia.py` + `xgb_alphaearth_italia.py`),
  asi que la terna vuelve a ser la del campeon. El default del runner es
  `(tsvit-pheno, utae, xgb-alphaearth-italia)`; `--members` sigue disponible para
  experimentar (p.ej. `tsvit-pheno utae` denso-only con `--parcel-strategy blobs`).
  El `tsvit-pheno-fullm` queda como opcion documentada, NO como default.
- **Agregacion denso->parcela por componentes conexas** (`blobs`, default sin
  inputs) o por **ParcelID EuroCrops rasterizado** (`eurocrops`, recomendada para
  la terna campeon porque une al xgb 1:1). Decision documentada arriba en "CAMBIO A
  PROTOCOLO PARCELA"; honesta sin tocar el builder de US-078.
- **TSViT warm-start = cls-tokens, no `to_seg`**. En TSViT-pheno-v1 (L4, dim=128,
  depth 4+4, n_timesteps=10, F1 0.75 PASTIS) la "cabeza por clase" es el banco de
  `temporal_cls_tokens (1,18,128)`; `to_seg (64,128)` es compartido (se copia
  verbatim). Se warm-startean las 20 filas de cls-tokens de las clases conservadas.
  (En `finetune_baltico` TSViT NO warm-starteaba cabeza: aqui SI, generalizado.)
- **U-TAE id namespace = semantic_id + 1** (id 0 background, 19 void en la cabeza
  20-cls de Isaac); el warm-start mapea las clases conservadas a las filas 1..18.
- **Label-space denso con background** (40 clases = bg + 39 crops) para alinear el
  eje de clases del modelo 1:1 con las mascaras `TARGET_<id>.npy` en disco;
  background excluido de loss y metricas (ignore_index=0).
- **Voting OOF por fold espacial**: leave-one-spatial-fold-out a nivel patch sobre
  las preds densas IT (anti-fuga). NOTA OPERATIVA: con `test_fold` aislando 1 solo
  fold, el voting no puede CV (degrada con gracia + warning honesto). Con el dataset
  COMPLETO el test debe abarcar >=2 folds espaciales (elegir el fold de test que
  agrupe varios super-cells, o reservar varios folds de eval) para que los 3 pesos
  se aprendan OOF de verdad.

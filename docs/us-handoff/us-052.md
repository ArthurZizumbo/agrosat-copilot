> **Decisiones de implementacion:**
> - **Rate-limit por sesion (no IP):** `session_id_key` extrae `X-Session-ID`; fallback a
>   `get_remote_address` solo como red de seguridad (el guard ya exige sesion). Verificado:
>   sesiones distintas no comparten bucket.
> - **Enforcement vs storage del limiter:** slowapi aplica el limite contra el objeto `limiter`
>   ligado por el decorador (no `app.state.limiter`, que solo se usa para inyectar headers). Por eso
>   el fixture de test swapea el `_storage`/`_storage_uri`/`_limiter` del **singleton** a `memory://`,
>   no instancia uno paralelo.
> - **Guard pragmatico MVP (D5):** UUID malformado/faltante -> 400 (en `get_request_session_id`);
>   sesion inexistente/ajena -> 403 (RLS fail-closed, 0 filas). Sin validacion de `user_id`.

>   sin DB real y la prod use `app_database_url`.

## Hallazgos críticos (verificados leyendo el código, NO asumidos)

1. **El modelo NO se cambia donde dice el AC.** `chat_service.py` ya usa `gemini-2.5-pro`; el `gemini-3.1-pro`
   está SOLO en `config.py:89` y el chat_service **nunca lo lee**. Hay que tocar ambos para coherencia.
2. **RIESGO SEGURIDAD — la RLS de US-051 hoy NO aplica al /chat.** El `ToolContext` usa el pool de
   `ml/agent/db.get_pool()` que lee `database_url` (rol superuser `agrosat`, **BYPASSRLS siempre**). El
   `SET LOCAL app.current_session` de las tools es decorativo como superuser. **B2 lo corrige** apuntando al
   pool `app_database_url`.
3. **slowapi + StreamingResponse:** el decorador exige `request: Request` en la firma; el límite se evalúa
   antes de abrir el stream → un `429` sale como JSON normal, sin gotcha de buffering (verificado en Context7).

## Flujo RLS real del /chat (aclaración del AC)

- El endpoint **NO scopea el stream a nivel router**: delega el aislamiento en las **tools del agente**
  (`ml/agent/db.session_scoped_conn` emite `SET LOCAL app.current_session`).
- El `get_scoped_conn` de US-051 se usa **solo para el auth-guard** (`SELECT 1 FROM chat_sessions`).
- **Condición necesaria (B2):** el pool del `ToolContext` debe ser el de `app_database_url` (NOBYPASSRLS); con el
  pool superuser actual la RLS no aísla.

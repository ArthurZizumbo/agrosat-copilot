## Resumen ejecutivo

Extender `PastisFilter` (`ml/data/pastis_filter.py`, de Isaac) con un **modo nuevo `dominance_ratio`**:
mantener un patch si `Meadow_px <= ratio * (2da clase mas grande EN ESE PATCH)`, `ratio=3` por defecto.
Parametrizable por `n_classes`/`target_classes` (la 2da clase se busca solo entre el conjunto objetivo).
El histograma per-patch se computa con `np.bincount(target[0].ravel(), minlength=20)` sobre el canal 0
del TARGET `(3,128,128)` uint8 (0=Background, 1-18 cultivos, 19=Void). El modo `coverage`/`min_coverage`
**legacy queda intacto** (no rompe `pastis_farslip_filtered_splits.json`). Tests verdes en `tests/ml/data/`.

## Correcciones a la US (verificadas en recon contra disco)

- **El "filtro 3:1" NO existe hoy**: `pastis_filter.py` solo implementa un umbral de cobertura combinada
  (`_passes`, default `min_coverage=0.50`). `dominance_ratio` es logica NUEVA, no un test del umbral.
- **Cambio aditivo**: `_passes` bifurca por `self.mode`; la rama `coverage` queda byte-identica.
- **Background(0)/Void(19) se excluyen por id literal** del computo de la 2da clase, **sin depender de
  `ignore_index`** (`_load_mask` devuelve el canal 0 crudo con Void=19; default `ignore_index=255`).
- **`target_classes` es un `set`**: la 2da clase se halla por conteo (`max`), no por indice.
- **Edge cases definidos** (el plan no los fija): `meadow==0 -> KEEP`; `meadow>0 & second==0 -> DROP`.
- **Firma `tuple[bool,float]` PRESERVADA** -> `filter_patch_ids`/`filter_folds`/`coverage_stats` intactos.

## Logica del filtro 3:1 (golden values)

```
hist = np.bincount(mask.ravel(), minlength=20)
meadow_px = hist[meadow_class]            # default class 1
if meadow_px == 0: KEEP
candidates = [c for c in target_classes if c not in (meadow_class, 0, 19)]
second_px = max((hist[c] for c in candidates), default=0)
if second_px == 0: DROP                    # Meadow sin competidor
keep = meadow_px <= ratio * second_px      # ratio default 3
```

Referencia REAL (verificada en disco, reproducida en CI con TARGET sintetico):
`TARGET_10102` (Meadow=6950, Corn=2264 -> 6950 > 3*2264 -> **DROP**); `TARGET_10004` (Meadow=0 -> **KEEP**).

## Riesgos principales

1. **R-LEGACY (riesgo #1)**: romper el modo coverage / `pastis_farslip_filtered_splits.json`. Mitigacion:
   cambio estrictamente aditivo (default `mode="coverage"`, defaults sin cambios), rama coverage
   byte-identica, NO tocar el JSON ni su `.dvc`; test de regresion.
2. **R-MEADOW**: identificar mal Meadow. Es **class id 1** (confirmado en 3 archivos); `meadow_class=1`.
3. **R-IGNORE**: bg(0)/void(19) contaminan el ratio. Excluir por id literal, no por `ignore_index`.
4. **R-EDGE**: `second_px==0`. Politica: `meadow==0 -> KEEP`; `meadow>0 & second==0 -> DROP`.
5. **R-CALIDAD**: `pastis_filter.py` usa stdlib logging + `print()` + type hints incompletos -> migrar a
   structlog/key-value + logger + tipar para que `make check` pase.

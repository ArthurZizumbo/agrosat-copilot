## Que entrega

Deteccion de drift de distribucion con Evidently AI (API moderna 0.7.x) aterrizada como pipeline
reutilizable mas asset Dagster con schedule semanal:

- **Drift de bandas Sentinel-2 / indices espectrales** via test de Kolmogorov-Smirnov (KS).
- **Drift de embeddings AlphaEarth / FarSLIP** via MMD (Maximum Mean Discrepancy) nativo de
  Evidently (`EmbeddingsDrift`). AlphaEarth atribuido como `SATELLITE_EMBEDDING/V1/ANNUAL`
  data v1.1 64-dim CC-BY-4.0 (NO v2.1) en docstrings de modulo y asset.
- **Drift de clases predichas** via Chi-cuadrado sobre el espacio 18-clase contiguo de US-030
  (columna `class_id` casteada a str para forzar el test categorico).
- **Asset Dagster `drift_check`** (group `monitoring`) con `deps` a los assets de ingesta reales
  `farslip_embeddings_consolidated` + `parcel_features_fused`, que computa el reporte, escribe el
  HTML, dispara la alerta y emite lineage.
- **Reporte HTML** en `data/monitoring/drift/report_{week}.html` (clave ISO `YYYY-Www`) y subida
  best-effort a `gs://agrosat-reports/drift/{week}/report.html` cuando hay ADC (bucket del plan v8,
  no `agrosat-artifacts`).
- **Alerta** cuando `drift_score > 0.3` (`DRIFT_SCORE_THRESHOLD`, comparacion estricta) via el
  resource `drift_notifier`.
- **Schedule semanal** `drift_check_weekly_schedule` (cron `0 6 * * 1`, lunes 06:00 UTC) —
  PRIMER schedule del proyecto, default STOPPED (opt-in, no dispara en dev).

## Notas / blockers

- **Plan B activo (sin particion por fecha)**: el proyecto aun no genera ingestas particionadas por
  fecha/trimestre, asi que el current set NO es "el trimestre actual". El asset construye un contraste
  REAL del mismo corpus (clase mayoritaria vs resto), que produce drift genuino entre subpoblaciones
  PASTIS. El pipeline ya esta parametrizado (`DEFAULT_CURRENT_PARQUET`) para apuntar a un current real
  cuando exista. Registrado en `docs/blockers/epic10-notas.md`.
- **API Evidently moderna**: se usa 0.7.x (`from evidently import Report, Dataset, DataDefinition`;
  `evidently.presets.DataDriftPreset`; `evidently.metrics.EmbeddingsDrift`). El snippet de la skill
  `agrosat-evidently-drift` es API 0.4.x (`evidently.report.Report` + `metric_preset` + `ColumnMapping`)
  y NO se copio.
- **MMD real, no proxy**: se usa el detector MMD nativo de `EmbeddingsDrift` (no PSI/Wasserstein de
  respaldo). El verdict se deriva del score continuo `[0,1]` contra un umbral documentado, no de la
  truthiness del float.
- **GCS / SMTP no verificados en dev**: subida a `gs://agrosat-reports/drift/` requiere ADC (degrada a
  local sin fallar) y el envio SMTP real solo se ejercita en prod (`enabled=False` por defecto -> alerta
  loggeada via structlog). Ambos documentados en `docs/blockers/epic10-notas.md`.
- **Schedule default STOPPED**: `drift_check_weekly_schedule` es opt-in; no dispara automaticamente
  hasta encenderse desde la UI / deploy.
- **Contexto E10 (no regresiones de esta US)**: FIX del orquestador para US-059 (DEFAULT_REGISTRY
  dedicado + `get_default_metrics()` singleton) elimino el "Duplicated timeseries" al re-instanciar la
  app (rompia 13 tests de integracion de chat). FIX de harness para US-065 (`_FakeConn`/`_FakePool` en
  `integration/test_chat_endpoint.py`) corrige un fallo PRE-EXISTENTE de US-054, no una regresion de E10.

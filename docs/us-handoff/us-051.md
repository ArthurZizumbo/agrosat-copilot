  - **up**: rol `agrosat_app NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE LOGIN` idempotente vía

### Decisiones de aislamiento (coding)

- **`parcels` (session_id nullable)**: policy directa `session_id = current_setting('app.current_session',
  true)::uuid`. Filas con `session_id IS NULL` quedan invisibles a TODOS los tenants (fail-closed). Aceptable
  MVP (el seed siembra con sesión); deuda: backfill + `NOT NULL` en rollforward futuro.
- **`features_parcels` (sin session_id)**: aislamiento INDIRECTO vía subquery `EXISTS (SELECT 1 FROM parcels p
  WHERE p.id = features_parcels.parcel_id AND p.session_id = current_setting(...)::uuid)` en USING **y** WITH
  CHECK (impide adjuntar features a parcelas de otra sesión). La RLS de `parcels` también aplica dentro de la
  subquery (defensa en profundidad). Deuda: columna denormalizada `session_id` + trigger.
- **`current_setting('app.current_session', true)` (missing_ok)**: sin sesión seteada devuelve NULL → `col =
  NULL` es NULL → 0 filas (fail-closed), nunca error. Consistente con el contrato `set_config('app.current_session',
  $1, true)` de `ml/agent/db.py`.
- **`rag_documents` SIN RLS**: corpus global PASTIS-R (no per-session); lectura pública para todos los tenants.
  Out-of-scope de RLS, documentado en la propia migración.
- **Roles**: `agrosat_app` (app, NO bypassa) creado en la migración; `agrosat` (superuser del compose) conserva
  BYPASSRLS implícito = rol de migración que bypassa. NO se crea rol de migración separado. El test de
  aislamiento DEBE conectarse como `agrosat_app` (un superuser bypassa RLS SIEMPRE, incluso con FORCE).
- **No aplicado localmente**: Docker compose sin contenedores arriba; la migración NO se aplicó (lo hará la fase
  QA). Sintaxis validada por revisión. Las 4 migraciones existentes intactas.

## Decisiones técnicas clave (planning)

1. **Rol `agrosat_app` (no-superuser, NOBYPASSRLS) creado en la migración**; `agrosat` (superuser del compose)
   = rol de migración que bypassa. Separación cumplida sin romper el compose. **Verificado en Context7
   (`postgres/rls.c`): superuser bypassa RLS SIEMPRE, incluso con FORCE** → el test DEBE correr como `agrosat_app`
   o sería falso verde.
2. **Grafo de ownership real** (leído de las 4 migraciones): `aois.session_id` y `parcels.session_id` = owner
   directo UUID; `features_parcels` **NO tiene `session_id`** → se aísla por subquery `EXISTS` contra `parcels`;
   `chat_sessions` se filtra por su propio `id`; `rag_documents` = **corpus global, SIN RLS** (no multi-tenant).
3. **`current_setting('app.current_session', true)::uuid` con `missing_ok=true`** → fail-closed (0 filas) sin
   error cuando no hay sesión seteada; no rompe queries del agente.
4. **`parcels.session_id` nullable** → filas NULL invisibles (fail-closed); aceptable MVP, deuda backfill+NOT NULL.
5. **Contrato `set_config` compartido**: backend reusa el mismo string SQL y key `app.current_session` que
   `ml/agent/db.py` (DRY; evaluar helper común).
6. **Una policy `FOR ALL`** (USING + WITH CHECK) cubre SELECT/INSERT/UPDATE/DELETE por tabla.

## Zonas sensibles

- **Superuser bypass**: cualquier conexión como `agrosat` (o superuser) ignora la RLS. El enforcement real

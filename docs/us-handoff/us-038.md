## Correcciones a la US (verificadas en recon contra disco)

- **`build_tsvit` NO expone hoy los hiperparametros Full-M** (`ml/models/tsvit_wrapper.py:455-497`): la factory
  solo pasa `num_classes, n_timesteps, img_size, in_channels, patch_size, dim, depth_temporal, depth_spatial,
  semantic_dim`. **`heads`, `dim_head`, `mlp_ratio`, `dropout` existen en `TSViT.__init__` (lineas 246-261)
  pero faltan en la factory** -> hay que ANADIRLOS (keyword-only, default == L4). No tocar la clase.
- **El default es "trimmed for L4"** (docstring 44-48: `dim=128, depth 4+4, heads=4, dim_head=32`). Full-M =
  subir esa capacidad (propuesto: `dim=192, depth 6+6, heads=6, dim_head=64`; ver Seccion 2 del plan).
- **"T completo" se controla por el DATASET, no el wrapper**: `_equispaced_indices(n_available, n_select)`
  (`pastis_seg_dataset.py:178-195`) con `n_select >= T` devuelve `np.arange(T)` (TODA la serie). Pasar
  `n_timesteps=64` (>= T_max PASTIS ~61) -> sin recorte.
- **RIESGO PE temporal (R-TLEN)**: el pipeline NO pasa `doy` al forward -> el modelo usa
  `temporal_pos_ordinal[1, n_timesteps, dim]`. El modelo debe construirse con `n_timesteps >= T_max` (64) o la
  PE ordinal se queda corta para T completo (bug silencioso). La PE por DOY real existe en el wrapper pero el
  pipeline no la alimenta (fuera de alcance).
- **RIESGO harness (R-HARNESS, #1)**: `build_model_for_kind` (`segmentation_inference.py:117-120`) reconstruye
  TSViT con `build_tsvit(...)` **defaults L4**. Si el `best.pt` es Full-M -> `load_state_dict` lanza shape
  mismatch. **El harness debe reconstruir con la MISMA capacidad Full-M** (config en el checkpoint o
  `model_kwargs` en el `CheckpointSpec`). Decidir ANTES del run.
- **El loop full ya existe**: warmup+cosine (`SequentialLR(LinearLR->CosineAnnealingLR)`, 1139-1155), AMP
  autocast, grad-clip 1.0, `last.pt`/`best.pt` por epoch + auto-resume (`_load_checkpoint_seg`), MLflow
  (`track_experiment`, data_version+code_version). **NO reimplementar.**
- **El harness re-score corre sobre fold-5** (`rescore_all_checkpoints(fold=5)`, `dense_metrics.py:551`); el
  registry hoy tiene `tsvit-pheno` pero **no `tsvit`** -> anadir la entrada.

## Riesgos principales

1. **R-HARNESS (#1)**: el harness reconstruye TSViT L4 y carga un `best.pt` Full-M -> shape mismatch.
   Mitigacion: el harness reconstruye con la MISMA capacidad (config en checkpoint o `model_kwargs` en spec);
   test de carga. **Decidir ANTES del run.**
2. **R-TLEN**: PE ordinal corta si T completo (~61) > `n_timesteps` del modelo (pipeline no pasa `doy`).
   Mitigacion: construir con `n_timesteps=64` (>= T_max); el dataset no recorta.
3. **R-OOM**: batch 20 + T completo + dim 192. Estimacion 25-40 GB << 96 GB (cabe). bf16 autocast. Si OOM:
   bajar batch a 12-16 o `n_timesteps` a 45.
4. **R-SATUR**: mIoU no sube a 0.65+ (saturacion PASTIS ~70%). Mitigacion: reporte honesto fold-4/fold-5 +
   caveat; target es banda (0.65 minimo); NO inflar a 0.75+.
5. **R-TIME**: 40 epochs no caben en una ventana. Estimacion 3-6 h (cabe). Auto-resume (`last.pt`) cubre cortes;
   `--num-workers 8-12` para no estrangular la GPU con I/O (T~61 frames/patch).
6. **R-FIRMA/R-NBREAK**: romper la firma de `build_tsvit` / runs L4 de notebooks. Mitigacion: kwargs keyword-only
   con default L4; run name `alt-tsvit-v1` (L4) sigue disponible.
7. **R-MLFLOW**: run queda RUNNING; lineage en `:5010` (la VM puede usar MLflow nativo SQLite, no Docker).
   Mitigacion: cerrar el run; ingestar al `:5010` local (patron US-034) o `--mlflow-uri` correcto.
8. **R-DATA**: `data/PASTIS-R` ausente en la VM o sin `NORM_S2_patch.json`. Mitigacion: verificar en F: ANTES;
   scp/rsync por tunel o `dvc pull` (ojo 401 sin ADC -> push desde local o scp).

`build_and_train`/CLI entrenan TSViT con T completo (`n_timesteps=64`), 128px nativo, Full-M (dim 192, depth 6+6,
heads 6), batch 20, 40 epochs, warmup+cosine (Tarasiou 2023); el run H100 `alt-tsvit-fullm-v1` corre sin OOM con
auto-resume y registra MLflow (`:5010`) con `data_version`+`code_version`, curvas y `best.pt`; **mIoU fold-4 >=
0.65** (objetivo 0.68-0.72, NO 0.75+); el `best.pt` se registra como `tsvit` en el harness y se re-score en
**fold-5** apples-to-apples; reporte honesto fold-4/fold-5 con caveat de saturacion PASTIS ~70%; `best.pt` ->
DVC; `make check` limpio.

## Resumen ejecutivo

US-056 es **scaffolding honesto**: el MVP corre inferencia SINCRONA y esta US entrega la interfaz async + su
documentacion, NO un worker Pub/Sub productivo (eso requiere GCP Pub/Sub vivo + Cloud Run GPU L4). Su definicion
de "hecho" ES ser un stub documentado que falla claro, nunca un no-op silencioso. `JobsService.submit_job` con
`enqueue_mode="sync"` (default, REAL) corre la inferencia INLINE delegando al runner `classify_new_parcel` (el
mismo tool del reasoner de `/chat`, CPU-light `xgb-alphaearth`) y devuelve el job ya `DONE`/`FAILED`; con
`enqueue_mode="pubsub"` (FUTURE) lanza `NotImplementedError` claro ("Pub/Sub mode is Full-only (US-056 deferred,
ADR-009)", topic `inference-jobs`). Modelo pesado en `sync` -> `FAILED` honesto (el runner NO se invoca, no se
finge). El subscriber `ml/workers/inference_worker.py` documenta la FORMA del callback Full (validate -> infer
GPU -> persist GCS -> publish -> ack/nack) pero `_run_inference`/`_publish_result`/`run_subscriber` lanzan
`NotImplementedError` explicito; solo `parse_job_request` (validador) es runnable. **No se monta router `/jobs`**
en el MVP (US diferida; seria el adaptador HTTP a `JobsService` al activar Full).

## Lo implementado realmente (no asumido)

- **`backend/app/services/jobs_service.py`**: `JobsService` con `submit_job`/`get_job_status`, `EnqueueMode`
  (`sync`/`pubsub`), `JobRequest`/`JobStatus`/`JobState` (`StrEnum` `queued/running/done/failed`). Registro de
  jobs in-memory (`dict`, valido en MVP porque el sync completa antes de retornar). Runner + pool inyectables
  (tests sin XGBoost ni DB). `job_id` UUID4 hex trazable en logs structlog. `_default_runner` importa
  `ml.agent.tools.classify` lazy (jobs_service importa sin polars/xgboost).
- **`ml/workers/inference_worker.py`** (paquete `ml/workers/` nuevo): `handle_message` (forma del callback Full),
  `parse_job_request` (REAL, valida el body a `JobRequest`), `InferenceResult` (schema topic `inference-results`),
  `_run_inference`/`_publish_result`/`run_subscriber` (`NotImplementedError` explicito, Full-only). El `__main__`
  NO arranca subscriber: loguea + lanza `run_subscriber()` que falla claro.
- **`docs/decisions/ADR-012-inferencia-sincrona-mvp.md`**: por que sincrono en MVP, la interfaz `JobsService` y el
  plan de activacion Full (Terraform topics `inference-jobs`/`inference-results`/`inference-jobs-dlq`, DLQ
  `max_delivery_attempts=3`, Cloud Run GPU L4, notificador SSE).
- **Editados**: ninguno (cero variables nuevas en `Settings`: reusa `pubsub_inference_topic`, `gcp_project_id`,
  `gcs_artifacts_bucket`). El punto de montaje `/jobs` NO se toca (US diferida).

## Deuda honesta / fuera de alcance (es la naturaleza de la US)

- **Worker Pub/Sub productivo NO existe**: es FUTURE/diferido por diseno (ADR-009/ADR-012). El MVP corre
  inferencia sincrona. `_run_inference`/`_publish_result`/`run_subscriber` lanzan `NotImplementedError`.
- **Registro de jobs in-memory**: el Full lo persistira en PostgreSQL para coordinacion inter-proceso (deuda
  explicita en ADR-012).
- **Router `/jobs` no montado**: seria el adaptador HTTP a `JobsService` cuando se active Full.
- **Plan de activacion Full** (wiring, no rediseno): Terraform topics + DLQ, rama `pubsub` de `submit_job`,
  quitar los `NotImplementedError` del worker, notificador SSE, idempotencia keyed por `job_id` en GCS.

## Resumen ejecutivo

US-052 endurece (NO reescribe) el endpoint SSE `POST /chat` con tres controles: rate-limit por sesion via
slowapi (`@limiter.limit(CHAT_RATE_LIMIT="10/minute", key_func=session_id_key)`), auth-guard
`Depends(verify_chat_session)` que corre `SELECT 1 FROM chat_sessions` bajo `get_scoped_conn` (US-051, 0 filas ->
403 fail-closed), y el wiring RLS del `ToolContext`: el pool del agente pasa de `ml/agent/db.get_pool()` (rol
superuser `agrosat`, BYPASSRLS) al pool `app_database_url` (rol `agrosat_app` NOBYPASSRLS) via `pool_factory`
inyectable — sin esto la RLS de US-051 NO aislaria las tools del `/chat` (era un falso verde de seguridad). El
modelo reasoner por defecto se fijo en `gemini-3.5-flash` (decision de Arthur por coste/latencia; se elimino el
hardcode `gemini-3.1-pro`). El handler de `RateLimitExceeded` se registra en `main.py` para que el 11vo request
salga como JSON 429 (no SSE a medias). SoC respetado: el router es un adaptador HTTP fino, toda la logica vive en
`ChatService`.

## Lo implementado realmente (no asumido)

- **`backend/app/core/rate_limit.py`** (nuevo): `session_id_key(request)` (extrae `X-Session-ID`, fallback
  `get_remote_address`), `build_limiter`, singleton `limiter` (`storage_uri=redis_url`, `default_limits=[]`),
  `CHAT_RATE_LIMIT="10/minute"`. La aplicacion del limite es contra el objeto `limiter` ligado por el decorador.
- **`backend/app/api/deps.py`** (nuevo): `verify_chat_session` (SELECT 1 bajo `get_scoped_conn`; 0 filas -> 403);
  `asyncpg` importado en runtime (no solo TYPE_CHECKING) para que FastAPI resuelva el `Depends`.
- **`backend/app/services/chat_service.py`**: `_VARIANT_TO_MODEL["gemini"]`/`_DEFAULT_MODEL` -> `gemini-3.5-flash`;
  `_build_context` usa `backend.app.core.db.get_pool` via `pool_factory` inyectable (B2 RLS).
- **`backend/app/api/chat.py`**: decorador `@limiter.limit`, `request: Request` + body renombrado a `body`,
  `Depends(verify_chat_session)`.
- **`backend/app/main.py`**: `app.state.limiter = limiter` + `add_exception_handler(RateLimitExceeded, ...)`
  (`# type: ignore[arg-type]` por la varianza slowapi/Starlette).

## Deuda honesta / fuera de alcance

- **Cobertura backend >=70 % en CI**: se verifica con `make test` completo en CI, no en esta verificacion local.
- **`gemini-3.5-flash` sin GA real**: los tests no llaman a red (agente stub); la validacion en vivo del modelo
  cloud es de US-059. La desviacion consciente del AC original (`gemini-2.5-pro` -> `gemini-3.5-flash`, decision
  de Arthur por coste/latencia) queda documentada en este resolved + handoff + plan.
- **DRY**: `backend.app.core.db` replica el contrato del listener de `ml/agent/db.py` (no lo duplica;
  reusa `to_asyncpg_dsn`). Intencional.

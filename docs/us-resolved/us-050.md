## Resumen ejecutivo

US-050 es **documental** (sin entrenamiento, sin codigo ejecutable). El plan decia "redactar
ADR-009", pero ADR-009 ya existe (reactivacion H100 + pivote FarSLIP); para no sobrescribir esa
decision se creo **ADR-011** (Gemma 4 26B-A4B LoRA = FUTURE, status Aceptada FUTURE, NO se entrena
antes del 27-jun). El ADR formaliza por que Gemma 4 LoRA queda fuera de la presentacion y corrige
varios supuestos del skill `agrosat-llm-finetuning` que una verificacion honesta en HuggingFace +
docs de PEFT (jun-2026) revelo insostenibles: el id real es `google/gemma-4-26B-A4B-it` (el
`gemma-4-26b-it` no existe); QLoRA esta bloqueado (expertos MoE = tensores 3D fused
`nn.Parameter` que `bitsandbytes` no cuantiza); la via real de fine-tune es
`target_parameters=["mlp.experts.gate_up_proj","mlp.experts.down_proj"]` (PEFT >= 0.17,
bleeding-edge), no `target_modules` (que solo matchea ~0.91% de params). Se actualizaron el skill
y los espejos `CLAUDE.md`/`AGENTS.md`.

## Decisiones tecnicas clave + caveats

- **QLoRA bloqueado**: los expertos MoE son tensores 3D fused `nn.Parameter` -> `bitsandbytes` no
  cuantiza ese layout.
- **Via real bleeding-edge**: `target_parameters` para MoE `nn.Parameter` 3D requiere PEFT >= 0.17
  (overhead por-experto, no multi-adapter).
- **AgroMind eval-only**: 28482 QA sin train split -> fine-tune = leakage (coherente con US-049).

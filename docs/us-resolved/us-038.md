## Decisiones tecnicas clave + caveats

- **n_timesteps=37 (NO 64)**: el plan pidio 64 (>=T_max para la PE), pero el dato real lo desmiente — PASTIS tiene
  T VARIABLE (T_MIN=37, T_MAX=61, T_MEDIAN=46; 563 patches con T<40). `_equispaced_indices` solo submuestrea si
  `n_select < T`; con 64 los patches cortos quedan a su T nativo y el `torch.stack` del batch falla. 37 = T_MIN
  fuerza un submuestreo uniforme de 37 fechas equiespaciadas en TODO patch (batch apilable) cubriendo el ciclo
  fenologico completo. Es la fuente unica de verdad (train + registry + tests).
- **Bug del harness re-score (R-HARNESS extendido)**: el harness construia el dataset temporal con `n_timesteps=10`
  (default) mientras el modelo se entreno con 37 -> recibia series de T distinto al aprendido -> su PE ordinal
  `[1,37,dim]` usaba solo las filas 0..9 -> mIoU colapsaba a 0.17 (bug SILENCIOSO: 0 missing/unexpected keys).
  Fix: `_rescore_one` pasa `n_timesteps` del `spec.model_kwargs` al dataset temporal. Con el fix: fold-5 0.6789
  (coherente con val fold-4 0.699). Sin el fix el numero era espurio.
- **Contrato R-HARNESS (capacidad)**: `CheckpointSpec.model_kwargs` lleva la config Full-M para que
  `build_model_for_kind` reconstruya la topologia exacta al cargar el `state_dict` (el best.pt no incrusta la
  capacidad). Retrocompat: defaults de `build_tsvit` = L4 (no rompe notebooks 5a/5b).
- **Estabilidad**: AMP + GradScaler + grad-clip 1.0 + warmup->cosine (evitan el NaN ~epoch 8 del TSViT).

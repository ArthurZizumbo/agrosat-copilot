## Resumen ejecutivo

US-047 implementa el **factory del agente** (`create_agent`) y el **loop manual de
function-calling** (`stream_response`) con SDK `google-genai` y AUTOMATIC function calling
DESHABILITADO: lee `response.function_calls`, valida args con el `input_model` Pydantic del
`ToolSpec`, ejecuta `ToolSpec.fn(inp, ctx)` (inyectando `session_id` por tool), devuelve
`types.FunctionResponse` y emite `AgentEvent` tipados (tool_call, tool_result, text_delta, done,
error) con guard `MAX_TURNS=8`. El **backend LLM es una abstraccion inyectable** (`LLMBackend`
ABC): `GeminiBackend` (cloud), `VLLMOpenAIBackend` (Qwen on-prem US-048), `OllamaBackend`
(Gemma multimodal); `make_backend(model, settings)` enruta por prefijo del id. El system prompt
analista (Be My Eyes, citas obligatorias) vive en `prompts.py`. `ChatService` (US-046) se cablea
al agente real.

## Decisiones tecnicas clave + caveats

- **`GeminiBackend`** usa API no-stream (`generate_content`) para resolver function_calls
  (canonica) + stream para texto; soporta cliente async (`client.aio`) y sync (test doubles).
- **`backends.py` 67% cobertura**: paths de streaming real no unit-testeables sin LLM en vivo;
  la logica de mapeo si esta testeada.
- **Excepciones pre-loop**: el guard de error es ultimo recurso; excepciones antes del loop no se
  capturan en `stream_response`.
- **Coordinacion de cierre**: `backends.py`/`prompts.py` se completaron a mano con la interfaz
  exacta que `agent.py` consume (un workflow previo murio a mitad). Tests de US-045
  `test_function_declarations` actualizados a 10 tools (US-046 anadio `retrieve_context`).

## Resumen ejecutivo

US-065 entrega la observabilidad estructurada del endpoint `/chat` SSE: una unica linea structlog
canonica `chat_turn_metrics` por turno con latencia end-to-end clasificada por SLO (`simple` 0
tool-calls -> 3s, `multi_step` >=1 tool-call -> 15s, con `slo_met: bool`), conteo de tool-calls, tokens
del proveedor (REALES o `None`, nunca inventados) y `variant` + `model` activos como clave FinOps. Incluye
la propagacion del `usage` real desde el SDK por el contrato de eventos del agente (`BackendChunk.usage`
-> `DoneEvent.usage`), un export Prometheus perezoso y gateado (off por defecto, degradacion honesta) y
la doc operativa `docs/observability/chat-metrics.md`. El helper puro `chat_metrics.py` es DRY e
inmutable; los 13 tests unitarios pasan. La US queda **WARN** por deuda funcional honesta (tokens de
Qwen `None` en streaming) y por un fallo PRE-EXISTENTE de tests de integracion de chat ajeno a esta US.

## Por que WARN (deuda honesta, no falla de entrega)

El entregable de US-065 esta completo y sus 13 tests unitarios pasan, pero el cierre se marca **WARN**
por tres motivos honestos, todos documentados en `docs/blockers/epic10-notas.md`:

1. **B6 — tokens de Qwen/vLLM `None` en streaming**: el backend OpenAI-compatible de vLLM/Qwen
   (`VLLMOpenAIBackend`) NO emite `usage` en streaming salvo que se pase
   `stream_options={"include_usage": True}`, que hoy no se setea. En esa ruta `tokens_*` queda `None`.
   Gemini SI entrega tokens reales. No se inventan tokens (regla de datos reales). Es deuda funcional
   real: el slot de tokens del switch A/B no se llena para la variante on-prem hasta aplicar el fix.

2. **B7 — verificacion MLflow `:5010` no hecha en vivo**: el server Docker `:5010` no estaba corriendo en
   la sesion; la escritura de tags (`code_version`/`data_version`) ya esta garantizada por
   `track_experiment` (US-019) y el procedimiento de verificacion queda documentado, pero la auditoria en
   vivo no se ejercito.

3. **B8/B9 — panel Grafana sin scrape + tests de integracion de chat rotos PRE-EXISTENTE**: el panel de
   chat necesita un Prometheus scrapeando `/metrics` con el flag on (no fabrica trafico sintetico). Y los
   tests de integracion `test_chat_endpoint.py` / `test_chat_uses_session_model.py` fallan con
   `Duplicated timeseries` por el middleware HTTP de **US-059**, NO por US-065 (verificado: el fallo
   existe igual en el arbol limpio). El fix correcto pertenece a US-059. Los 13 tests unitarios de chat
   metrics SI pasan.

En resumen: codigo + tests unitarios verdes y observabilidad completa por structlog; el WARN refleja que
los tokens de la variante on-prem y el panel/MLflow vivo dependen de pasos externos (fix `include_usage`,
scrape Prometheus, server `:5010` levantado) que no se ejecutaron en esta sesion.

## Cumplimiento de estandares

- **Datos reales o `None`**: tokens del proveedor reales (Gemini) o `None` (Qwen sin `include_usage`),
  nunca inventados.
- **DRY + inmutabilidad**: `ChatMetricsAccumulator` (`frozen`) -> cada turno/stream concurrente no
  comparte estado mutable.
- **SoC**: instrumentacion en service + util; el router sigue siendo adaptador HTTP. Latencia con una
  sola fuente de verdad (el `time.perf_counter()` de `ChatService.stream`).
- **Degradacion honesta (R3)**: el export Prometheus es perezoso y gateado; cualquier fallo se traga con
  `logger.debug` -> el chat nunca se cae por la observabilidad.
- Type hints, docstrings Google ingles, prosa ES, sin emojis.

## Resumen ejecutivo

US-045 puebla `ml/agent/` (antes esqueleto puro) con las **9 FunctionTools geoespaciales** del
agente sobre una infraestructura comun: `schemas.py` (9 pares `ToolInput`/`ToolOutput` Pydantic
v2 strict), `db.py` (`session_scoped_conn` con `set_config('app.current_session',$1,true)`),
`context.py` (`ToolContext`) y `tools/__init__.py` (registro lazy `TOOL_REGISTRY` + conversor
Pydantic->genai). Las 9 tools se reparten en **5 sync demo** (list_parcels, get_parcel_timeseries,
get_aoi_stats, classify_new_parcel, explain_prediction) + **4 deferred** (search_stac, get_tiles,
add_aoi, compare_models). Cada tool es `async def run(inp, ctx) -> Output`. Seguridad: SQL 100%
parametrizado, `WHERE session_id=$1` en cada query de DB (defensa en profundidad; la RLS policy
es EPIC 11), aislamiento cross-session verificado. SDK `google-genai` para `FunctionDeclaration`
(NO google-adk, removido del lock).

## Decisiones tecnicas clave + caveats

- **RLS policy = EPIC 11**: hoy las tools garantizan aislamiento por `WHERE session_id` +
  `SET LOCAL` (defensa en profundidad).
- **Fix de cierre**: `GeoJSONGeometry._ALLOWED_TYPES` debia ser `ClassVar[frozenset[str]]`
  (Pydantic v2 lo trataba como `ModelPrivateAttr`).
- **Nota para el loop**: `get_settings()` real no se puede llamar en tests (el `.env.local`
  dev tiene llaves que `Settings(extra="forbid")` rechaza); los tests usan `FakeSettings`.
- **`compare_models`**: un `parcel_id:int` plano no matchea los OOF (ids compuestos `patch_local`);
  camino vacio honesto cubierto.

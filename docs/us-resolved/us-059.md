## Resumen ejecutivo

US-059 entrega el scaffolding de observabilidad tecnica del backend FastAPI: un `PrometheusMiddleware`
(Starlette `BaseHTTPMiddleware`) que instrumenta **toda request real del proceso** (`Histogram`
`http_request_duration_seconds` para p50/p95/p99 via `histogram_quantile`, `Counter`
`http_requests_total` para RPS / error rate, `Counter` `http_request_exceptions_total`), un endpoint
fino `GET /metrics` que expone el registry en `CONTENT_TYPE_LATEST`, control anti-cardinalidad (el
label `path` se normaliza al template de ruta y las rutas no resueltas caen bajo `<unmatched>`),
plantillas Grafana versionadas (API / worker ML / data pipeline), alert rules Prometheus y 5 tests
sobre `CollectorRegistry` aislado. Las metricas son **reales del proceso** (cada request incrementa
contadores y observa el histograma) — sin trafico sintetico ni valores de GPU inventados. La parte de
chat (latencia p95, tool-call success, tokens) se difiere honestamente a US-065 por corte de alcance
del plan v8.

## Cumplimiento de estandares

- **SoC**: el router solo expone; la instrumentacion vive en el middleware.
- **Type hints**, docstrings Google ingles, prosa ES, `structlog`, sin emojis, sin `print()`.
- **Anti-cardinalidad** impuesta por diseno (`resolve_route_template` + `<unmatched>`), no por
  convencion.
- **Datos reales**: metricas del proceso; sin GPU util inventada ni trafico `/chat` sintetico.

## Decisiones tecnicas clave + caveats

- **FIX load-bearing — `DEFAULT_REGISTRY` dedicado + `get_default_metrics()` singleton**: re-instanciar
  la app (import de modulo + factory de tests de integracion) ya NO lanza `Duplicated timeseries`. Sin
  esto, re-registrar las colectoras sobre el `REGISTRY` global rompia 13 tests de integracion de chat.
  Los tests unitarios usan su propio `CollectorRegistry` para aislamiento.
- **B5 (`epic10-notas.md`)**: con `prometheus-client` 0.25.0, `CONTENT_TYPE_LATEST` es
  `version=1.0.0` (no el historico `0.0.4`); el test asserta contra el simbolo de la libreria, no
  contra un string hardcodeado.

## Pendientes / fuera de alcance (blockers documentados en `epic10-notas.md`)

- **B1**: GPU util / OOM (`DCGM_FI_DEV_FB_USED`/`..._FREE`) requiere `dcgm-exporter` + Prometheus
  scrapeando la H100/L4; no hay scrape activo en este entorno -> panel/alerta como plantilla, sin datos
  inventados.
- **B2**: alertas a canal real (email/Alertmanager o alert policy Cloud Monitoring) requieren proyecto
  desplegado; reglas declaradas, wiring pendiente.
- **B3**: Cloud Run `min_instances=0` no es scrapeable por pull estable -> push gateway o Cloud
  Monitoring (nota tecnica en `infrastructure/grafana/README.md`).
- **B4**: paneles de chat (latencia p95, tokens, modelo activo, tool-call success) se pueblan con
  trafico `/chat` real -> US-065 (NO se fabrica trafico sintetico).
- **multi-worker**: el registro global de `prometheus_client` requiere `PROMETHEUS_MULTIPROC_DIR` o
  single-worker (target Cloud Run); documentado en el modulo y el README.

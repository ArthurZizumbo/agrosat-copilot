## Resumen ejecutivo

US-055 monta TiTiler como router DENTRO de la imagen backend (no servicio aparte): tiles PNG/WebP on-the-fly
desde COGs (GCS `vsigs` en prod, COG local/http en dev) para overlay NDVI/NDWI sobre MapLibre, sin
pre-renderizar. Dos superficies sobre un unico render compartido (DRY): `/cog/...` = `TilerFactory` completo
(endpoint literal del AC con `expression`/`rescale`/`colormap_name` libres) y `/tiles/{z}/{x}/{y}.png?url&index`
= adaptador del contrato estable de US-053 (TMS fijo `WebMercatorQuad`), que reemplaza el stub `501`. La cache
es Redis explicita (`cached_tile`, clave `tile:sha256(method|path|sorted(qs))`, `SETEX` 900 s, headers
`Cache-Control: public, max-age=900` + `X-Tile-Cache: HIT|MISS`) — helper explicito, NO middleware global (que
cachearia el SSE de `/chat`). NDMI sobre el COG farslip de 4 bandas (sin SWIR) responde `422` honesto. La
observacion de SSRF que el QA inicial dejo como hardening quedo MITIGADA: `validate_cog_url` aplica un allowlist
del parametro `url` (locales/`file://` siempre; `gs://` solo `gcs_data_bucket`; `http(s)://` solo hosts de
`tile_url_allowed_hosts`) -> 403 para hosts no permitidos, con test `test_tiles_ssrf_url_is_403`.

- **Editados**: `main.py` (monta `cog_tiler.router` bajo `/cog` + `add_exception_handlers`; importa `cog_tiler`
  que pinea PROJ), `pyproject.toml`/`poetry.lock` (`rio-cogeo` dev), `.env.example`.
- **`validate_cog_url`** (`cog_tiler.py:56`): allowlist por scheme — locales/`file://`/drive-letter siempre;
  `gs://` solo `settings.gcs_data_bucket`; `http(s)://` solo hosts de `settings.tile_url_allowed_hosts`; resto ->
  `CogUrlNotAllowedError` -> 403. Invocada en `render_cog_tile` (linea 219).
- **PROJ fix** (`proj_env.ensure_proj_data`): pinea `PROJ_DATA`/`PROJ_LIB` al `proj_data` bundled de rasterio
  ANTES de importar rasterio/titiler (gotcha del dev box Windows con PostGIS proj.db viejo). No-op en Cloud Run.

# Manual Test — US-048: Qwen on-prem self-hosted en la H100 (serving)

Verificacion del serving del reasoner Qwen MoE-A3B (variante-B on-prem, soberania de datos),
endpoint OpenAI-compatible intercambiable con Gemini desde el mismo `VLLMOpenAIBackend`. La via
vLLM esta **bloqueada por el host** (nested-virt off); la via **operativa** es **llama.cpp nativo
Windows + CUDA**, PROBADA end-to-end en la H100 (15-jun-2026). El serving es inherentemente un
flujo **GPU/manual**: la logica del cliente esta cubierta por tests (3 + subset backends), el
arranque real se valida en la VM.

> Commits: `2876355 feat(E7): US-048 codigo serving Qwen vLLM on-prem` + `4ca6b08 feat(E7): US-048
> serving Qwen on-prem via llama.cpp nativo Windows (PROBADO en H100)`.
> Handoff: [docs/us-handoff/us-048.md](../us-handoff/us-048.md) · Doc: [docs/serving/qwen35.md](../serving/qwen35.md).

| Via vLLM bloqueada | infra del host (nested-virt), NO el codigo; codigo vLLM completo y listo | [x] documentado |

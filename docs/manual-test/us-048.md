# Manual Test — US-048: Serving Qwen on-prem (H100)

Verificacion del serving on-prem del reasoner Qwen MoE-A3B. La via vLLM quedo BLOQUEADA por la
infraestructura del host (nested-virt off, no por el codigo) y se SUSTITUYO por **llama.cpp
nativo Windows + CUDA**, probado end-to-end en la H100 (endpoint OpenAI-compatible -> el
`VLLMOpenAIBackend` del agente funciona sin cambios). Lo automatizable son los 3 tests de la
logica del benchmark; el re-arranque del serving sigue `[ ]` (GPU compartida liberada tras la
prueba). Fuente de QA: handoff embebido ([docs/us-handoff/us-048.md](../us-handoff/us-048.md))
+ [docs/serving/qwen35.md](../serving/qwen35.md).

> US-048 cubre el criterio Serving on-prem del reasoner (EPIC 7) — Qwen3-30B-A3B Int4/GGUF
> single-GPU, endpoint OpenAI-compatible :8002, integracion con el backend dual de US-047.

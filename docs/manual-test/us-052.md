# Manual test — US-052: POST /chat SSE (rate-limit + auth-guard + RLS)

> Flujos que requieren validacion humana contra un backend en vivo. Los tests
> automatizados (25 verdes: 13 unit + 12 integracion) cubren el contrato con
> mocks; aqui se valida el endpoint real con Postgres + Redis + un session_id
> sembrado.

## Pre-requisitos

1. Stack local levantado (Postgres con RLS de US-051 + rol `agrosat_app`, Redis):
   ```bash
   docker compose up -d postgres redis
   dbmate up                          # aplica la migracion RLS de US-051
   ```
2. `.env.local` con:
   - `APP_DATABASE_URL` apuntando al rol `agrosat_app` (NOBYPASSRLS).
   - `REDIS_URL` (storage del limiter).
   - `LLM_VARIANT_DEFAULT=gemini` y `GEMINI_MODEL=gemini-3.5-flash` (default).
   - Credenciales Gemini (`GEMINI_API_KEY` o Vertex via `GOOGLE_GENAI_USE_VERTEXAI`).
3. Una sesion sembrada cuyo UUID conozcas. Inserta una fila propia bajo el rol
   `agrosat_app` con `SET LOCAL app.current_session`:
   ```bash
   export SID=11111111-1111-1111-1111-111111111111
   psql "$APP_DATABASE_URL" <<SQL
   BEGIN;
   SELECT set_config('app.current_session', '${SID}', true);
   INSERT INTO chat_sessions (id) VALUES ('${SID}')
     ON CONFLICT (id) DO NOTHING;
   COMMIT;
   SQL
   ```
4. Arranca el API:
   ```bash
   poetry run uvicorn backend.app.main:app --reload --port 8000
   ```

## 1. SSE en vivo (AC-1) — round-trip con streaming

```bash
curl -N -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -H "X-Session-ID: 11111111-1111-1111-1111-111111111111" \
  -d '{"messages":[{"role":"user","content":"Resume la parcela 11"}],"parcel_id":11}'
```

**Esperado:** la conexion queda abierta (`-N` desactiva el buffering de curl) y
emite frames en orden:

- `event: perceiver_observation` con el bloque estructurado real del perceiver.
- cero o mas pares `event: tool_call` / `event: tool_result`.
- una o mas `event: text_delta` (la respuesta llega por chunks, en vivo).
- `event: done` como frame terminal.

Sin `parcel_id`/`aoi` el `perceiver_observation` se omite y el stream arranca
directo con la respuesta del reasoner. Verifica que **no hay un solo bloque al
final**: los `text_delta` deben aparecer progresivamente.

## 2. Rate-limit en vivo (AC-4) — 10/minuto por sesion -> 429 al 11vo

```bash
SID=11111111-1111-1111-1111-111111111111
for i in $(seq 1 11); do
  code=$(curl -s -o /dev/null -w "%{http_code}" -X POST http://localhost:8000/chat \
    -H "Content-Type: application/json" \
    -H "X-Session-ID: ${SID}" \
    -d '{"messages":[{"role":"user","content":"hola"}]}')
  echo "req ${i} -> ${code}"
done
```

**Esperado:** `req 1..10 -> 200` y `req 11 -> 429`. El 11vo es **JSON** (no un SSE
a medias): el limite se evalua antes de abrir el stream.

```bash
curl -s -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" -H "X-Session-ID: ${SID}" \
  -d '{"messages":[{"role":"user","content":"hola"}]}' | head -c 200
# -> {"error":"Rate limit exceeded ..."} (Content-Type NO es text/event-stream)
```

**Aislamiento por sesion:** repite el loop con un `X-Session-ID` distinto y
verifica que arranca de nuevo en `200` (no comparte bucket). Espera 60 s para que
la ventana de la primera sesion se reabra.

## 3. Auth-guard (AC-5) — 400 / 403

```bash
# Falta el header -> 400
curl -s -o /dev/null -w "missing  -> %{http_code}\n" -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" -d '{"messages":[]}'

# Header malformado -> 400
curl -s -o /dev/null -w "malformed-> %{http_code}\n" -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" -H "X-Session-ID: not-a-uuid" -d '{"messages":[]}'

# UUID valido pero sesion inexistente/ajena -> 403 (RLS fail-closed, 0 filas)
curl -s -o /dev/null -w "foreign  -> %{http_code}\n" -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -H "X-Session-ID: 99999999-9999-9999-9999-999999999999" -d '{"messages":[]}'
```

**Esperado:** `400`, `400`, `403`.

## 4. RLS real de las tools (AC-6) — aislamiento cross-session

Esto es lo que los tests de integracion **no** cubren (usan pool fake; el
aislamiento completo vive en la suite testcontainers de US-051). Validacion
manual:

1. Con la sesion A (sembrada), pide al copiloto que liste parcelas
   (`list_parcels`). Anota el conjunto devuelto.
2. Crea una sesion B con sus propias parcelas (siembra otra fila + parcelas bajo
   `app.current_session=B`).
3. Desde la sesion A vuelve a pedir el listado: **no deben aparecer las parcelas
   de B**. El pool del `ToolContext` usa `app_database_url` (rol `agrosat_app`
   NOBYPASSRLS), asi que el `SET LOCAL app.current_session` de las tools aisla de
   verdad. Con el pool superuser viejo (`ml.agent.db.get_pool`) este paso
   fallaria (veria todo) — la red de seguridad es este test manual + la suite
   US-051.

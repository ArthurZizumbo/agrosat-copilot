Guion de validacion en navegador (`cd frontend && pnpm dev`, abrir `http://localhost:3000`).

- `pnpm install` aplicado, dev server arriba (`pnpm dev`).

## Flujos

### 1. El mapa carga (init SSR-safe)

1. Cargar la pagina. El canvas MapLibre aparece centrado sobre Toscana (`[11.105, 43.305]`, zoom 6).
2. Controles visibles: navegacion (top-right, sin compass), escala metrica (bottom-left), atribucion Esri (compact).
3. Sin errores en consola; `maplibre-gl` se importa dinamicamente solo en cliente (no hay error de `window` en SSR).
4. Hint de mapa vacio abajo-centro (`map.empty`) mientras no hay parcelas ni AOI.

**Esperado**: mapa interactivo, basemap satelital Esri, cero requests a Mapbox.

### 2. Demo AOI + parcelas (flyTo)

1. Disparar "area demo" (sidebar / boton que invoca `flyToDemoAoi` via `mapApiRef`).
2. El mapa vuela al bbox demo; se pinta el AOI (relieve ambar punteado) y las parcelas demo coloreadas por cultivo.
3. Leyenda de cultivos (top-left) aparece con las clases presentes.
4. Hover sobre una parcela -> cursor pointer + highlight (opacidad 0.7) de esa parcela.

**Esperado**: paridad funcional con el MapCanvas previo (la logica vive ahora en `useMap`, no duplicada).

### 3. Draw AOI (rectangulo)

1. Activar draw mode (toolbar). El cursor pasa a crosshair.
2. Arrastrar sobre el canvas: aparece el rubber-band punteado ambar (lo dibuja MapCanvas leyendo `drawRect` de `useMap`).
3. Soltar con un arrastre real (> 6px): se crea el AOI (`selectDrawnAoi`), se pinta y queda activo; draw mode se desarma.
4. Click sin arrastrar -> no crea AOI, solo desarma draw mode.
5. `Escape` durante el arrastre cancela el rectangulo y desarma draw mode.

**Esperado**: AOI dibujado disponible como `aoi` inline en el siguiente POST /chat.

### 4. Click parcela -> el chat sabe de esa parcela (cross-store)

1. Con parcelas pintadas (flujo 2), click sobre una parcela.
2. Aparece el popup i18n (cultivo / confianza / NDVI / area / fuente) en el idioma activo.
3. Aparece el chip "Parcela seleccionada: Parcela <id>" (top-right, bajo los controles), con el `parcel_id` REAL de la feature (no inventado), titulo `map.parcel_in_chat`.
4. Internamente: `mapStore.selectedParcel` guarda `{parcel_id, crop_class}` (highlight/chip) y `chatStore.activeParcelId` guarda el id (lo que viaja al backend).
5. Enviar un mensaje en el chat: el body del POST /chat incluye `parcel_id: <id real>` (verificable en Network o por el test `use-chat-retry`).
6. Click en la ✕ del chip (`clearParcelSelection`): limpia AMBOS stores en lockstep (mapStore + chatStore.activeParcelId = null).

**Esperado**: el id que viaja al backend es el de la feature renderizada; geometria densa NO se inventa (es FUTURE).

### 5. Switch de basemap (live)

1. Cambiar basemap (satellite -> streets -> topo).
2. `map.setStyle` reemplaza el raster; en `styledata` se re-anaden los overlays (findings + AOI) y se re-cablean interacciones.
3. Las parcelas/AOI dibujados se conservan tras el switch (no desaparecen).

**Esperado**: switch sin perder overlays; sin Mapbox en ningun basemap (Esri / OSM / OpenTopoMap, todos keyless).

### 6. Responsive 2-panel + cleanup

1. Layout chat + mapa en dos paneles; redimensionar la ventana -> el mapa ocupa su panel (`h-full w-full`).
2. Navegar fuera de la vista del mapa (desmontar `MapCanvas`): `onBeforeUnmount` -> `destroyMap()` ejecuta `map.remove()`, quita el listener `keydown`, para todos los watchers (`stopHandles`) y resetea refs; `mapApiRef.value = null`.
3. Volver a entrar: el mapa se reconstruye limpio (sin listeners duplicados ni fugas).

**Esperado**: sin warnings de listeners colgados; re-entrada idempotente.

# Manual test — US-051: RLS multi-tenant (migración dbmate)

Pasos manuales que requieren Docker / inspección humana. Validan que la
Row-Level Security por `session_id` se aplica de verdad (rol no-superuser),
que la migración aplica y revierte limpia, y que el aislamiento cross-tenant
es real. Complementan el test automatizado
`backend/tests/integration/test_rls_isolation.py` (testcontainers).

Prerrequisitos: Docker Desktop corriendo; `dbmate` instalado; repo en la rama
`feature/E8-US-051-rls`.

> Nota de QA (2026-06-19): los comandos de abajo se ejecutaron contra el
> docker-compose local; resultados pegados en cada paso. La migración aplica,
> revierte y re-aplica limpia; los 9 tests de aislamiento pasan; la verificación
> manual confirma el aislamiento A/B y el fail-closed sin sesión.

---

## 0. Levantar la base de datos local

```bash
docker compose up -d postgres redis
# esperar healthy
docker exec agro_sat_copilot-postgres-1 pg_isready -U agrosat
# -> /var/run/postgresql:5432 - accepting connections
```

El compose mapea Postgres al puerto host **55432** (`POSTGRES_HOST_PORT:-55432`).

## 1. Aplicar la migración RLS (dbmate up)

`dbmate` carga un `.env` por defecto; pásale un env-file vacío y la URL explícita
para evitar interferencias.

```bash
URL='postgres://agrosat:agrosat@localhost:55432/agrosat?sslmode=disable'
printf '' > /tmp/empty.env

dbmate --no-dump-schema --env-file /tmp/empty.env --url "$URL" -d ./db/migrations status
# -> [ ] 20260620000418_rls_multi_tenant.sql  (Pending: 1)

dbmate --no-dump-schema --env-file /tmp/empty.env --url "$URL" -d ./db/migrations up
# -> Applied: 20260620000418_rls_multi_tenant.sql in ~20ms
```

(Equivalente con Makefile si `.env.local` tiene `DBMATE_DATABASE_URL` apuntando a
55432: `make db-migrate`.)

## 2. Inspeccionar pg_policies y el estado de RLS

```bash
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -c \
"SELECT tablename, policyname, cmd, qual IS NOT NULL AS has_using, with_check IS NOT NULL AS has_check
 FROM pg_policies WHERE policyname='tenant_isolation' ORDER BY tablename;"
```

Esperado (4 filas: `aois`, `chat_sessions`, `features_parcels`, `parcels`; `cmd=ALL`,
`has_using=t`, `has_check=t`).

```bash
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -c \
"SELECT relname, relrowsecurity, relforcerowsecurity FROM pg_class
 WHERE relname IN ('chat_sessions','aois','parcels','features_parcels','rag_documents') ORDER BY relname;"
```

Esperado: las 4 tablas multi-tenant con `t/t` (ENABLE + FORCE); `rag_documents`
con `f/f` (corpus global, sin RLS, por diseño).

```bash
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -c \
"SELECT rolname, rolsuper, rolbypassrls FROM pg_roles WHERE rolname IN ('agrosat','agrosat_app') ORDER BY rolname;"
```

Esperado: `agrosat` -> `t/t` (superuser/bypass, rol de migración); `agrosat_app`
-> `f/f` (NO superuser, NO bypass: la RLS le aplica). **Este es el control clave:
si `agrosat_app` tuviera bypass, el aislamiento sería un falso verde.**

## 3. Demostrar aislamiento cross-tenant como `agrosat_app`

Sembrar dos sesiones (A, B) como superuser; luego consultar como `agrosat_app`.

```bash
# Seed (superuser) — dos sesiones con un AOI cada una.
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat \
 -c "INSERT INTO chat_sessions (id, user_id) VALUES
     ('11111111-1111-1111-1111-111111111111','qa-manual-A'),
     ('22222222-2222-2222-2222-222222222222','qa-manual-B');" \
 -c "INSERT INTO aois (session_id, geom, label) VALUES
     ('11111111-1111-1111-1111-111111111111', ST_GeomFromText('POLYGON((11 43,11.1 43,11.1 43.1,11 43.1,11 43))',4326),'A-aoi'),
     ('22222222-2222-2222-2222-222222222222', ST_GeomFromText('POLYGON((11 43,11.1 43,11.1 43.1,11 43.1,11 43))',4326),'B-aoi');"

# Sesión A primada -> ve SOLO A-aoi.
docker exec -e PGPASSWORD=agrosat_app agro_sat_copilot-postgres-1 \
 psql -U agrosat_app -d agrosat -c \
 "SELECT set_config('app.current_session','11111111-1111-1111-1111-111111111111',true);
  SELECT label FROM aois WHERE label IN ('A-aoi','B-aoi') ORDER BY label;"
# -> A-aoi   (1 row)

# Sesión B primada -> ve SOLO B-aoi.
docker exec -e PGPASSWORD=agrosat_app agro_sat_copilot-postgres-1 \
 psql -U agrosat_app -d agrosat -c \
 "SELECT set_config('app.current_session','22222222-2222-2222-2222-222222222222',true);
  SELECT label FROM aois WHERE label IN ('A-aoi','B-aoi') ORDER BY label;"
# -> B-aoi   (1 row)

# Sin sesión seteada -> 0 filas (fail-closed, sin error). missing_ok=true.
docker exec -e PGPASSWORD=agrosat_app agro_sat_copilot-postgres-1 \
 psql -U agrosat_app -d agrosat -c \
 "SELECT label FROM aois WHERE label IN ('A-aoi','B-aoi');"
# -> (0 rows)

# Limpieza.
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat \
 -c "DELETE FROM chat_sessions WHERE user_id LIKE 'qa-manual-%';"
```

Resultado QA (2026-06-19): A primada -> `A-aoi`; B primada -> `B-aoi`; sin sesión
-> 0 filas. Aislamiento confirmado a nivel DB con el rol de aplicación.

> El `set_config(..., true)` y el `SELECT` deben ir en el **mismo** statement `-c`
> (psql los envuelve en una sola transacción), porque `SET LOCAL` solo persiste
> dentro de la transacción. En el backend esto lo garantiza
> `session_scoped_conn` (abre una transacción y emite el `set_config` bound).

## 4. Test de aislamiento automatizado (testcontainers)

```bash
cd backend && poetry run pytest tests/integration/test_rls_isolation.py -v
```

Esperado: 9 passed (~5 min; levanta su propio contenedor PostGIS+pgvector).
Casos: rol no-superuser/no-bypass; SELECT A solo ve lo suyo; fail-closed sin
sesión; UPDATE/DELETE cross-tenant afectan 0 filas; INSERT con `session_id`/parent
ajeno bloqueado por WITH CHECK (SQLSTATE 42501); INSERT propio permitido;
round-trip migrate:down -> up.

Resultado QA (2026-06-19): `9 passed in 280.85s`.

## 5. Rollback y re-aplicación (round-trip)

```bash
URL='postgres://agrosat:agrosat@localhost:55432/agrosat?sslmode=disable'

dbmate --no-dump-schema --env-file /tmp/empty.env --url "$URL" -d ./db/migrations down
# Verificar: 0 policies, rol dropeado, RLS deshabilitado.
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -tAc \
 "SELECT count(*) FROM pg_policies WHERE policyname='tenant_isolation';"   # -> 0
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -tAc \
 "SELECT count(*) FROM pg_roles WHERE rolname='agrosat_app';"             # -> 0

dbmate --no-dump-schema --env-file /tmp/empty.env --url "$URL" -d ./db/migrations up
docker exec agro_sat_copilot-postgres-1 psql -U agrosat -d agrosat -tAc \
 "SELECT count(*) FROM pg_policies WHERE policyname='tenant_isolation';"   # -> 4
```

Resultado QA (2026-06-19): down -> 0 policies / rol dropeado / RLS+FORCE en `false`;
re-up -> 4 policies. Round-trip limpio.

## Notas de operación

- En staging/prod la app DEBE conectarse con el rol `agrosat_app` (o un rol cloud
  sin BYPASSRLS) vía `APP_DATABASE_URL`; el password real viene de Secret Manager /
  Key Vault, nunca del default dev `agrosat_app`.
- `parcels.session_id` es nullable: filas con `NULL` quedan invisibles a todos los
  tenants (fail-closed). Deuda: backfill + `NOT NULL` en rollforward futuro.
- `features_parcels` se aísla por subquery `EXISTS` contra `parcels` (no tiene
  `session_id` propio). Deuda: columna denormalizada + trigger en US futura.

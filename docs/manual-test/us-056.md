# US-056 — Manual test (Worker Pub/Sub de inferencia · scaffolding honesto, FUTURE)

US-056 es **scaffolding honesto** (DIFERIDA / FUTURE, [ADR-009](../decisions/ADR-009-h100-reactivacion-pivote-farslip-alcance-v8.md) /
[ADR-012](../decisions/ADR-012-inferencia-sincrona-mvp.md)). El MVP corre inferencia **sincrona**; esta US entrega la
interfaz async + su documentacion, NO un worker Pub/Sub productivo. La verificacion manual demuestra que: (1) el
modo `sync` corre inferencia REAL inline, (2) el modo `pubsub` falla CLARO (`NotImplementedError`, nunca no-op),
(3) el worker `ml/workers/inference_worker.py` NO arranca un subscriber falso, (4) la validacion Pydantic del
`JobRequest` rechaza payloads malformados.

> No requiere Docker ni GCP. El `JobsService` se ejercita en proceso con runner/pool inyectables; el worker se
> inspecciona via import + invocacion directa. Todo desde la raiz del repo (`backend/`).

## 2. Modo `pubsub` falla CLARO (nunca no-op silencioso)

El control de honestidad central de la US: el modo async diferido NO finge exito.

```bash
cd backend && poetry run python - <<'PY'
import asyncio
from backend.app.services.jobs_service import JobsService, JobRequest

req = JobRequest(
    session_id="11111111-1111-1111-1111-111111111111",
    aoi_geojson={"type": "Point", "coordinates": [9.6, 45.1]},
    model_id="xgb-alphaearth",
    year=2019,
)
svc = JobsService(enqueue_mode="pubsub")
try:
    asyncio.run(svc.submit_job(req))
    print("FAIL: pubsub no debio tener exito")
except NotImplementedError as e:
    assert "Full-only" in str(e) and "ADR-009" in str(e) and "inference-jobs" in str(e)
    print("OK: pubsub lanza NotImplementedError claro ->", str(e)[:80], "...")
PY
```

Esperado: `OK: pubsub lanza NotImplementedError claro -> Pub/Sub mode is Full-only (US-056 deferred, ADR-009) ...`

Evidencia en codigo: `backend/app/services/jobs_service.py:269` `raise NotImplementedError("Pub/Sub mode is
Full-only (US-056 deferred, ADR-009) ...")`, precedido de `logger.warning("inference_job_pubsub_deferred", ...)`.

## 3. El worker NO arranca un subscriber falso

```bash
# Importa limpio SIN google-cloud-pubsub (el tipo Message vive bajo TYPE_CHECKING).
poetry run python -c "import ml.workers.inference_worker as w; print('import OK')"

# run_subscriber falla claro (Full-only, requiere GCP Pub/Sub + Cloud Run GPU L4).
poetry run python -c "import ml.workers.inference_worker as w; w.run_subscriber()" 2>&1 | tail -3
```

Esperado:
- `import OK` (el modulo importa sin la dependencia de runtime de GCP).
- `NotImplementedError: The Pub/Sub subscription loop is DEFERRED ... It requires a live GCP Pub/Sub topic ... and
  a Cloud Run GPU L4 service. ... The MVP serves inference synchronously via JobsService(enqueue_mode='sync').`

Evidencia: `ml/workers/inference_worker.py:238` (`run_subscriber` -> `NotImplementedError`),
`:143`/`:165` (`_run_inference`/`_publish_result` -> `NotImplementedError`). Solo `parse_job_request` (validador)
es runnable. El bloque `__main__` (linea 250) loguea `inference_worker_not_runnable_in_mvp` y llama
`run_subscriber()` (que falla) — se niega a fingir un worker corriendo.

## 4. `parse_job_request` es REAL (unico runnable del worker)

```bash
cd backend && poetry run python - <<'PY'
import json
from ml.workers.inference_worker import parse_job_request

body = json.dumps({
    "session_id": "11111111-1111-1111-1111-111111111111",
    "aoi_geojson": {"type": "Point", "coordinates": [9.6, 45.1]},
    "model_id": "xgb-alphaearth",
    "year": 2019,
}).encode()
req = parse_job_request(body)
print("OK: parse_job_request ->", req.model_id, req.year, req.aoi_geojson.type)

# Payload invalido -> ValidationError (no se acepta basura).
try:
    parse_job_request(b'{"bogus": true}')
    print("FAIL")
except Exception as e:
    print("OK: payload invalido rechazado ->", type(e).__name__)
PY
```

Esperado: `OK: parse_job_request -> xgb-alphaearth 2019 Point` y `OK: payload invalido rechazado -> ...`.

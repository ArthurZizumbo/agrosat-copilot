## Contexto del bloqueo original

El modulo `infrastructure/terraform/modules/gcp/main.tf:630-643` definia los args del Cloud Run mlflow con el password Postgres **embebido directamente como string literal**:

```hcl
args = [
  "server",
  "--backend-store-uri",
  "postgresql://agrosat:${random_password.db_password.result}@/mlflow?host=/cloudsql/...",
  ...
]
```

Anti-patron de seguridad: el password queda visible en `gcloud run services describe agrosat-mlflow-dev`, accesible a cualquiera con `roles/run.viewer` sobre el proyecto.

## Solucion aplicada (2026-05-24)

3 cambios coordinados:

1. **Wrapper script** `infrastructure/docker/mlflow-start.sh`: construye el `--backend-store-uri` en runtime usando env var `DB_PASSWORD` inyectada por Cloud Run via `--set-secrets`. NO printea el password en stdout/stderr.

2. **Dockerfile** `infrastructure/docker/mlflow.Dockerfile`: agregado `COPY infrastructure/docker/mlflow-start.sh /usr/local/bin/mlflow-start` + `chmod +x` + `ENTRYPOINT ["/usr/local/bin/mlflow-start"]`.

3. **Terraform** `infrastructure/terraform/modules/gcp/main.tf`: eliminados `command` + `args` con password. Reemplazados por 5 env vars limpias (ENV, GCP_PROJECT_ID, CLOUDSQL_CONNECTION, ARTIFACT_ROOT, DB_PASSWORD). La quinta (DB_PASSWORD) usa `value_source.secret_key_ref` apuntando a `agrosat-db-password:latest`.

El SA `agrosat-mlflow-sa` ya tenia `roles/secretmanager.secretAccessor` (modules/gcp/main.tf:167) — no requirio cambio IAM.

## Verificacion

- `gcloud run services describe agrosat-mlflow-dev --format=yaml | grep -E "args|backend-store-uri"` -> 0 matches (password NO esta en spec).
- `gcloud run services describe ... | grep DB_PASSWORD` -> solo `secretKeyRef`, sin valor en plano.
- Cloud Run revision `agrosat-mlflow-dev-00004-5sn` READY=True, logs muestran `alembic.runtime.migration: Context impl PostgresqlImpl` + `Listening at: http://0.0.0.0:5000`.
- Cloud Build dedicado `infrastructure/cloudbuild-mlflow-only.yaml` reconstruye solo mlflow (29s) sin tocar ml-train (5.65 GB intacto).

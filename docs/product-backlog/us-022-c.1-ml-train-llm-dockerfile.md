# US-022-c.1 — Imagen ml-train-llm.Dockerfile para Gemma 4 / Qwen3.5 H100 LoRA

**Estado**: backlog
**Origen**: US-022-c P1 Fix #5 (Dockerfile 2026-05-24)
**Epic**: E6 / E7 (LLM fine-tuning + serving)
**Sprint**: V3-V5 H100 (post 28-may)
**SP estimado**: 3
**Owner**: Arthur (MLOps)
**Trigger**: cuando se planee la ventana V3 H100 (Gemma 4 26B-MoE LoRA, 28-30 may)

## Contexto

US-022-c P1 etapa 2 (Cloud Build ml-train) requirio EXCLUIR `ml-gpu-linux` (flash-attn + vllm) del builder porque:
1. `flash-attn 2.8.3` requiere `nvcc` para compilar kernels CUDA durante el wheel build.
2. La base `nvidia/cuda:13.0.0-runtime-ubuntu24.04` NO trae `nvcc` (solo runtime libs).
3. `vllm 0.20.2` tambien necesita compilacion CUDA via setup.py custom.

FarSLIP (US-017 P1) NO los necesita (usa CLIP standard via transformers), pero las ventanas V3-V5 H100 SI:
- V3 (28-30 may): Gemma 4 26B-MoE LoRA → necesita flash-attn-2 para FSDP + grad ckpt.
- V4 (1-3 jun): Qwen3-VL-30B-A3B LoRA → idem flash-attn-2.
- V5 (5-7 jun): Qwen3.5-35B-A3B serving → vLLM como engine.

## Alcance

Crear `infrastructure/docker/ml-train-llm.Dockerfile`:
- Base: `nvidia/cuda:13.0.0-devel-ubuntu24.04` (trae `nvcc`, `cudnn-dev`, `nccl-dev`).
- Builder stage: `poetry export --with ml,ml-gpu,ml-gpu-linux,geo` (incluye flash-attn + vllm).
- Runtime install splitter (paso 1 torch+numpy+ninja, paso 2 resto, paso 3 flash-attn+vllm con `--no-build-isolation`).
- Tag: `ml-train-llm:latest` separado de `ml-train:latest`.
- Pipeline aislada: `infrastructure/cloudbuild-llm-only.yaml`.

Actualizar `ml/configs/`:
- `h100_gemma4.yaml` referencia `ml-train-llm:latest` (no `ml-train`).
- `h100_qwen3vl.yaml` idem.
- `h100_qwen35_serving.yaml` idem.

## Costo / Tiempo

- Cloud Build estimado: ~45 min, ~$0.50 USD (E2_HIGHCPU_8).
- AR storage extra: ~18 GB * $0.10/GB/mes = ~$1.80/mes (puede limpiarse imagen vieja despues de V5).

## Riesgos

- R1: nuevo flash-attn (v3.0+) puede romper compatibilidad con torch 2.11+cu130. Mitigacion: pinar a `flash-attn==2.8.3` y validar en smoke V3.
- R2: vllm + transformers 5.x puede tener conflicts. Mitigacion: poetry lock --no-update + revisar conflicts antes del rebuild.
